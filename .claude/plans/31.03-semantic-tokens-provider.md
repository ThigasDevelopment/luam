# 31.03 - Serve semantic tokens from the LSP

## Objective

Publish the distinctions only resolution can make — native versus user function,
parameter versus local, class versus any capitalized name — as LSP semantic
tokens, so every editor that speaks the protocol colours Luam correctly instead
of only VS Code with a TextMate grammar.

## Why This Is Part of a Theme Milestone

A theme can only paint what something is labelled as. Half the roles in the 31.1
table have no positional signature: `createVehicle` and `spawnPlayer` look
exactly like a user function to a regex, and a parameter used in a body looks
exactly like a local. Without this task the theme's Set 1 and Set 3 collapse and
the milestone's premise — every element differentiated — is false.

It is also what makes the theme portable. The grammar is a VS Code artifact;
semantic tokens are the protocol. Neovim, Zed, and any future client get the
same reading from the same server, which is the position `architecture.md`
already commits to when it says the LSP is editor-agnostic.

## Scope

- **In:** A `semanticTokensProvider` on the LSP, built from the existing scope
  tree, symbol index, and MTA catalog, plus the `semanticTokenScopes` fallback
  the VS Code extension needs so non-Luam themes still render something sane.
- **Out:** New analysis. If the symbol index cannot already answer a question,
  this task emits no token for it rather than inventing one. Deepening the index
  is its own work, not a colouring concern.

## Token Model

Standard LSP types, restricted to what the index actually knows:
`class`, `interface`, `enum`, `enumMember`, `type`, `typeParameter`, `parameter`,
`variable`, `property`, `function`, `method`, `decorator`, `event`, `keyword`.

Standard modifiers: `declaration`, `definition`, `readonly`, `static`,
`deprecated`, `defaultLibrary`.

Custom modifiers, which are where Luam earns its own theme:

- `mtaNative` — the symbol comes from the MTA catalog, not from user code.
- `serverOnly` / `clientOnly` — the native's environment, so a reader sees which
  half of the game a call lives in without hovering.
- `erased` — the token disappears from the emitted Lua. This is R2 expressed as
  data instead of as a guess about syntax.
- `generated` — the member exists because a decorator produced it, so a reader
  can tell an authored member from an expanded one.

## Steps

### T-01 - Declare the capability

**Agent:** architecture-engineer

- [ ] Add `semanticTokensProvider` to `SERVER_CAPABILITIES` with the legend
      above, `full: true` and `range: true`. Range support keeps a large file
      responsive when only the viewport changed.
- [ ] Gate on the client capability reported at initialize. A client that does
      not ask for semantic tokens must see no behaviour change.

### T-02 - Build the token encoder

**Agent:** architecture-engineer

- [ ] Add `packages/lsp/src/features/semantic-tokens.ts` producing the delta-
      encoded `data` array the protocol requires: line delta, start delta,
      length, type index, modifier bitset.
- [ ] Sort by position before encoding and assert monotonicity in a test. A
      single out-of-order token corrupts every token after it, and the failure
      shows up as scrambled colour rather than as an error.
- [ ] Emit nothing for a position the index cannot classify. An absent token
      falls back to the grammar, which is the correct degradation.

### T-03 - Map the symbol index onto the legend

**Agent:** architecture-engineer

- [ ] Translate `SymbolKind` to token types: `local` and `global` to `variable`,
      `parameter` to `parameter`, `field` to `property`, `enum-member` to
      `enumMember`, `type-alias` to `type`, and the rest by name.
- [ ] Use `SymbolReference.kind` to separate a name in type position from the
      same name in value position, so `Vehicle` as an annotation and `Vehicle`
      in `new Vehicle()` are not the same token.
- [ ] Set `declaration` on the declaring occurrence, which is what drives the
      bold-for-definition half of R3.
- [ ] Set `readonly` on a local the scope tree shows is never reassigned, only
      when the index can prove it.

### T-04 - Mark the MTA surface

**Agent:** architecture-engineer

- [ ] Resolve a call target against the catalog the document's environment
      already scoped — the LSP resolves `server`, `client`, or `shared` before
      anything else runs, so the answer is available without new work.
- [ ] Set `defaultLibrary` plus `mtaNative`, and add `serverOnly` or
      `clientOnly` from the catalog entry's environment.
- [ ] Set `defaultLibrary` alone for the Lua stdlib, so Set 1 keeps the stdlib
      and the MTA surface apart.

### T-05 - Mark the erased layer

**Agent:** architecture-engineer

- [ ] Set `erased` on every token the emitter drops: annotations, `interface`
      and `type` declarations and their names, `declare` symbols, and decorator
      names. The emitter already knows which constructs it erases; take the list
      from there rather than restating it.
- [ ] Set `generated` on decorator-produced accessors, which the checker records
      in its generated-member side tables.

### T-06 - Give VS Code a fallback map

**Agent:** architecture-engineer

- [ ] Add `contributes.semanticTokenScopes` to the extension manifest, mapping
      each type and custom modifier to the TextMate scope 31.2 defines. A user
      on a third-party theme then still gets a reasonable colour, and the Luam
      theme overrides it precisely.
- [ ] Add a `luam.semanticHighlighting` setting so a user can turn it off
      without disabling the extension.

### T-07 - Keep it off the hot path

**Agent:** architecture-engineer

- [ ] Serve tokens from the analysis the document already produced. If a request
      would force a re-parse, return the previous result rather than blocking.
- [ ] Record the cost on a representative file and state it in the task notes.
      Semantic tokens run on every keystroke; a number is the only way to know
      the editor stayed responsive.

## Acceptance Criteria

- [ ] `semanticTokensProvider` is advertised, and a client that does not request
      the capability observes no change.
- [ ] Every custom modifier is produced by at least one fixture and asserted.
- [ ] An MTA native, a Lua stdlib call, a user function, and a method in one
      file produce four distinguishable tokens.
- [ ] A parameter and a local in the same body produce different tokens at both
      their declaration and their use.
- [ ] The encoder's output round-trips: decoding `data` reproduces the token list
      it was built from.
- [ ] `pnpm --filter @luam/lsp test` passes, and full-document tokens for the
      largest fixture stay under the budget recorded in T-07.
