# 44.01 - Bind a member reference to its receiver

> File: `.claude/plans/44.01-member-reference-binding.md`

## Objective

Stop a property from resolving to an unrelated declaration that happens to share
its name, which is what makes hovering `props.password` answer with a class field.

## Reproduction

Confirmed on the current tree through `LanguageService.hover`:

```luam
type Props = {
    secret?: string;
}

class Network {
    secret: string = "x";
}

function take(props: Props)
    local value = props.secret;
end
```

Hovering `secret` in `props.secret` answers the class field. Delete the class and
the same hover answers `Props.secret: string?`, which is the correct type. The
class does not have to enclose the access — a class anywhere in the file is
enough.

## Root Cause

- `receiverName` (`packages/lsp/src/symbols/collector-state.ts:90`) names a
  receiver only when its type is `named`. A parameter typed by a type alias
  reaches the collector as a `record`, so the member reference is recorded with a
  `null` container.
- `containerMatches` (`packages/lsp/src/symbols/symbol-index.ts:25`) treats a
  `null` container on either side as a match, so a container-less member reference
  resolves to any declaration with the same name and a member kind — here, the
  class field.
- `hoverAt` asks `index.declarationFor(offset)` first, so that wrong resolution
  wins before `memberHover`, which reads the checker's type and is correct.

## Scope

- **In:** Naming a receiver from every type that carries a name, and refusing the
  wildcard match for a member reference. Every feature that reads
  `declarationFor` inherits the fix.
- **Out:** Any change to the checker or to inference, and the hover text itself,
  which is 44.02.

## Steps

- [ ] Extend `receiverName` to name a `record` receiver and a receiver whose type
      resolves through an alias, returning the name the checker prints.
- [ ] Make `containerMatches` strict for the `member` kind: a member reference
      resolves only to a declaration whose container is the receiver it was
      recorded with. A reference whose receiver stays unnamed resolves to nothing.
- [ ] Keep value and type references as they are; they carry no container and must
      keep resolving by scope.
- [ ] Walk the surfaces that call `declarationFor` — hover, definition, references,
      highlight, rename, document symbols — and record which of them change.

## Acceptance Criteria

- [ ] In the reproduction above, hover, definition and rename on `props.secret`
      answer for `Props.secret` and never for the class field.
- [ ] `self.secret` inside the class still resolves to the class field.
- [ ] A member of an MTA element, of a library and of a class instance resolve as
      they did before, each proven by an existing test.
- [ ] No feature falls back to a same-named declaration when the receiver cannot
      be named; it answers from the checker's type, or answers nothing.
