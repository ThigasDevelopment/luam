# 32.05 - Cover milestone 32 with checker and LSP tests

## Objective

Lock the behaviour milestone 32 adds — checked method calls, a formatter, code
actions and workspace symbols — with tests that fail when any of it regresses.

## Scope

- **In:** Checker fixtures for method-call checking, formatter property and
  corpus tests, and LSP tests for code actions and workspace symbols.
- **Out:** The documentation fixes in [32.04](32.04-documentation-drift.md).
  `pnpm docs:verify` already covers them.
- **Out:** Benchmarks. If formatting or workspace symbols turn out to be slow,
  that is a performance-engineer task with its own plan.

## Context

Two of the three features this milestone adds rewrite or edit the user's source,
which raises the bar for what counts as covered. A formatter that drops a
construct and a quick fix that produces uncompilable source are both silent
failures on the developer's own code, so both need tests that check the *result*
compiles rather than tests that compare strings.

The suite already has the shapes this needs: fixture-and-snapshot tests in the
compiler, and the `docs/snippets` corpus that every documentation example is
drawn from. That corpus is the natural formatter input, because it is the largest
body of `.luam` in the repository and it is already known to compile.

## Steps

### T-01 - Cover method-call checking

**Agent:** test-engineer

- [ ] Fixture per receiver kind: object type, native library instance, class,
      interface, MTA element, and `any`.
- [ ] Assert the wrong arity and the wrong argument type each report, with the
      position on the argument.
- [ ] Assert a method declared with an explicit `self` and one declared without
      report the same arity.
- [ ] Assert the class, interface and MTA element cases are byte-identical to
      their pre-milestone snapshots.

### T-02 - Cover the formatter

**Agent:** test-engineer

- [ ] Idempotence: formatting formatted output is a no-op, asserted across the
      whole corpus rather than on a handful of cases.
- [ ] Meaning preservation: for every file in `docs/snippets` and the compiler
      fixtures, the Lua compiled from the formatted source is byte-identical to
      the Lua compiled from the original.
- [ ] Comment attachment, including a trailing comment and a comment between two
      declarations.
- [ ] A file with parse errors yields no edits.

### T-03 - Cover code actions and workspace symbols

**Agent:** test-engineer

- [ ] For every diagnostic marked fixable, assert the action is offered, and
      assert applying it both clears the diagnostic and leaves source that
      compiles.
- [ ] Assert no action is offered for a diagnostic outside that list.
- [ ] Workspace symbols find a class, an interface, an enum and an exported
      function in an unopened file, each carrying its environment.

## Acceptance Criteria

- [ ] `pnpm typecheck` and `pnpm test` pass across the workspace.
- [ ] Every acceptance criterion in 32.01, 32.02 and 32.03 has a test that fails
      when the behaviour is reverted.
- [ ] The formatter corpus test covers every `.luam` file in `docs/snippets`,
      and adding a snippet adds it to the test without editing the test.
- [ ] No quick-fix test asserts on text alone; each one recompiles the result.
