# 39.04 - Enforce the source conventions in the pipeline

## Objective

Close the enforcement gap milestone 36 deferred, so `code-conventions.md` is
checked by a gate rather than by a reviewer's memory.

## Scope

- **In:** A conventions check in the merge gate, composed from the reusable
  workflow units milestone 36 extracted, covering the `.luam` corpus through
  `luam format --check` and the TypeScript sources through whatever T-01
  selects.
- **Out:** Changing any convention. The rules in `code-conventions.md` are the
  input, not the question.
- **Out:** Reformatting the TypeScript workspace as part of this task, if T-01
  selects a tool that would. That is its own change with its own review.

## Context

Milestone 36 deferred this in writing:

> Automated enforcement of the source conventions. The workspace has no linter
> or formatter, so `code-conventions.md` — kebab-case, single quotes, the line
> and file limits — is enforced only by review. Adding one is a new gate rather
> than a reorganization of an existing pipeline, and it belongs to its own task.

This is that task. One half of it stopped being a question when
[39.01](39.01-format-command.md) shipped `luam format --check`: the `.luam` corpus
gains an enforceable, idempotent standard with a command that exits `1` when a
file differs.

The other half — the TypeScript in `packages/` and `tools/` — has no tool at all.
The workspace's devDependencies are `esbuild`, `typescript`, `vitepress` and
`vitest`. Nothing checks kebab-case filenames, single quotes, the 175-character
line limit or the 250-line file limit.

The pipeline this plugs into is already written. Milestone 36 extracted
`unit-typecheck.yml`, `unit-test.yml`, `unit-build.yml` and `unit-docs.yml` as
`workflow_call` units that `ci.yml`, the release path and a fork run all compose,
and `@luam/pipeline` asserts that every required check name resolves to a job
that reports. A new gate job is a new unit plus a ruleset update, and the suite
will fail if the two disagree — which is the property that makes this safe to add.

## Design

### Two halves, one job

One `unit-conventions.yml` reporting as a single check, running both halves. A
contributor sees one red check, not two, and the required-check set in
`.github/rulesets/main.json` grows by one name.

### The `.luam` half

`luam format --check` over the repository's own corpus: `docs/snippets`,
`examples/`, the compiler fixtures. It exits `1` on any file that differs, and
39.01 T-04 already asserts the corpus is a fixed point, so this passes on the day
it lands.

[39.05](39.05-formatter-configuration.md) makes the style a project choice
through a `.luam.formatter` file, which does not weaken this gate: **this
repository sets no such file and keeps the milestone 32 defaults**, so
`--check` here means what it means today. The gate asserts that this
repository's own corpus is formatted, not that every Luam project shares one
style. T-02 should commit to that in writing, because a reader who sees the
formatter become configurable will reasonably ask whether the gate still
decides anything.

### The TypeScript half

T-01 chooses between two shapes, and records the rejection:

1. **A conventions script in `tools/`.** Reads `code-conventions.md`'s
   mechanical rules and asserts them: kebab-case file names, the line limit, the
   file limit, single quotes. No new dependency, no reformatting, no opinions the
   project did not already write down. It checks exactly the rules that exist.
2. **A standard linter and formatter.** More coverage, at the cost of a
   dependency, a configuration file, an opinion set that will disagree with the
   codebase somewhere, and a reformatting commit touching every file.

Option 1 is the recommendation. The conventions are already written and already
mechanical; a tool that enforces them is a script, and one that brings its own
opinions is a negotiation. Option 2 is recorded so the rejection is on the
record, and so a future task that wants broader coverage knows what it is
choosing.

Either way the check must be reproducible locally from `CONTRIBUTING.md`, which
milestone 36 made a requirement of every required check.

### The ruleset

`.github/rulesets/main.json` currently requires five checks. This adds a sixth.
Two constraints from milestone 36 apply unchanged: the check must report on every
pull request, so it cannot be path-filtered; and it must be one a fork run can
satisfy, so it needs no secret and no write token. Both are asserted by
`@luam/pipeline`, and the ruleset file and the live ruleset have to move together
— the live rulesets were applied from those files verbatim.

## Out of Scope

- Changing any convention.
- Broader static analysis than the conventions the project has written down.
- Auto-fixing in CI. The gate reports; the developer fixes.

## Risks

## Record

### T-01 - The TypeScript half is a script

**Option 1 was taken: a conventions script in `tools/`, as `@luam/conventions`.**
Option 2, a standard linter and formatter, is rejected and recorded: it costs a
dependency, a configuration file reconciling its opinions with the project's, and
a reformatting commit touching every file — to enforce rules the project has
already written down and already satisfies. A tool that enforces written rules is
a script; one that brings its own is a negotiation.

The cost of the script is that it owns a scanner. That is unavoidable rather than
incidental: the comment and quote rules cannot be decided by a regular
expression, because a `//` inside a URL and a `/*` inside a glob are not
comments. `source-scan.ts` walks each file once, tracking string literals,
template literals with their `${}` expressions, and regular expressions, and
reports only what is really code. Running it over the workspace found zero false
comment hits, which is the evidence that it works.

No network dependency is added. The script reads the working tree and nothing
else; the `.luam` half runs the bundled CLI, which makes no network call when it
formats.

**Coverage, stated rather than assumed** — the full table lives in
`code-conventions.md` under "What the gate enforces". In short:

*Enforced:* kebab-case file names, TypeScript only, four-space indentation, no
comments, single quotes, no `../` imports inside `packages/*/src`, and
`luam format --check` over the whole `.luam` corpus.

*Not enforced, with the reason recorded in the same place:* the `../` rule
outside `packages/*/src`, where no alias exists and none would resolve under
Node's own type stripping; the line and file limits, which the workspace exceeds
today — 621 lines and 507 characters at the extremes — and which cannot be turned
on without a refactor of the checker and the test suite that belongs to its own
task; import grouping and ordering, which would need a workspace-wide reordering
commit; the barrel `index.ts` rule, where all three existing files are package
entrypoints the convention allows and telling an entrypoint from a barrel needs
judgement; and everything about meaning.

### T-02 - The violations found and fixed

The only rule the workspace violated was **single quotes**: 34 double-quoted
strings across 20 files, every one of them a Luam source fixture in a test plus
one hover string in `packages/lsp/src/features/class-keyword-text.ts`. All 34 were
rewritten to single quotes; none contained a single quote, so no escaping
changed. Kebab-case, TypeScript-only, indentation, comments and parent imports
were already clean, and `luam format --check .` already passed over all 89 `.luam`
files.

The gate's independence from [39.05](39.05-formatter-configuration.md) is recorded
in `code-conventions.md`: this repository sets no `.luam.formatter` and keeps the
milestone 32 defaults, so `--check` here means what it always meant. The gate
asserts that this repository's corpus is formatted, not that every Luam project
shares one style. If this repository ever added a `.luam.formatter`, the gate
would still decide something — it would assert the corpus matches the style that
file names — but the file would have to be committed and the defaults it changes
stated in `code-conventions.md`, because a style nobody wrote down is a style
nobody can review.

The two files in `docs/snippets/errors/` that deliberately do not parse are
warned about and do not fail the run, which is what lets the gate cover the whole
repository with no exclusion list.

### T-03 and T-04 - The unit and the ruleset

- `.github/workflows/unit-conventions.yml` reports as **Conventions**, declares
  `contents: read`, pins `actions/checkout` to the same SHA the other units use,
  and reaches only first-party `./` actions otherwise. It needs no secret and no
  write token, so a fork run satisfies it.
- `ci.yml` composes it beside `typecheck`, `test` and `docs`, with no path
  filter, so it reports on every pull request.
- `.github/rulesets/main.json` now requires six checks; `conventions / Conventions`
  is the sixth. `@luam/pipeline` passes: the name resolves to a job that reports,
  no permission budget is exceeded, and no action is unpinned.
- A deliberate violation was proven to turn the check red in both halves — a
  `Deliberate_Violation.ts` holding a comment and a double-quoted string exits
  `1` with three reports, and an unformatted `.luam` file makes
  `luam format --check .` exit `1`. Both were removed afterwards and the check is
  green.

**Open, and the user's to do:** the live `main` ruleset on GitHub still requires
five checks. It has to be updated from the committed JSON so the file and what
GitHub enforces stay the same text, and that is a change to the repository's own
protection settings — it is not made from here without being asked.
