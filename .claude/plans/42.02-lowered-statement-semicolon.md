# 42.02 - Keep the trailing semicolon of a lowered statement on the statement line

## Objective

Stop stranding the semicolon a developer wrote after a multi-line statement on a line of its own when that statement is lowered to canonical Lua, so a development build never contains a bare `;`.

## Context

`canonicalEdit` in `packages/compiler/src/emitter/preserve-canonical.ts` replaces the
authored span of a statement the preserving path cannot keep. The span stops at the end of
the statement, before the semicolon the author wrote after it. When the replacement is
shorter than the authored text, the missing newlines are appended to the replacement to hold
the line count, which pushes that untouched semicolon down.

Reproduced with a development build of:

```luam
self.adapters = {
    mysql = new MySQLAdapter(self)
};
```

which emits

```lua
self.adapters = { mysql = new 'MySQLAdapter' (self) }

;
```

This is the same class of defect as [27.01](27.01-orphan-semicolon.md), which absorbed the
trailing semicolon into an *erasure* span. `erasedEnd` already exists in this file and is
used by `erasedEdit`; the lowering branch never calls it.

The flattening of the table itself is not a defect. `docs/en/reference/output-layouts.md`
records that `new`, a template string, a compound assignment and a native extension produce
canonical Lua for the whole statement they appear in. Preserving the authored layout around
a lowered sub-expression is a separate change, out of scope here and noted in the
[roadmap](../docs/roadmap.md) under milestone 42.

## Scope

- **In:** The trailing semicolon of a statement replaced by `canonicalEdit`, and the
  placement of the padding newlines relative to it.
- **Out:** The layout of the canonical replacement itself. Finer-grained lowering, which
  would keep the authored table layout around a `new`.

## Steps

### T-01 - Establish the failing case

**Agent:** architecture-engineer

- [ ] Add a development-output test for a multi-line statement with a trailing semicolon
      whose lowering collapses it to one line.
- [ ] Cover a `new` inside a table literal, a template string, and a compound assignment.
- [ ] Cover the same statements without a trailing semicolon, and as the last statement in a
      file, so the repair is proven not to invent one.
- [ ] Assert directly that no generated line consists only of a semicolon, reusing the guard
      27.01 added.

### T-02 - Absorb the semicolon into the replacement

**Agent:** architecture-engineer

- [ ] Extend the edit end to `erasedEnd(source, span)` so the authored semicolon is inside
      the replaced range.
- [ ] Append the authored separator to the replacement, before the padding newlines.
- [ ] Measure `missing` against the extended span so the line count is still preserved.
- [ ] Confirm the source mapping for the statement still resolves to the authored line.

## Acceptance Criteria

- [ ] A lowered multi-line statement keeps its semicolon on the same line as the generated
      statement.
- [ ] No generated line consists only of a semicolon, in development or release.
- [ ] Line counts are unchanged, and `expectLineFidelity` still passes for every fixture.
- [ ] A statement with no trailing semicolon gains none.
- [ ] `pnpm typecheck` and `pnpm test` pass.
