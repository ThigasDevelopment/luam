# 38.06 - Document authoring and consuming a Luam library

## Objective

Give both manual trees the two pages this feature needs — how to use a library,
and how to write one — and correct every page that describes a world where the
only way to share Luam code is to copy files.

## Scope

- **In:** A consuming section on the manifest page, an authoring page, the
  configuration field entries, the new diagnostics, the limitations entries, a
  recipe, and both changelogs.
- **Out:** Operating a directory, an index, or any listing of libraries. Luam
  runs no infrastructure, and a page that implies otherwise creates an
  expectation the project has decided not to meet.

## Context

`docs/en/language/exports.md` describes the export contract, which is the *other*
answer — a runtime boundary between two deployed resources. ADR-038 keeps both
and calls them orthogonal: a stateful service is a resource with exports, a pure
module is a library. If the documentation does not draw that line clearly, every
reader will ask which one they want, and the two field names — `dependencies` and
`libraries` — are close enough to make a wrong guess easy.

That distinction is the single most important thing these pages have to
communicate, and it should appear on both, not buried in one.

## Steps

### T-01 - Consuming a library

**Agent:** documentation-engineer

- [ ] Add a `libraries` section to `docs/*/tooling/luam-manifest.md`: what it
      lists, that order is emission order, and that a listed package must be
      installed by the developer.
- [ ] State the distinction from `dependencies` on that page, in a form a reader
      skimming for the right field will land on.
- [ ] Add the field to `docs/*/reference/configuration-fields.md` with its
      validation rules.
- [ ] Add the new diagnostics to `docs/*/reference/diagnostics.md`:
      `config-library-missing`, `config-library-invalid`,
      `config-library-duplicate`, `config-library-escape`,
      `config-library-requirement-missing`, `project-library-collision`, and
      whatever 38.03 T-01 decided about API shadowing.

### T-02 - Authoring a library

**Agent:** documentation-engineer

- [ ] Add a page describing the `luam` field: `sources` per environment,
      `requires`, and that patterns are package-root relative and may not escape
      it.
- [ ] State that a library's types come from its source, that it is compiled by
      its consumer, and that a library which does not type-check breaks that
      consumer's build.
- [ ] State that the library owns its environment and the consumer cannot
      reassign it.
- [ ] State that every top-level name becomes a global in the consuming resource,
      and that this is why collisions are compile errors — the one fact a library
      author most needs before choosing names.
- [ ] Cross-link `docs/*/language/exports.md` in both directions, naming which
      answer fits a stateful service and which fits a pure module.

### T-03 - Limitations and boundaries

**Agent:** documentation-engineer

- [ ] Add a limitations entry, labelled **Design boundary**, for the absence of
      transitive resolution, with the flat-namespace reasoning ADR-038 gives.
- [ ] Add an entry for collisions being reported rather than resolved.
- [ ] Add an entry for library assets, recorded as out of scope by 38.04.
- [ ] Add the matching entries to `docs/scripts/limitations-contract.ts`.

### T-04 - A recipe and the changelogs

**Agent:** documentation-engineer

- [ ] Add a recipe that consumes a library end to end, compiled by
      `pnpm docs:snippets` like every other snippet project.
- [ ] Add the milestone 38 entry to `CHANGELOG.md` and both
      `docs/*/changelog.md`.
- [ ] Run `pnpm docs:verify`.

## Acceptance Criteria

- [ ] Both trees describe consuming and authoring, and `pnpm docs:parity` passes.
- [ ] The `dependencies` versus `libraries` distinction is stated on both pages.
- [ ] Every diagnostic this milestone adds appears in both diagnostics
      references.
- [ ] `pnpm docs:limitations` passes with the new entries.
- [ ] The recipe's snippet project compiles.
- [ ] No page implies Luam operates a registry, an index, or any hosted
      infrastructure.
- [ ] `pnpm docs:verify` passes end to end.

## Out of Scope

- A library directory or listing.
- Guidance on publishing to npm beyond what a library author needs from Luam.
