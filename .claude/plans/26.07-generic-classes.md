# 26.07 - Add erased generic user classes

## Objective

Allow classes to declare and consume type parameters while emitting one ordinary Lua class implementation.

## Options Considered

| Option | Runtime cost | Type precision | Decision |
|---|---|---|---|
| Erase generic parameters | None | Full compile-time substitution | Accept |
| Monomorphize each specialization | Code growth | Full | Reject |
| Treat class parameters as `any` | None | Low | Reject |

## Scope

- **In:** Class type parameters, constraints, defaults if already supported by alias generics, constructor inference, substitution, generic inheritance, diagnostics, LSP, and erasure tests.
- **Out:** Runtime reification, specialization, variance annotations, and higher-kinded types.

## Steps

### T-01 - Specify generic class identities

**Agent:** architecture-engineer

- [ ] Define the relationship between class values, constructed instance types, raw generic references, and aliases.
- [ ] Define inference precedence, omitted arguments, recursive bounds, inheritance substitution, and diagnostic wording.

### T-02 - Extend parser and type model

**Agent:** architecture-engineer

- [ ] Add type parameters to class declarations and type arguments to class references and construction.
- [ ] Reuse generic alias substitution and cycle protections rather than creating a second generic engine.
- [ ] Include generic signatures in declaration fingerprints and dependency edges.

### T-03 - Add inference and checking

**Agent:** architecture-engineer

- [ ] Infer constructor type arguments from arguments and expected type where unambiguous.
- [ ] Substitute parameters through fields, methods, constructors, implemented interfaces, and parent classes.

### T-04 - Verify erasure

**Agent:** test-engineer

- [ ] Cover explicit and inferred arguments, nested generics, inheritance, constraints, recursion, wrong arity, and incompatible specializations.
- [ ] Assert that specializations emit one class implementation with no runtime type artifacts.

## Acceptance Criteria

- [ ] `class Box<T>` produces precise `Box<string>` members and constructor results.
- [ ] Generic inheritance substitutes parent and interface members correctly.
- [ ] Recursive or excessively deep instantiation terminates with an actionable diagnostic.
- [ ] Generic parameters and arguments are fully erased from Lua output.
