# 49.05 - Document the root-level layout

## Objective

Say plainly, in both languages, that a resource can be one file next to its
manifest, what side that file runs on, and what the new diagnostic is asking for.

## Scope

- **In:** `docs/en` and `docs/pt-br` — the layout guide, the environments page,
  the manifest reference, the diagnostics table, troubleshooting — plus the
  changelogs and the scaffolded manifest comment.
- **Out:** New recipes. The first-resource recipe stays on the `src` layout,
  which is still what `luam init` writes and still the right default for a
  resource that grows.

## Steps

- [ ] [project-layout](../../docs/en/guide/project-layout.md) is the page that
      states today's rule — a file no pattern and no mapping names is not part of
      the build. Keep that sentence and give it its one exception: a `.luam` file
      directly in the project root is compiled even when no pattern names it, and
      it runs `shared` unless a `#!` directive says otherwise. Show the two-file
      tree, manifest and `index.luam`, beside the `src` tree already there.
- [ ] [environments](../../docs/en/mta/environments.md) already documents the
      folder rule and the directive that overrides it. Add the third row: a root
      file has no folder to read, so the directive is the only thing that speaks,
      and `shared` is the answer when it stays silent.
- [ ] [configuration](../../docs/en/mta/configuration.md) documents `sources`.
      State that the root pickup does not depend on it, so removing the block or
      keeping the scaffolded one both work for a flat resource.
- [ ] [diagnostics](../../docs/en/reference/diagnostics.md) gains a
      `config-unmatched-source` row beside `config-no-sources`, and the
      `config-no-sources` line narrows to "the project has no `.luam` file".
      Add `config-empty-asset` beside `config-missing-asset` in the same table.
- [ ] [luam-manifest](../../docs/en/tooling/luam-manifest.md) documents `assets`.
      Give it the pattern table 49.06 measured — `assets`, `assets/*`,
      `assets/**`, `assets/**/*`, `assets/**/*.png`, `**/*.png` — since the
      difference between `assets/*` and `assets/**/*` is exactly what an author
      guesses wrong, and say that a mapping matching nothing is now a warning.
      Note that the scaffolded block ships commented out with `#`, the
      manifest's line comment, and that `--` is `lex-foreign-comment`.
- [ ] [troubleshooting](../../docs/en/guide/troubleshooting.md) gets the case
      that produced this milestone: a build that fails with a file sitting right
      there, and the three fixes the diagnostic names.
- [ ] Mirror every change in `docs/pt-br`. The pages are translations of the same
      structure; a row added on one side and missing on the other is the failure
      mode to avoid.
- [ ] Add the entry to `CHANGELOG.md` under `Unreleased` and to both
      documentation changelogs.
- [ ] Add one `#` comment line to
      [the manifest template](../../packages/template/files/luam.manifest) above
      `sources`, saying the block is the layout for a project with folders and
      that a file in the project root is compiled without it. Keep it to one
      line; the template is the first Luam a new user reads. 49.06 owns the
      commented `assets` block in the same file — do not restate it here.

## Acceptance Criteria

- [ ] Both languages describe the root-level file, its side, and the directive
      that changes it, with the same wording and the same examples.
- [ ] The diagnostics tables in both languages list `config-unmatched-source`,
      `config-empty-asset`, and the narrowed `config-no-sources`.
- [ ] The manifest reference explains `assets` patterns by example in both
      languages, including the `assets/*` and `assets/**/*` difference.
- [ ] The three changelogs carry the entry.
- [ ] Every documentation link added resolves, and no page claims the `src`
      layout is required.
