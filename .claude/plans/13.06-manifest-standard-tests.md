# 13.06 - Cover the manifest standard with layout, order, and offline tests

> File: `.claude/plans/13.06-manifest-standard-tests.md`
> Every manifest snapshot in the suite is rewritten by this milestone. The point
> of this task is that they are rewritten once, deliberately, and that the new
> ones assert the standard rather than record whatever the generator happened to
> print.

## Objective

Pin the authored manifest standard, the load order, the helper relocation, the
directive removal, and the offline behaviour of the version lookup.

## Scope

- **In:** Compiler manifest and resource tests, CLI build and prune tests, LSP
  and VS Code tests touched by the directive removal, and the fixtures behind
  them.
- **Out:** Running the generated Lua. No Lua interpreter is in the stack, so
  load order is asserted through manifest order as it has been since milestone 6.

## Steps

- [ ] Rewrite the manifest snapshots against the standard, and add a test that
      reads `examples/meta.xml` as the reference shape so a future change to the
      generator is compared to the authored file rather than to itself.
- [ ] Cover the attribute policy directly: a server script with no `type`, a
      shared script with `cache="false"`, `<info>` with no `name`, one element
      per shared export.
- [ ] Cover the wildcard behaviour: one entry per environment, no entry for an
      empty side, and a manifest that does not change when a module is added.
- [ ] Cover `loadOrder`: a pinned file ahead of its group, a pinned asset ahead
      of the rest, an entry matching no file failing the build, and the order
      being stable across a warm rebuild.
- [ ] Cover pruning without the manifest enumeration: a deleted source file
      leaves the resource, a file the build never wrote survives.
- [ ] Cover the helper relocation, including the `env` helper that pins its own
      environment, and assert nothing is generated under `src/**/lib`.
- [ ] Cover the version lookup with the network stubbed three ways — success,
      failure with a cache, failure without one — and assert no test performs a
      real request.
- [ ] Delete the `setting` and `depends` tests rather than skipping them, and
      add the counter-tests that both words are ordinary identifiers again.
- [ ] Re-run the 300-file benchmark and record the numbers in
      [performance.md](../docs/performance.md). Wildcards mean less string
      building per build, so the manifest phase should not regress.

## Acceptance Criteria

- [ ] `pnpm typecheck`, `pnpm build`, and `pnpm test` pass with no skipped test,
      and the suite count is recorded in the roadmap acceptance.
- [ ] No test reaches the network, asserted by stubbing the transport and the
      release lookup.
- [ ] A scaffolded project from `luam init` builds, checks clean, and produces a
      manifest that matches the standard.
- [ ] Cold build and warm rebuild stay within the spread recorded for milestone
      12 (47.4–51.8 ms and 1.13–1.6 ms on the 300-file benchmark).
