# 46.02 - Hint every name a multi-return local declares

> File: `.claude/plans/46.02-multi-return-inlay-hints.md`

## Objective

Make `local cX, cY, cZ = getVehicleComponentPosition(...)` show `: number` on each
of the three names instead of the whole tuple on the first, so the hint reads as
the code reads.

## Context

`localHints` pairs declarator `n` with `statement.values[n]` and renders that
expression's type, which for a call returning a tuple is the tuple. Three defects
fall out of one line:

- The first name shows a tuple it does not hold.
- Every name after the first shows nothing, because the value list is shorter than
  the declarator list.
- `local only = f()` shows the tuple rather than the first element, contradicting
  the narrow-to-first rule the checker applies and the hover the same file
  produces for a name the checker declared.

The hint is the surface where this is worst. Hover is asked for one name at a
time; a hint is rendered on every name at once, so the wrong answer sits beside
the right ones.

## Scope

- **In:** The local-type hint kind, for a `local` whose value list distributes
  across more names than it has expressions.
- **Out:** The return, callback-parameter and parameter-name kinds. None of them
  reads a value list.
- **Out:** `generic-for` variables. They receive no hint today and gaining one is
  its own decision, recorded as deferred in the milestone.
- **Out:** The settings, their defaults and the initialization-options shape.

## Steps

- [ ] Rewrite `localHints` over the 46.01 helper, so each declarator reads the type
      its own index distributes to.
- [ ] Apply `widenInferred` per element, after the distribution rather than before,
      so a literal element widens the way a single-value local already does.
- [ ] Keep every suppression the kind has today: an annotated declarator, an empty
      name, a type that prints as `any`, and an index the value list cannot account
      for.
- [ ] Keep each hint anchored at the end of its own name, so three hints on one
      line land at three offsets.
- [ ] Confirm the range filter still applies per hint: a hint for a name outside
      the requested range is not emitted because a name inside it was.

## Acceptance Criteria

- [ ] `local a, b, c = triple()` renders `: number`, `: string` and `: boolean` at
      the three names.
- [ ] `local only = triple()` renders `: number`.
- [ ] `local x, y = 1, triple()` renders `: number` twice — the non-final call
      narrows to its first element.
- [ ] `local a, b, c = 1` renders one hint, and `local a, b = ...` renders none.
- [ ] `local a, b: string, c = triple()` skips the annotated name and still hints
      the other two correctly.
- [ ] The reported catalog case renders `: number` on `cX`, `cY` and `cZ`.
- [ ] Every existing assertion in `packages/lsp/tests/inlay-hints.test.ts` passes
      untouched.
