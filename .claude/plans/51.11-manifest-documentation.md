# 51.11 - Document the reformulated manifest

## Objective

Leave the manual describing one manifest — the table form — with a migration
page that a reader arriving from the old form finds before they find anything
else.

## Scope

- **In:** The manifest and configuration pages in both locales, the quick start,
  the output and generated-manifest references, the migration page, and the
  README.
- **Out:** `.luam.server` and `.luam.formatter` pages, which are unaffected.

## Steps

- [ ] Rewrite `tooling/luam-manifest` around the table form: the shape, the
      five sections, and one worked example that is the `heaven-roleplay`
      fixture, shown next to the `meta.xml` it generates.
- [ ] Regenerate `reference/configuration-fields` from the catalog. It is derived,
      so the only edit is to the generator if the table is wrong.
- [ ] Add a migration page: what changed and why, the field-by-field table from
      `REMOVED_FIELDS`, the `luam migrate` command, the code action, and the one
      case that refuses — a renaming `assets[].to`.
- [ ] Document the blank line as a group boundary on the manifest page and in the
      formatter page, with the rule that a run collapses to one and that the
      formatter never introduces one.
- [ ] Update `reference/output-layouts` for the sectioned generated file, and show
      a generated `meta.xml` in full at least once.
- [ ] Update the quick start and the README so the first manifest a reader sees is
      the new one.
- [ ] Translate every changed page to pt-BR. English is the source locale and CI
      fails when a page is missing from one.
- [ ] Run `pnpm docs:verify` — parity, snippets, outputs, examples and the build —
      and fix what it names rather than what it hints at.

## Acceptance Criteria

- [ ] No page in either locale shows the assignment form except the migration
      page, which shows it only as the before.
- [ ] The manifest page shows one complete manifest and the complete `meta.xml`
      it generates.
- [ ] `reference/configuration-fields` matches the catalog with no hand edit.
- [ ] The migration page names every removed field and its replacement.
- [ ] The blank-line rule is documented on both the manifest and formatter pages.
- [ ] `pnpm docs:verify` passes.
