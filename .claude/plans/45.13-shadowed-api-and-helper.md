# 45.13 - Report a declaration that overwrites an MTA API or a runtime helper

> File: `.claude/plans/45.13-shadowed-api-and-helper.md`

## Objective

Say something when a resource redefines a name the compiler models, because the
checker keeps typing every later call against a signature that no longer runs.

## Reproduction

All four of these compile with no diagnostic on the current tree:

```luam
_dxDrawText = dxDrawText

function dxDrawText(text, x, y, w, h, ...)
    return _dxDrawText(text, x, y, w + x, h + y, ...)
end

function math.clamp(value: number, min: number, max: number): number
    return math.max(math.min(value, max), min)
end

function Vector3:lerp(a, b, t)
    return Vector3(a.x, a.y, a.z)
end

repeat s, c = s:gsub('%d', '') until c == 0
```

The first changes the meaning of `dxDrawText` for the whole resource — the fourth
and fifth arguments stop being a width and a height and become a right and a
bottom — and every subsequent call is still checked against the catalog. The
second replaces the `math.clamp` the runtime helper injects, which the extension
rewrite `ratio.clamp(a, b)` lowers to. The third assigns a method to an
undeclared global. The fourth writes an implicit global inside a `repeat`.

## Scope

- **In:** A top-level assignment or function declaration whose name is a catalog
  API, a Luam runtime global, an injected runtime helper member, or a Lua 5.1
  standard library member. An implicit global write, reported separately so it can
  be tuned on its own.
- **Out:** A local that shadows any of those, which is ordinary Lua and stays
  silent. Blocking the override: a resource is allowed to patch a global, and the
  diagnostic is there so the author says it on purpose.

## Steps

- [x] Report `check-shadowed-api` for a top-level declaration of a name the
      catalog declares in this file's environment, naming the API and stating that
      later calls are still checked against the catalog signature.
- [x] Report `check-shadowed-helper` for a member of an injected runtime helper —
      `math.clamp`, `table.size`, `string.trim` and the rest — and state which
      extension rewrite lowers to it, since that is the part the author cannot
      see.
- [x] Report `check-implicit-global` for an assignment to a name that is neither
      declared, nor a catalog global, nor a project global, gated behind a
      `compiler` option that defaults **off** so no existing project starts
      failing.
- [x] Make all three warnings, so `warningsAsErrors` is the switch for a project
      that wants them fatal.
- [x] Give each one a documented suppression: a different name, or an explicit
      declaration file entry that records the new signature so the checker uses
      it. The second is what makes the diagnostic actionable rather than noise.
- [x] Add the three codes to the diagnostics reference with the reproduction
      above.

## Acceptance Criteria

- [x] Each of the four snippets reports exactly one diagnostic, at the
      declaration.
- [x] `local dxDrawText = dxDrawText` reports nothing.
- [x] `check-implicit-global` is silent with the option off and reports with it
      on.
- [x] A project that declares the replacement signature in a `.d.luam` file
      reports nothing and checks later calls against the declared signature.
- [x] The emitted Lua and the manifest are unchanged.

## Outcome

The fourth snippet — `repeat s, c = s:gsub('%d', '') until c == 0` — reports one
`check-implicit-global` **per name it creates**, so two, not one. It assigns two
undeclared names; reporting one and hiding the other would be worse.

`compiler = { noImplicitGlobals = true }` is the option, defaulting off, and it is
recorded in the manifest reference and the configuration fields for both locales.
The new `check-shadowed-api` warning also caught a real defect in the manual: the
`export http` example redefined `getPlayerCount` and called itself. It now
declares `getOnlineCount`.
