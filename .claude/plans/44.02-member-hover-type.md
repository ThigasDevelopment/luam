# 44.02 - Answer a property hover with the type the checker gave it

> File: `.claude/plans/44.02-member-hover-type.md`

## Objective

Make a hover on a property read the receiver's type first, so an optional field
reads `string?` and a guarded one reads what the guard narrowed it to.

## Scope

- **In:** The order of the hover chain for an offset that sits on a property, and
  the text it produces for a record member.
- **Out:** New content for hovers that are already correct, and any change to the
  checker.

## Steps

- [ ] In `hoverAt`, when the offset sits on the property of a member expression,
      ask `memberHover` before the symbol index, and keep the index for every
      other offset.
- [ ] Print an optional member with its optionality, and name the owner the way
      the checker names it.
- [ ] Where the flow analysis narrowed the access path, hover the narrowed type
      and name the declared one, so a guarded `props.password` reads as narrowed
      rather than as declared.
- [ ] Keep the MTA, library, project and class-instance hovers ahead of the
      fallback they already sit in front of.

## Acceptance Criteria

- [ ] Hovering `props.password` where `password?: string` answers `string?`, with
      or without a same-named class field in the file.
- [ ] Inside `if props.password and type(props.password) == "string" then`, the
      hover on `props.password` answers `string`.
- [ ] Hovering the receiver still answers the receiver — `parameter props: NetworkProps`.
- [ ] Every hover fixture in the suite keeps its current answer.
