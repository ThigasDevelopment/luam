# 49.02 - Rebuild when a root-level source changes

## Objective

Make `luam dev` react to the file 49.01 taught the build to compile, so editing
`index.luam` at the project root triggers a rebuild instead of leaving the
running server on the last output.

## Scope

- **In:** [source-watcher](../../packages/cli/src/watch/source-watcher.ts) and
  the predicate that decides whether a change is a source change.
- **Out:** The language server, which needs no change — it scans the workspace
  folder, not the `sources` roots, so an open root file already resolves through
  `resolveEnvironment`. A regression test that pins that belongs to 49.04.

## Why the watcher is a separate task

`watchSources` watches `resolver.roots`, the directories the patterns point at.
With the default mapping those are `src/server`, `src/client` and `src/shared`,
so a root file is invisible to it: 49.01 alone gives a resource that builds once
and never rebuilds. The fix has one trap — watching the project root recursively
would also watch `build/`, and a build writes into it — so it is worth its own
review rather than a paragraph inside another task.

## Steps

- [ ] Watch the project root non-recursively, alongside the existing recursive
      watchers. Skip it when `resolver.roots` already contains `''`, which
      `watchRoots` returns for a pattern such as `*.luam` or `**/*.luam`; that
      case is already a recursive watch over the whole project.
- [ ] Extend `isWatched` so a path with no `/` in it and the `.luam` extension
      counts as watched even when `resolver.resolve(path).matches.length === 0`.
      Depth and extension together are what keep `build/` out: the output is
      `.lua`, and it is never at depth 0.
- [ ] Keep `.test.luam` out of the rebuild trigger, the way discovery keeps it
      out of the build, so saving a test file does not rebuild the resource.
- [ ] Leave `watchedRoots` returning the pattern roots. It reports what the
      manifest declares; the root watch is not a declared root and adding it
      there would leak into every caller that prints or diffs them.
- [ ] Check the other consumer of the roots before assuming this is the only
      one: `write-options.ts` derives output cleaning targets from them, and a
      root-level source must not turn the project root into a cleaning target.

## Acceptance Criteria

- [ ] `luam dev` on a flat project rebuilds when `index.luam` is saved, and when
      a new `feature.luam` is created at the root.
- [ ] Writing the build output does not trigger a rebuild, and no rebuild loop
      appears when `outDir` is left at its default.
- [ ] A project whose patterns already cover the root — `server = { '*.luam' }`
      — opens one watcher, not two.
- [ ] Saving `index.test.luam` triggers no rebuild.
- [ ] `pnpm -r test`, `pnpm lint` and `pnpm typecheck` pass.
