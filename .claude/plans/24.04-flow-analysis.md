# 24.04 - Add path-sensitive control-flow analysis

## Objective

Safely narrow stable property paths and propagate type facts through complete function control flow.

## Options Considered

| Option | Correctness | Complexity | Decision |
|---|---|---|---|
| Extend the current name map with dotted strings | Breaks on aliasing and mutation | Low | Reject |
| Build a control-flow graph with access-path facts | Can model joins and invalidation | High | Accept |
| Adopt an external type-flow engine | Poor fit with Luam AST and types | High | Reject |

## Scope

- **In:** CFGs, access-path identity, nil and discriminant facts, joins, loop fixed points, mutation invalidation, guard exits, diagnostics, and editor parity.
- **Out:** Interprocedural effect inference, arbitrary theorem proving, and unsound narrowing across unknown calls.

## Steps

### T-01 - Specify flow semantics

**Agent:** architecture-engineer

- [x] Define stable paths for locals, parameters, and property/index accesses with immutable literal keys.
- [x] Define invalidation for assignments, aliases, captured values, method calls, unknown calls, and loop back-edges.
- [x] Define reachability and joins for branches, returns, breaks, and loops.

### T-02 - Implement the flow engine

**Agent:** architecture-engineer

- [x] Build a per-function CFG and calculate facts to a bounded fixed point.
- [x] Replace identifier-only fact lookup with flow-node and access-path lookup.
- [x] Preserve current union operand rules and discriminated-union behavior.

### T-03 - Verify soundness and performance

**Agent:** test-engineer

- [x] Add positive fixtures for fields, nested fields, guards, joins, and loops.
- [x] Add negative fixtures for mutation, aliasing, callbacks, unknown calls, and unstable indexes.
- [x] Assert no output on invalid programs and identical CLI/LSP diagnostics.

**Agent:** performance-engineer

- [x] Benchmark large functions and cap pathological fixed-point iteration with a conservative fallback.

## Acceptance Criteria

- [x] `if self.connection ~= nil` narrows a stable, unmodified field in the guarded region.
- [x] A write or potentially mutating operation invalidates affected path facts.
- [x] Loop and branch analysis terminates and never accepts a program rejected by a clean conservative check fixture.
- [x] Existing narrowing and discriminated-union suites remain compatible unless an ADR explicitly changes behavior.
- [x] Large-project check time does not regress by more than 10%.
