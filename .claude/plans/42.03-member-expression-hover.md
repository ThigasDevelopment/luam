# 42.03 - Hover a member expression by the type the checker gave it

## Objective

Answer a hover over the property of a member expression with the type the checker already computed for it, so `self.adapters.mysql` reports `MySQLAdapter` instead of nothing.

## Context

The checker is correct. Verified by assignment against a wrong annotation, all four of these
report `check-type-mismatch: ... received "MySQLAdapter"`:

- `adapter: MySQLAdapter` read as `self.adapter`
- `adapters: { mysql: MySQLAdapter }` read as `self.adapters.mysql`
- the same inline table type on a local
- the same shape declared through an `interface`

So the type reaches `analysis.types`; the hover provider is what does not read it.

`hoverAt` in `packages/lsp/src/features/hover.ts` tries, in order, a decorator, the
contextual hover for `self` and `super`, an event, the symbol index, the workspace, the MTA
catalog, and `keywordHover`. A class field and a property of an object type are in none of
them. The only member path is `recordMemberHover`, which returns early unless the owner type
is a `record`, the kind used for project globals, and which matches the first member
expression in the file with that property name rather than the one under the cursor.

`contextualHover` deliberately declines when `self` is a receiver (`isReceiverMember`), so
the property after the dot falls through to `apiHover` and then to nothing.

## Scope

- **In:** A hover over the property of a member expression whose type is known, whatever the
  owner's kind: a class instance, an inline object type, an interface, a record.
- **Out:** Any change to inference or to the checker. Hover over an index expression written
  with brackets. Completion, which milestone 41 covers.
