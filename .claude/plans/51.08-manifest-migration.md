# 51.08 - Migrate every existing manifest

## Objective

Move every manifest that exists — in this repository and in every project
`luam init` has ever scaffolded — to the table form, without asking anyone to
do it by hand.

## Why this is not a straight removal

`luam init` writes the `sources` record into every scaffolded project, so the old
form is not a field a few projects set: it is in every manifest the tool has ever
produced. ADR-017's rule that removed fields fail rather than alias is the right
end state and is where this lands, but 50.03 already established the shape for
getting there — the field keeps working, warns once, and is removed in the major
where a break belongs.

The difference here is that the whole file changes shape, not one field, so the
warning has to come with the rewrite rather than with instructions.

## The path

| Stage | Behaviour |
|---|---|
| This minor | The assignment form loads, is converted internally, and reports `config-manifest-form` once, naming `luam migrate` |
| This minor | `luam migrate` and an editor code action rewrite the file |
| Next major | The assignment form is `config-removed-field` and the converter is deleted |

## Steps

- [ ] Keep a reader for the assignment form that produces the new value through
      the `REMOVED_FIELDS` mapping 51.02 built. It is a converter, not a second
      schema: nothing downstream sees the old shape.
- [ ] Report `config-manifest-form` once per manifest, anchored at the first
      assignment, naming the command. One warning for a whole-file change, not one
      per field.
- [ ] Add `luam migrate`, which rewrites a manifest in place and prints a diff.
      It writes nothing when the manifest is already in the new form and nothing
      when the conversion is not exact.
- [ ] Make the conversion exact or refuse. `sources` plus `loadOrder` becomes an
      ordered `scripts` list that reproduces the previous emission order —
      helpers, configuration, pinned entries, then the wildcards in `shared`,
      `server`, `client` order. `assets` with a `to` that differs from its `from`
      has no equivalent, so it is refused by name with the manual move spelled out.
- [ ] Offer the same rewrite as a code action, through the provider 32.03 built.
- [ ] Rewrite the scaffold template, every fixture, every snippet, the example
      resource and both locales of the manual in the same commit as the converter,
      so nothing in the repository demonstrates the old form.
- [ ] Check `warningsAsErrors` deliberately: a project that promotes warnings and
      has not migrated stops building. It should, and this states it so nobody
      files it as a regression.
- [ ] Record the major that removes the converter in `REMOVED_FIELDS` next to the
      entry, so the next person finds the decision instead of re-deciding it.

## Acceptance Criteria

- [ ] An assignment-form manifest builds, warns once, and produces the same
      `meta.xml` it produced before this milestone.
- [ ] `luam migrate` on that manifest produces a table-form file whose build
      is byte-identical to the warned build.
- [ ] `luam migrate` on an already-migrated manifest writes nothing and says so.
- [ ] An `assets` entry with a renaming `to` refuses migration, names the entry,
      and states the move.
- [ ] The code action produces the same text as the command.
- [ ] `warningsAsErrors = true` turns `config-manifest-form` into a failure.
- [ ] No `.luam.manifest`, fixture, snippet or documented example in the
      repository is in the old form.
