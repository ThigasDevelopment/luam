# 37.03 - Cover milestone 37 with checker tests

## Objective

Lock both milestone 37 behaviours with tests that fail for the right reason, so
the return rule cannot regress into silence and a generic function cannot regress
into `any`.

## Scope

- **In:** Unit and fixture coverage for `check-missing-return` and for generic
  functions, the emitter snapshots that prove erasure, and the corpus assertions
  that prove neither change moved existing output.
- **Out:** LSP coverage beyond what 37.02 T-06 delivers. Editor behaviour for
  hover and signature help is asserted there.
- **Out:** Benchmarks. Neither change adds a pass; both extend one that runs.

## Context

Both tasks in this milestone change what the checker reports, and both were
found by compiling a probe rather than by reading code. That is the shape the
tests should take: a fixture that would have passed before and must fail now,
and a fixture that would have failed before and must pass now.

The blast-radius measurements in 37.01 T-02 and the fallout fixes in 37.01 T-05
produce a list of real files that changed meaning. Every one of them is a test
case that already has an answer.

## Record

### T-01 - Missing return

`packages/compiler/tests/missing-return.test.ts`, 22 cases.

The declared-type matrix crosses three bodies — every path returns, some path
returns, no path returns — against the annotations: absent, `any`, `string?`,
`string | nil`, `void`, `nil`, a concrete type and a tuple. `void` and `nil` are
exercised on a body whose `return` carries no value, because a `return 'yes'`
under `: void` is `check-return-mismatch` and would have tested the wrong thing.

All four constructs that reach `checkFunctionBody` are covered: a function
declaration, a function expression, a class method, a static method and a
constructor. A constructor with no declared return type is asserted clean, so
the check cannot start rejecting ordinary constructors.

Loops: `while true do` and `repeat ... until false` report nothing; each with a
`break` reports; an inner loop that breaks inside an outer loop that does not
reports nothing, which pins that `hasBreak` does not descend into a nested loop;
and a loop on a non-literal condition reports.

The `error(...)` case has its own `describe` block named **the known false
positive**, asserting that it reports and saying in the test name why.

Position is asserted too: the diagnostic lands on line 1, the signature, not the
closing `end`.

No regression tests were needed for 37.01 T-05, because T-02 measured zero hits
and nothing was fixed.

### T-02 - Generic functions

`packages/compiler/tests/generic-functions.test.ts`, 29 cases, grouped by the
question each answers: declaration forms, inference, explicit arguments,
constraints, scope, the `<` ambiguity, and erasure.

Inference covers a bound parameter, two parameters bound independently, two
arguments that disagree (the first wins), an array parameter that binds through
its element, and a parameter that appears only in the return position becoming
`any`.

Every ambiguous `<` form 37.02 T-01 recorded has a test pinning which way it
parses, including the comparison against a parenthesised call.

Scope covers a generic method inside a generic class resolving both sets, a
method parameter shadowing a class parameter of the same name, and the absence of
`check-unknown-type` on a type parameter.

`packages/lsp/tests/generic-functions.test.ts` adds four editor cases: hover on
a generic declaration and on a generic method shows the type parameters, hover on
a call result shows the specialized type, and a generic declaration produces no
diagnostics through the language service.

### T-03 - Output and corpus

`packages/compiler/tests/fixtures/generics.luam` is a new fixture, which buys
four locks at once from `fixtures.test.ts` — the token stream, the AST, zero
checker diagnostics, and the emitted Lua — and two more from
`format-corpus.test.ts`, which sweeps the fixture directory: the file is already
formatted, and formatting is idempotent and meaning-preserving.

The emitted snapshot is the erasure proof in context: `identity<number>(2)`
emits `identity(2)`, `function <U>` emits `function`, and `T[]`, `T?` and
`extends Named` leave nothing behind. `generic-functions.test.ts` asserts the
stronger form directly — a generic function emits byte-for-byte what the same
function with `any` in place of its parameters emits.

The formatter was **not** a fixed point when the fixture was added; the two
spacing rules that fixed it are recorded in 37.02 T-05. That is the fixture
paying for itself on the first run.

Twelve AST snapshots changed, from `typeParameters`, `typeConstraints` and
`typeArguments` appearing on the four widened nodes. The diff was filtered for
any line that was not one of those three fields before the update ran; there were
none. No snapshot was updated in bulk without that check.

Corpus: `docs/snippets` (12 projects), the documented examples (244, 26 erroring
on purpose), the captured outputs (63) and `examples/` all pass unchanged. No
expectation changed.
