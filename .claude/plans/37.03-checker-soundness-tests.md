# 37.03 - Cover milestone 37 with checker tests

## Objective

Lock both milestone 37 behaviours with tests that fail for the right reason, so
the return rule cannot regress into silence and a generic function cannot regress
into `any`.

## Scope

- **In:** Unit and fixture coverage for `check-missing-return` and for generic
  functions, the emitter snapshots that prove erasure, and the corpus assertions
  that prove neither change moved existing output.
- **Out:** LSP coverage beyond what 37.02 T-06 delivers. Editor behaviour for
  hover and signature help is asserted there.
- **Out:** Benchmarks. Neither change adds a pass; both extend one that runs.

## Context

Both tasks in this milestone change what the checker reports, and both were
found by compiling a probe rather than by reading code. That is the shape the
tests should take: a fixture that would have passed before and must fail now,
and a fixture that would have failed before and must pass now.

The blast-radius measurements in 37.01 T-02 and the fallout fixes in 37.01 T-05
produce a list of real files that changed meaning. Every one of them is a test
case that already has an answer.

## Steps

### T-01 - Missing return

**Agent:** test-engineer

- [ ] A matrix over declared return types — absent, `void`, `any`, `nil`,
      optional, union containing `nil`, a concrete type, a tuple — crossed with
      three bodies: every path returns, some path returns, no path returns.
- [ ] The same matrix over the four constructs that reach `checkFunctionBody`: a
      function declaration, a function expression, a class method, a constructor.
- [ ] A `while true do` with no exit, and a `repeat ... until false`, each report
      nothing.
- [ ] An `if`/`elseif`/`else` whose every branch returns reports nothing; the
      same chain missing its `else` reports.
- [ ] A body ending in `error(...)` reports, and the test says so deliberately,
      naming it as the known false positive 37.01 T-01 recorded.
- [ ] Every case fixed in 37.01 T-05 has a regression test.

### T-02 - Generic functions

**Agent:** test-engineer

- [ ] Declaration forms: function declaration, function expression, class method,
      `declare function`, each with one parameter and with two.
- [ ] Inference: an argument binds a parameter; two arguments binding one
      parameter to conflicting types resolve the way T-04 of 37.02 decided; a
      parameter appearing only in the return type is `any`.
- [ ] Explicit arguments: correct count checks, wrong count reports
      `check-generic-arity`, a mismatched explicit argument reports
      `check-type-mismatch`.
- [ ] Constraints: a satisfying argument reports nothing; a violating one reports
      the same diagnostic the class path reports.
- [ ] Scope: a generic method inside a generic class resolves both sets, and a
      method parameter shadows a class parameter of the same name.
- [ ] Ambiguity: every `<` form 37.02 T-01 recorded as ambiguous has a test
      pinning which way it parses.

### T-03 - Output and corpus

**Agent:** test-engineer

- [ ] Emitter snapshots for a generic function in both layouts, asserting the Lua
      is identical to the same function with its parameters removed.
- [ ] The formatter is a fixed point on a file declaring a generic function, and
      the compiled Lua is byte-identical across a format.
- [ ] `docs/snippets`, the documented examples and `examples/` all compile, and
      any expectation that changed is individually justified.

## Acceptance Criteria

- [ ] Every acceptance criterion in [37.01](37.01-missing-return.md) and
      [37.02](37.02-generic-functions.md) has a test that fails when the
      behaviour is reverted.
- [ ] The suite passes on Node 22 and Node 24.
- [ ] No snapshot was updated in bulk; each change is named in the record.

## Out of Scope

- Editor coverage owned by 37.02 T-06.
- Performance measurement.
