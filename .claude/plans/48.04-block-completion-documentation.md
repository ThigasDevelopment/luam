# 48.04 - Document block completion

## Objective

Record what the editor now writes when a block item is accepted, in both
locales, so the behaviour is discoverable and nobody files it as the formatter
misbehaving.

## Scope

- **In:** The language server page, the changelog, and the roadmap rows.
- **Out:** New reference pages. This is one section on an existing page.

## Steps

- [x] Add a Block Completion section to
      [language-server](../../docs/en/tooling/language-server.md) and its pt-br
      mirror: the closers, the scaffolds, that the closer is preselected only
      while the block is unclosed, and that a client without snippet support
      still receives the block as plain text.
- [x] Show `if 1 + 1 == 2 then` as the worked example, since it is the case that
      motivated the feature.
- [x] Note the interaction with the editor indentation rules in
      [language-configuration.json](../../packages/vscode/language-configuration.json):
      the block is inserted with `adjustIndentation`, so it lands at the header
      indentation and `increaseIndentPattern` does not double it.
- [x] Add a changelog entry under the unreleased heading in both locales.
- [x] Confirm `pnpm docs:verify` passes, parity and snippet checks included.
- [x] Move every milestone 48 status in the plan files and in the roadmap rows in
      the same commit.

## Acceptance Criteria

- [x] Both locales document the closers, the scaffolds and the preselect rule in
      the same wording.
- [x] The changelog names the feature in both locales.
- [x] `pnpm docs:verify` passes.
- [x] No plan file and roadmap row disagree on status.
