# 7.5 — Set up CI for build, tests, and release

> File: `.claude/plans/7.5-ci-workflows-github-engineer.md`

## Objective

Add GitHub Actions workflows that type-check, test, lint, and release the CLI
and VS Code extension.

## Scope

- **In:** CI workflow for install/typecheck/test/lint, release workflow for
  the CLI and extension, branch protection basics.
- **Out:** Deploying to an MTA server from CI.

## Steps

- [x] Add a CI workflow using `pnpm install --frozen-lockfile`.
- [x] Run `tsc --noEmit` and the full test suite.
- [ ] Run `lint` — no linter is configured in the workspace, see Notes.
- [x] Add a release workflow that packages the CLI and VS Code extension.
- [x] Add LSP and extension test steps.

## Acceptance Criteria

- [ ] CI is green on `main` — the workspace is not a git repository yet, so no
      run has executed. Every command the workflow runs was verified locally.
- [x] Release workflow produces a versioned CLI tarball and a versioned VSIX.
- [x] Cache makes install/typecheck/test faster across runs.

## Notes

- **Lint is not wired.** The workspace has no ESLint or Prettier dependency;
  conventions live in the `code-conventions` skill instead. A hard gate on the
  250-line rule would fail today: `packages/compiler/src/parser/ast.ts` (272)
  and `packages/lsp/src/symbols/statement-collector.ts` (264) exceed it.
  Deferred with the milestone.
- **Audit is split.** `pnpm audit --prod` gates the build and passes clean.
  The development-dependency audit reports advisories in `vite` and `esbuild`
  reached through `vitest`, so it runs informationally and Dependabot owns the
  upgrades.
- **Publishing is packaging only.** `@luam/cli` and `@luam/vscode` are both
  `private: true`, so the release workflow builds the artifacts and attaches
  them to a GitHub Release instead of pushing to npm and the Marketplace.
- **Extension tests are not headless VS Code.** They run under vitest against
  the extension's own modules. A `@vscode/test-electron` run is deferred.
