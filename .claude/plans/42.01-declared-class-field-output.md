# 42.01 - Emit a class field declared without a default in the preserved class body

## Objective

Make a field written as `name: Type;` reach the generated class as `name = nil` in the source-preserving path, so the declared shape reads from the Lua a developer opens instead of vanishing into a blank line.

## Context

[55ef41a](https://github.com/ThigasDevelopment/luam/commit/55ef41a) fixed this in the
canonical emitter: `emitMembers` in `packages/compiler/src/emitter/classes.ts` emits
`member.value === null ? 'nil'`. The fix never reached the source-preserving emitter, which
is the path a development build takes for an undecorated class.

`isKept` in `packages/compiler/src/emitter/preserve-declarations.ts` reads

```ts
return !isLazyField(member) && (member.kind === 'class-method' || member.value !== null);
```

so a field with no initializer is not kept, falls into the `blankSpan` branch, and its line
is blanked together with its separator.

Reproduced with a development build of:

```luam
class Core {
    adapters: { mysql: MySQLAdapter };

    constructor = function ()
        self.adapters = { mysql = new MySQLAdapter(self) };
    end
}
```

which emits `class 'Core' {` followed by a blank line where the field was written.

The contract is already documented. `docs/en/reference/output-layouts.md` line 125 reads
"A class field with no default | `name = nil`, on the line the field was written on, so the
declared shape reads from the generated class". The documentation describes the
source-preserving layout, so the code is what disagrees with it, not the other way round.

The field is emitted as `name = nil`, not as a table built from the annotation. A field
initialised to a shared table in the class body would be shared by every instance, which is
a defect, not a convenience; the annotation stays a compile-time contract and the
constructor remains the only place an instance table is created.

## Scope

- **In:** The class-field branch of `classEdits`, the separator it consumes, and the line
  count it has to preserve when the annotation spans more than one line.
- **Out:** The canonical emitter, which is already correct. The `@Lazy` field, which stays a
  block comment. Any change to the shape a field's annotation produces at runtime.

## Steps

### T-01 - Establish the failing case

**Agent:** architecture-engineer

- [ ] Add a development-output test for a class whose first member is a field with an
      annotation and no initializer.
- [ ] Cover a single-line annotation, an annotation spanning several lines, a `static`
      field, the field as the only member, and the field as the last member.
- [ ] Confirm each currently emits a blank line and that the line count still matches.

### T-02 - Keep the field and rewrite it

**Agent:** architecture-engineer

- [ ] Widen `isKept` so a non-lazy field is kept regardless of its initializer, and route a
      field with no initializer through its own edit.
- [ ] Replace the span from the field name through its separator with `name = nil` followed
      by the separator the author wrote, or by the separator the class body needs when the
      author wrote none.
- [ ] Pad the replacement with the newlines the authored span occupied, so a multi-line
      annotation does not shorten the file.
- [ ] Confirm the annotation erasure that overlaps the same span is dropped by
      `sourceEdits` normalization rather than fighting the new edit.
- [ ] Confirm a decorator on the field is still commented, or covered by the edit, and
      never left as live Lua.

### T-03 - Confirm the two paths agree

**Agent:** architecture-engineer

- [ ] Assert that a release build and a development build of the same class both name the
      field, with the same value.
- [ ] Re-run the line-fidelity fixtures and the emitter snapshots, and record every snapshot
      that changes.

## Acceptance Criteria

- [ ] `adapters: { mysql: MySQLAdapter };` emits `adapters = nil;` on the line it was
      written on.
- [ ] The class body still separates its members correctly, whether the author wrote `;`,
      `,` or nothing.
- [ ] Line counts are unchanged for every fixture, including a multi-line annotation.
- [ ] A `@Lazy` field is still a block comment and is still absent from the class table.
- [ ] The generated Lua loads under Lua 5.1.
- [ ] `pnpm typecheck` and `pnpm test` pass.
