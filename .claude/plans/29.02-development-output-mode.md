# 29.02 - Add a development output mode to the compiler and CLI

## Objective

Give the emitter a way to know it is producing output a developer will read, so later tasks can prefer source fidelity without changing what a release build ships.

## Options Considered

| Option | Release output | Plumbing cost | Decision |
|---|---|---|---|
| Add a manifest field for the mode | Unchanged | One field through three layers plus a manifest surface | Reject |
| Reuse the existing strictness mode | Wrong axis entirely | None | Reject |
| Derive the mode from `output.minify`, carried through compile options | Unchanged for a minified build | One field through three layers | Accept |

**Decision recorded on execution.** The manifest gains no field. `minify` already
states whether the output is meant to be read: `output.minify = false` (or
`--no-minify`) is the request for readable output, and `dev` and `ensure` never
minify, so both are always in the mode. The compile boundary still carries an
explicit `development` flag, because the emitter must not read a write-layer
concern; the CLI is what derives it.

## Scope

- **In:** One option on the compile boundary, its default, its propagation into `EmitState`, and the CLI wiring that enables it for `dev` and leaves `build` on the release path.
- **Out:** Any behavior change. This task adds a gate that nothing reads yet.

## Steps

### T-01 - Define the option

**Agent:** architecture-engineer

- [x] Add `development` to `CompileOptions`, defaulting to `false` so a release build is unchanged.
- [x] Command-derived, not manifest-configurable. Recorded in the options table above.
- [x] The manifest field table is untouched, because no field was added.

### T-02 - Carry it to the emitter

**Agent:** architecture-engineer

- [x] Thread the option through `CompileOptions` and `CompileProjectOptions` into `emitPreservingSource`.
- [x] Expose it on `PreserveInput` rather than `EmitState`: every construct that branches on the mode is a surgical edit over authored text, which the canonical emitter never sees. `EmitState` gains no unread field.
- [x] Include it in the ambient key so a mode change invalidates cached modules.

### T-03 - Wire the CLI

**Agent:** architecture-engineer

- [x] Enable the mode in `dev` and `ensure`, and derive it in `build` from the resolved `minify`.
- [x] Follow the existing precedent: `build` resolves `minify` once and passes it to both `runCompile` and `productionWriteOptions`.
- [x] No new flag. `--minify` and `--no-minify` already select the form.

## Acceptance Criteria

- [x] A minified build is byte-identical to today, because only the readable path reads the option.
- [x] A cached project rebuilt in the other mode is not served from the previous mode cache.
- [x] `pnpm typecheck` and `pnpm test` pass.
