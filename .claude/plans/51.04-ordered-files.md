# 51.04 - Replace `assets` with an ordered `files` list

## Objective

Make a directory of assets one line in the manifest and one line in the generated
file, by writing the destination pattern once and emitting it as written.

## The shape

```luam
files = {
    'list.xml',

    'assets/images/**/*.png',
    'assets/shader/**/*.fx',
}
```

## Why `from` and `to` collapse into one path

`assets` maps `from` to `to`, so a file can be renamed on the way in. The cost is
that the generated `<file>` list cannot be read against the tree: today
`manifestFiles` sidesteps that by enumerating one element per resolved file, so
a directory of images is hundreds of lines that all have to be regenerated when
one image is added. With one path the pattern the author wrote is both the source
and the `<file src>`, so the generated file stays the size of the manifest.

Renaming is removed, not reshaped. A file that must land somewhere else is moved
in the project.

## Scope

- **In:** The entry shape, matching, ordering, emission as written, and the
  removal of `assets`.
- **Out:** `download="false"` and the other `<file>` attributes, which have no
  consumer yet and are excluded by ADR-017's rule.

## Steps

- [ ] Replace `AssetMapping[]` with an ordered `string[]`, under the same glob
      grammar and the same containment rules as `scripts`.
- [ ] Copy each matched file to the path the pattern describes, and record the
      entry that produced it so a collision names the entry rather than the file.
- [ ] Emit one `<file>` per entry carrying the entry's own text, not one per
      resolved file.
- [ ] Keep every destination in the one output index ADR-017 established —
      scripts, helpers, libraries, the generated `meta.xml` and files — and report
      `config-output-collision` when two entries claim one path, even when the
      bytes match.
- [ ] Report `config-empty-file-entry` for an entry that matched nothing, reusing
      the message shape 49.06 built.
- [ ] Keep `.env` out of the `<file>` list, as `manifestFiles` does today. A
      client that can download the environment file is the one case where the
      literal-emission rule must not apply.

## Acceptance Criteria

- [ ] `files = { 'assets/images/**/*.png' }` emits exactly one `<file>` element
      with that pattern, whatever the number of matching files.
- [ ] Every matching file reaches the resource at the path the pattern describes.
- [ ] Entry order is element order.
- [ ] An entry that matches nothing fails the build naming the entry.
- [ ] Two entries claiming one destination report `config-output-collision` with
      both positions.
- [ ] `.env` never appears in the generated file, and a `files` entry that would
      match it is an error rather than a silent drop.
- [ ] `assets` is in `REMOVED_FIELDS` naming `files`, and the message says that
      `to` has no replacement.
