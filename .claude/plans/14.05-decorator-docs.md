# 14.05 - Document decorators in the language reference

> File: `.claude/plans/14.05-decorator-docs.md`
> The naming rule is the whole feature. If an author has to run the compiler to
> learn whether their field produces `getEnabled` or `isEnabled`, the
> documentation has failed.

## Objective

Give decorators a section in the language reference that an author can read once
and then predict every name the compiler will generate.

## Scope

- **In:** A `Decorators` section in `language-design.md`, the naming table, the
  diagnostic list, the README language surface, and the changelog entry.
- **Out:** ADR-009 itself, written in 16.1 as part of the design decision.

## Steps

- [ ] Add a `Decorators` section to `.claude/docs/language-design.md`, placed
      after `Classes and Inheritance` and before `Interfaces and Aliases`. It
      states the syntax, that decorators bind to the next declaration, that names
      are not keywords, and that `@Getter`/`@Setter` are the only two.
- [ ] Include the naming table verbatim from
      [14.02](14.02-getter-setter-accessors.md), with the
      `isAdmin` and the `island` rows, since those are the two an author guesses
      wrong.
- [ ] State the booleanness rule as what it is: the *resolved* type decides. A
      field typed through an alias, an optional `enabled?: boolean`, and a field inferred
      from a `true`/`false` default all produce `is`. Say what does not: a union
      that merely contains `boolean`, and an untyped field.
- [ ] Note that the accessor's signature shows the annotation the author wrote —
      `admin: Flag` gives `isAdmin(): Flag` — so the reader is not surprised that
      the name follows the resolved type while the type text does not.
- [ ] Show the generated Lua for a small decorated class, next to the Luam that
      produced it, in the style the class section already uses.
- [ ] List the diagnostics — `check-unknown-decorator`, `check-decorator-target`,
      `check-decorator-conflict`, `check-duplicate-decorator`,
      `parse-unexpected-decorator`, `parse-decorator-arguments` — with the source
      that triggers each.
- [ ] Say plainly what decorators are *not*, so the next reader does not have to
      infer it from absence: no arguments, no user-defined decorators, and
      nothing outside a class.
- [ ] Update the language surface list in the root `README.md` and add the
      `CHANGELOG.md` entry.
- [ ] Update `.claude/docs/roadmap.md` with what the milestone decided during
      implementation, in the form the earlier milestones use.

## Acceptance Criteria

- [ ] An author can predict the generated name for any field from the
      documentation alone, without reading the compiler.
- [ ] Every diagnostic code the milestone introduces appears in the docs with a
      snippet that produces it.
- [ ] The Lua sample in the docs matches the committed fixture snapshot — if the
      emitter changes, the doc sample is wrong and a reviewer can see it.
- [ ] All new prose is English, and links resolve.
- [ ] `.claude` is never linked from a public file. The README describes the
      feature; it does not point at the internal docs.
