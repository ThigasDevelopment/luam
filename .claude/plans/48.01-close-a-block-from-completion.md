# 48.01 - Close a block from the completion list

## Objective

Offer the keyword that closes the open block as one completion item that writes
the whole block, so `if 1 + 1 == 2 the|` completed with Enter lands on an empty
indented line between `then` and its `end`.

## Scope

- **In:** A block scanner for the LSP, the closer items `then .. end`,
  `do .. end` and `until condition`, and their wiring into `completionAt`.
- **Out:** Scaffolds typed from the opening keyword — `if`, `for`, `while`,
  `function` — which are 48.02. Also out: `else` and `elseif` continuations,
  the brace blocks of `class`, `interface` and `enum` (the editor already closes
  `{`), and reformatting code the user did not just type.

## Why the language server and not a snippets file

A VS Code `snippets` contribution is the cheap version and it is the wrong one.
It serves one editor, while the language server serves every client that speaks
LSP, and it knows nothing about the document: it would offer `then .. end`
inside a string, inside a call argument, and on a block that already has its
`end`. The scanner this task adds is what makes the item contextual, and the
same scan answers whether a second `end` is wanted at all.

## Steps

- [ ] Export `advance` and `ScanState` from
      [source-context](../../packages/lsp/src/features/source-context.ts). It is
      already the one scanner in the LSP that knows where strings and comments
      begin and end, and a second reader should drive it rather than copy it.
      Do not grow that file — it already sits at the 250-line convention.
- [ ] Add `packages/lsp/src/features/block-context.ts`, driving that scanner
      across the whole document and reading identifier runs while the mode is
      `code`:
      - Push a frame on `if`, `for`, `while`, `function` and `repeat`, and on a
        `do` that is not the `do` closing a `for` or `while` header.
      - Pop on `end`, and on `until` for a `repeat` frame.
      - Carry `headerOpen` per frame: true for `if`, `for` and `while` until
        their `then` or `do` is read; `elseif` reopens the header of the frame it
        continues; `function`, `do` and `repeat` frames are never header-open.
      - Snapshot the top frame as the walk crosses the completion offset, then
        keep walking to the end of the file so the result also reports whether
        that frame ever receives its `end`.
      - Return `{ frame, unbalanced }`.
- [ ] Add `packages/lsp/src/features/block-completion.ts` mapping a frame to its
      closer: an `if` or `elseif` header wants `then`, a `for` or `while` header
      wants `do`, a `repeat` frame wants `until`. Nothing else produces an item.
- [ ] Build the items the way
      [event-handler-snippet](../../packages/lsp/src/features/event-handler-snippet.ts)
      already builds its scaffold:
      - `label: 'then .. end'`, `filterText: 'then'` so the word being typed
        still matches, `kind: CompletionItemKind.Snippet`, and a `detail` in the
        one wording the hovers use — `then ... end — close the if block`.
      - `insertText: 'then\n    $0\nend'` with `InsertTextFormat.Snippet` and
        `InsertTextMode.adjustIndentation`, the pair `constructorItem` in
        [completion-items](../../packages/lsp/src/features/completion-items.ts)
        already relies on to keep a nested block aligned.
      - `until` inserts `until ${1:condition}` and no `end`.
- [ ] Honour the client. `completionAt` already receives `snippets` from
      `useSnippets`; when it is false, emit the same block as plain text with no
      tab stop rather than leaking `$0` into the buffer.
- [ ] Rank it. Give the closer `sortText: '0then'` so it precedes the plain
      `then` from `KEYWORD_ITEMS`, and set `preselect` only when the scan
      reported the block unbalanced. A block that already has its `end` still
      offers the item, one row lower and unselected, so Enter does not write a
      second `end` into working code.
- [ ] Call it from
      [completion](../../packages/lsp/src/features/completion.ts) after the
      trigger, type-position and directive guards, and only when
      `expectedArgument` returned null — a call argument is no place for a block.
      Leave `KEYWORD_ITEMS` alone; the plain keyword stays available.

## Acceptance Criteria

- [ ] In `if 1 + 1 == 2 the|` the list offers `then .. end` first, and accepting
      it produces `if 1 + 1 == 2 then`, an indented empty line holding the
      cursor, and `end` at the header's indentation.
- [ ] `for index = 1, 10 d|` and `while running d|` offer `do .. end`; a line
      inside a `repeat` offers `until condition`.
- [ ] Nothing is offered inside a string, inside a comment, in a type position,
      after `.` or `:`, or inside a call's arguments.
- [ ] `if ready the|` on a block that already ends is offered without
      `preselect`, so Enter picks the plain keyword.
- [ ] A client that reports no snippet support receives plain text and no `$0`.
- [ ] `source-context.ts` gains only the two `export` words; the block walk lives
      in its own file and both new files stay inside the conventions.
- [ ] `pnpm -r test`, `pnpm lint` and `pnpm typecheck` pass.
