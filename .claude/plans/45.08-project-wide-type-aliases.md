# 45.08 - Publish a type alias to the project, the way an interface already is

> File: `.claude/plans/45.08-project-wide-type-aliases.md`

## Objective

Make `type` reach the whole resource like `interface`, `class` and `enum` do, so
the choice between an alias and an interface is about the shape being described
and not about which files may read it.

## Reproduction

```luam
# src/shared/a.luam
type Alias = 'x' | 'y'
interface Iface { v: number }
```

```luam
# src/shared/b.luam
local a?: Alias = nil    # check-unknown-type: Type "Alias" is not defined.
local i: Iface = { v = 1 }   # accepted
```

Both declarations sit in the same directory, in the same environment, in the same
project. One crosses the file boundary and the other does not, and nothing in the
language documents the difference.

The ported resource hit it twice: `VehicleGarageType`, declared beside the
`Vehicle` class in `src/shared/entities`, is unknown in
`src/server/services/vehicles.service.luam`; `Position`, declared in a shared
declaration file, is unknown in `src/client/pages/dealership.page.luam`.

## Context

`check-unknown-type` is a warning, so the code still compiles — with the name
degraded to an unchecked `named` type. That is worse than an error: the annotation
looks like it is doing work and is not.

## Scope

- **In:** Alias declarations entering the project declaration surface, the
  environment rules that already scope a declaration to a side, duplicate-name
  reporting across files, and the editor surfaces that list types.
- **Out:** `local enum`, which is deliberately file-scoped and stays so. Any
  import syntax. Any change to the emitted Lua: an alias is erased.

## Steps

- [ ] Record an alias in the project declaration registry beside interfaces,
      classes and enums, keeping its environment so a `server` alias stays out of
      a `client` file exactly as a `server` interface does.
- [ ] Report two files declaring the same alias name as a duplicate, with the same
      code and shape as the existing duplicate-class diagnostic, and decide
      whether a `local type` file-scoped form is worth adding — the
      recommendation is no, since no other type form has one and `local enum`
      exists only because an enum emits a value.
- [ ] Resolve a generic alias across files with its parameters intact.
- [ ] Make the deferred unknown-type check consult the project surface, so a
      forward reference to an alias in a later file does not warn.
- [ ] Offer a project alias in completion and resolve go-to-definition to its
      declaring file.

## Acceptance Criteria

- [ ] The reproduction compiles with no warning, and `Alias` narrows as it does
      inside its own file.
- [ ] The two occurrences from the ported resource compile.
- [ ] A `server` alias used in a `client` file reports the environment diagnostic
      an interface reports.
- [ ] Two files declaring `type Alias` report one duplicate diagnostic.
- [ ] Go-to-definition on a cross-file alias lands on its declaration.
- [ ] The emitted Lua and the manifest are unchanged.
