# 32.04 - Correct the generic-classes claim and the stale project memory

## Objective

Fix three places where the documentation describes a Luam that no longer exists:
a comparison page that denies a shipped feature, and two clauses in the project
memory that describe a file name and a network contract the product moved past.

## Scope

- **In:** The generic-classes claim in `comparison.md` in both languages, and the
  `luam.json` and network-contract clauses in `.claude/CLAUDE.md`.
- **Out:** Any code change. Every item here is wording; the behaviour each one
  describes is already correct.
- **Out:** A general documentation audit. These are three known defects, not a
  sweep.

## Context

### Generic classes are supported and the docs deny it

[comparison.md:67](../../docs/en/guide/comparison.md) tells a developer arriving
from TypeScript that "Generic classes are not supported" and links to
[limitations](../../docs/en/reference/limitations.md) for the detail. Both halves
are wrong:

- [classes.md](../../docs/en/language/classes.md) documents `## Type parameters`
  in full — `class Box<T>`, inference from the constructor argument,
  `extends Box<T>` forwarding and pinning, `T extends Shape` constraints, and
  erasure at emit — along with `check-generic-arity`,
  `check-generic-constraint` and `check-generic-depth`.
- `limitations.md` has carried no generic-classes entry since milestone 24. The
  changelog for that release records the entry being rewritten, and the link now
  points at a page that does not discuss the subject.

`docs/pt-br/guide/comparison.md:69` carries the same claim in Portuguese.

The effect is the worst kind of documentation defect: the page a newcomer reads
first talks them out of a feature that works.

### The project memory names a file that was renamed

`.claude/CLAUDE.md` states that `luam init` "scaffolds `luam.json` and nothing
else". It writes `.luam.manifest`, and has since milestone 20 made the manifest
the project contract — see [cli.md](../../docs/en/tooling/cli.md), which
documents `luam init` writing one file by that name. `luam.json` appears more
than once in the memory file.

### The network contract undercounts by one

`.claude/CLAUDE.md` says a shipped build has "exactly one allowed call, in the
`cli`": the build-time lookup of the latest MTA release. `luam setup` makes a
second one — `packages/cli/src/editor/editor-service.ts` downloads the release
VSIX from GitHub when the editor's marketplace install does not succeed.

The invariant the contract exists to protect is untouched: `setup` is not a
build, and a build with no network still succeeds. The wording is what is wrong,
and a contract that is literally false is a contract nobody can enforce.

## Steps

### T-01 - Correct the generic-classes claim

**Agent:** documentation-engineer

- [ ] Replace the claim in `docs/en/guide/comparison.md` with what is true, and
      point it at [classes](../../docs/en/language/classes.md#type-parameters).
- [ ] Mirror the change in `docs/pt-br/guide/comparison.md`.
- [ ] Grep both trees for any other page that repeats the claim or links to
      `limitations` for it.
- [ ] Add a changelog entry, since this changes what the docs promise.

### T-02 - Correct the project memory

**Agent:** documentation-engineer

- [ ] Replace every `luam.json` occurrence in `.claude/CLAUDE.md` with
      `.luam.manifest`, and confirm each surrounding sentence still describes
      current behaviour.
- [ ] Reword the network contract so the CLI's two calls are both named: the
      build-time MTA release lookup, and the `setup` VSIX download. Keep the
      invariant sentence — the compiler packages make no network calls, and a
      build with no network still succeeds — exactly as it stands.
- [ ] Check `.claude/docs/` for the same two drifts.

- [ ] `.claude/CLAUDE.md` contains no `luam.json`.

      states the invariant unchanged.
