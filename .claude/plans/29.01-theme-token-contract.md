# 29.01 - Define the theme token contract and palette

## Objective

Establish one editor-agnostic source of truth — a palette, a role table, and a
distinctness rule — that every Luam theme is generated from, so a minimal set of
colours still gives every element of the language its own reading.

## The Design Problem

Minimal and differentiate-everything pull against each other only if
distinctness is treated as global. It is not. Two roles that can never occupy
the same syntactic position — a block comment and a type alias — may share a
style without ever being confused. Two roles that compete for the same position
— an MTA native and a user function at a call site — must not.

So the contract defines **confusion sets**: groups of roles that can appear in
the same position. Distinctness is required *inside* a set and reused *across*
sets. That is what keeps the hue count at four while every element still reads.

## Scope

- **In:** A new `packages/theme` package holding the palette, the role table,
  the confusion sets, and the light and dark value assignments. Roles for both
  `source.luam` and `source.luam-manifest`, plus editor chrome and diagnostics.
- **Out:** Any generated theme file, any grammar change, any LSP change. This
  task produces the contract the rest of the milestone consumes.

## Design Rules

These are normative. Every later task and every test in 31.6 enforces them.

**R1 - Four syntax hues, one neutral, one reserved.** Neutral ink for names,
cyan for what the compiler erases, violet for what survives into Lua, sand for
values. Red is reserved for diagnostics and is never a syntax colour.

**R2 - Cyan means compile-time.** A cyan token has no counterpart in the emitted
Lua: type annotations, `interface`, `type`, `declare`, decorators, strictness
directives, and every type name. Violet marks the opposite — `class`, `enum`,
`new`, `constructor`, `local`, `function`, and control flow all emit code. This
makes the erased layer legible at a glance, and it is the one rule a user learns
that pays for the whole theme.

**R3 - Three axes, in this order.** Hue carries meaning, value step carries
specificity (strong / base / muted), style carries provenance. Bold marks a
definition site. Italic marks something the user did not write — Lua stdlib, MTA
natives, and symbols from declaration files. Underline is unused.

**R4 - Distinctness holds inside a confusion set.** Two roles in the same set
must differ in at least one axis, and if they differ only in value step the
contrast between them must be measurable (see R5).

**R5 - Contrast is a number, not a judgement.** Body text against the editor
background is at least 4.5:1 on both themes. Ambient roles — comments,
punctuation — are at least 3:1. Two roles in one confusion set separated only by
value step are at least 1.6:1 against each other.

**R6 - One documented exception.** The environment directive is tinted by
environment: `server` cyan-strong, `client` violet-strong, `shared` ink-2, all
bold. It breaks R2 deliberately, on exactly one token at the top of a file,
because a file's environment is the single most consequential fact about it.

## Steps

### T-01 - Scaffold `packages/theme`

**Agent:** architecture-engineer

- [ ] Create the package with no runtime dependency on any other Luam package.
      It is data plus pure functions; the compiler must never import it, and it
      must never import the compiler.
- [ ] `src/palette.ts` holds the two ramps as named steps, seeded from the
      documentation tokens already in `docs/.vitepress/theme/tokens.css` so the
      site, the icon, and the editor read as one product: ink, cyan `#34c9e0` /
      `#0b6e82`, violet `#a78bfa` / `#6d3ff0`, sand `#e0a44a` / `#9a6206`, and
      red `#f87171` / `#c0392f`.
- [ ] Extend each hue to the three steps R3 requires, and record how the strong
      and muted steps were derived so a later hue is added the same way.

### T-02 - Write the role table

**Agent:** architecture-engineer

- [ ] `src/roles.ts` enumerates every role as `{ id, confusionSet, hue, step,
      style, description }`. The id is the theme's own vocabulary, not a
      TextMate scope — mapping to scopes and to semantic tokens happens in 31.4.
- [ ] Cover the six confusion sets below in full. Every scope the two grammars
      emit today, and every semantic token 31.3 adds, must land on a role.

**Set 1 - callables at a call site.** User function `ink`; method `ink-2`;
constructor `violet`; MTA native `ink` italic; Lua stdlib `ink-2` italic;
decorator `cyan-strong` italic.

**Set 2 - names in a declaration head.** Class `cyan-strong` bold; interface
`cyan` bold; enum `cyan-strong` bold; type alias `cyan-2` bold; inherited name
after `extends` or `implements` `cyan`; type parameter `cyan-2`.

**Set 3 - identifiers in an expression.** Local `ink`; parameter `ink-2`;
property or field `sand-2`; enum member `sand`; `self` and `super` `violet-2`;
vararg `violet-2`; unresolved global `ink-2` italic.

**Set 4 - keywords in a statement head.** Control flow `violet`; `local` and
`function` `violet-2`; runtime declaration keywords `violet-strong` bold; erased
declaration keywords `cyan-strong` bold; modifiers `violet-2`; the `export` and
`http` build directives `violet-strong`; strictness directive `cyan-2`;
environment directive per R6.

**Set 5 - literal values.** String `sand`; long bracket string `sand-2`;
template string `sand`; escape `sand-strong`; number `sand-strong`; boolean and
`nil` `violet-2`; interpolation delimiters `sand-2`, with the embedded
expression falling back to ordinary code colours.

**Set 6 - type positions.** Primitive `cyan-2`; named type `cyan`; the
annotation `:` and optional `?` `cyan-3`; union and intersection `cyan-3`;
generic brackets `cyan-3`; array suffix `cyan-3`.

- [ ] Add the editor chrome group: background, gutter, line highlight,
      selection, matching bracket, indent guide, inlay hint, and the four
      diagnostic severities. Red appears here and nowhere else.

### T-03 - Encode the constraints as data

**Agent:** architecture-engineer

- [ ] `src/constraints.ts` exports the confusion sets and the contrast floors
      from R5 as values, not prose, so 31.6 asserts against the contract itself
      rather than a copy of it.
- [ ] Add a `contrast(a, b)` helper implementing WCAG relative luminance. It is
      the only math in the package and it is pure.

### T-04 - Resolve the two themes

**Agent:** architecture-engineer

- [ ] `src/resolve.ts` turns `(role, mode)` into a concrete `{ foreground,
      fontStyle }`, and the chrome group into concrete colours. The generators in
      31.4 and 31.5 call only this.
- [ ] Both modes resolve from the same role table. A mode may not add, drop, or
      re-map a role — only the ramp changes.

## Acceptance Criteria

- [ ] `packages/theme` builds and typechecks, and imports nothing from the other
      packages.
- [ ] Every scope name present in `syntaxes/luam.tmLanguage.json` and
      `syntaxes/luam-manifest.tmLanguage.json` maps to exactly one role.
- [ ] Every role declares a confusion set; no role is orphaned.
- [ ] R2 holds mechanically: no role tagged as emitting Lua resolves to cyan and
      no erased role resolves to violet, apart from the R6 exception, which is
      marked as such in the data.
- [ ] `resolve()` is total for both modes over the full role table.
