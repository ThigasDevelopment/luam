# 11.3 — Gate the OOP API on the `oop` setting and emit the manifest tag

> File: `.claude/plans/11.3-oop-gate-and-manifest-architecture-engineer.md`
> This is the task that makes the feature worth having: the compiler guarantees
> the code and the manifest agree about whether the OOP API exists.

## Objective

Tie the OOP surface to `"oop": true` in `luam.json`, so a project that did not
enable it gets a diagnostic instead of a runtime `attempt to call a nil value`,
and a project that did gets the tag in `meta.xml`.

## Scope

- **In:** The `oop` configuration field, `<oop>true</oop>` in the manifest, the
  diagnostic for an OOP call in a project with the API disabled.
- **Out:** The catalog (11.1), member resolution (11.2), the editor (11.4).

## Steps

- [x] Add `oop: boolean` to `LuamConfig`, defaulting to `false`, validated like
      every other field.
- [x] Emit `<oop>true</oop>` above `<info>` when the field is `true`, and emit
      nothing when it is `false`. This is the first manifest element with text
      content rather than attributes, so `generateManifest` grows one helper.
- [x] Thread the flag into the compiler through `CompileOptions`, the way
      milestone 10 threaded `resourceName`, and fold it into the ambient cache
      key so flipping it rechecks the project.
- [x] Register the element classes only when the flag is on.
- [x] Report `check-oop-disabled` for a method call on an element type when the
      flag is off, naming the procedural function to use instead and the
      `luam.json` field that enables the API.
- [x] Confirm a project with `oop` off produces a manifest byte identical to the
      one it produced before this milestone.

## Acceptance Criteria

- [x] `"oop": true` puts `<oop>true</oop>` immediately above `<info>`; `false`
      or absent emits no element.
- [x] With the flag on, `player:getName()` checks. With it off, the same line is
      `check-oop-disabled` and the message names `getPlayerName`.
- [x] Flipping the flag invalidates the cache and rechecks every file.
- [x] A project with `oop` off is unaffected in every other respect.
- [x] `pnpm typecheck`, `pnpm build`, and `pnpm test` pass.
