# 52.01 - Compile the generated Lua to bytecode

## Objective

Give `build.details.obfuscate` the consumer ADR-047 named for it, so the field
stops reporting `config-unimplemented-option` and starts changing the artifact.

## Scope

- **In:** Compiling every generated Lua file through `luac`, the toolchain lookup,
  the failure path when `luac` is absent, and the option's diagnostic.
- **Out:** Any other form of obfuscation. Renaming locals, stripping strings and
  control-flow flattening are separate questions with separate costs.

## Steps

- [ ] Find `luac` the way the build finds any external tool, and report its
      absence as a build error naming what to install rather than falling back to
      source silently.
- [ ] Compile every generated Lua file after minification and before the write, so
      the bytecode is what the resource ships and the source never reaches it.
- [ ] Decide what the resource map means for a bytecode build, and either keep it
      accurate or say in the manual what it gives up.
- [ ] Remove `unimplemented` from the field in the catalog and delete the
      `config-unimplemented-option` path once nothing declares it.

## Acceptance Criteria

- [ ] `obfuscate = true` writes bytecode a real MTA server loads.
- [ ] `obfuscate = false` and an absent `obfuscate` write source, byte for byte
      what they write today.
- [ ] A missing `luac` fails the build with a message naming what to install.
- [ ] `config-unimplemented-option` is reported by nothing.
