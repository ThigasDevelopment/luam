# 39.01 - Add luam format with a check mode

## Objective

Make the formatter reachable without an editor, so a contributor on any setup can
format a project and a pipeline can assert that a branch is already formatted.

## Scope

- **In:** A `luam format` command that rewrites files in place, a `--check` mode
  that writes nothing and reports what differs, the file selection rules, and the
  exit codes.
- **Out:** New formatting rules. The style is fixed, recorded in
  `docs/*/reference/formatting.md`, and this command renders it — it does not
  extend it.
- **Out:** Formatting `.luam.manifest`. Decide in T-01 whether the manifest is in
  scope; it is a Luam file parsed like any other, so the answer is probably yes,
  but it is a decision rather than an assumption.

## Context

Milestone 32 built the formatter and deliberately excluded a CLI:

> A `luam format` CLI command. The editor is the surface here; what CI enforces
> is a later question.

This is that later question. The formatter is idempotent, preserves comments,
compiles to byte-identical Lua across the corpus, and yields no edits for a file
that fails to parse. It is exposed as two pure functions in
`packages/compiler/src/format/format.ts`:

- `formatSource(source: string): string | null`
- `formatRange(source: string, startLine: number, endLine: number): RangeEdit | null`

`null` means the file did not parse. Both are already consumed by
`packages/lsp/src/features/formatting.ts`. A CLI command is a file walk, a call
to the first function, and a write — the engine is done.

Two things make it worth doing rather than leaving to the editor. A contributor
without the extension has no way to satisfy a style the project asks for. And
milestone 36 deferred automated enforcement of `code-conventions.md` because "the
workspace has no linter or formatter" available to a pipeline; `--check` is the
half of that which already exists.

## Design

### Two modes, three exit codes

| Invocation | Effect | Exit |
|---|---|---|
| `luam format` | Rewrites every selected file that differs. | `0` |
| `luam format --check` | Writes nothing. Lists files that differ. | `0` if none differ, `1` if any do |
| Either, with an unparseable file | Reports it and does not touch it. | `1` |

`1` is the CLI's existing meaning — the command reported diagnostics — and
`--check` finding differences is exactly that. `2` stays reserved for an invalid
command line or configuration.

### What gets formatted

The manifest's `sources` patterns, the same set `luam check` compiles, plus
`.d.luam` declaration files. Not `node_modules`, not generated output, not the
`outDir`. A path argument narrows the selection to one file or directory; with no
argument, the whole project.

Library sources from [38.01](38.01-libraries-manifest-domain.md) are never
formatted. They belong to another package, and rewriting a file inside
`node_modules` is wrong however it is spelled.

### A file that does not parse

`formatSource` returns `null` and the command reports the file and moves on. It
does not run the checker and does not report type errors — that is `luam check`,
and a formatter that also type-checks blurs two commands whose exit codes mean
different things. Decide in T-01 whether an unparseable file makes the whole run
exit `1` or whether it is a warning; prefer `1`, since a file the formatter
cannot read is a file the command failed to format.

### Idempotence as a runtime assertion

The formatter is idempotent by construction and by test. The command should not
re-verify that per file at runtime, which would double the work on every
invocation for a property the suite already pins. T-03 records that decision
rather than leaving it to look like an omission.

## Steps

### T-01 - Decide the selection and failure rules

**Agent:** architecture-engineer

- [ ] Decide whether `.luam.manifest` is formatted.
- [ ] Decide whether an unparseable file fails the run or warns.
- [ ] Confirm library sources are excluded, and generated output with them.
- [ ] Decide whether a path argument is supported in the first version, and if so
      how it interacts with the manifest's patterns.

### T-02 - Register the command

**Agent:** architecture-engineer

**Files:** `packages/cli/src/cli/registry/`, `packages/cli/src/commands/`

- [ ] Add `format-registration.ts` and `format-command.ts`, following the shape
      of the existing eleven registrations.
- [ ] Own `--check` on this command only, so passing it elsewhere exits `2` as
      the registry already enforces.
- [ ] Accept `--cwd`, `--manifest` and `--no-color`, matching the commands that
      load a project.

### T-03 - Implement it

**Agent:** architecture-engineer

- [ ] Walk the selected files, call `formatSource`, and write only those that
      differ.
- [ ] In `--check`, write nothing and list what differs, one path per line.
- [ ] Report an unparseable file per T-01.
- [ ] Record the decision not to assert idempotence at runtime.
- [ ] Report a summary in the CLI's existing style — files scanned, files
      changed or differing, duration.

### T-04 - Confirm it agrees with the editor

**Agent:** architecture-engineer

- [ ] Confirm the command and the LSP formatting provider produce identical
      output for every file in `docs/snippets` and the compiler fixtures.
- [ ] Confirm the repository's own `.luam` corpus is already a fixed point, so
      `--check` passes on a clean checkout.

## Acceptance Criteria

- [ ] `luam format` rewrites a badly formatted file and leaves a formatted one
      untouched.
- [ ] `luam format --check` writes nothing, lists what differs, and exits `1` when
      anything does and `0` when nothing does.
- [ ] A second run of `luam format` changes nothing.
- [ ] A file that does not parse is reported and not written.
- [ ] Library sources and generated output are never formatted.
- [ ] The command and the LSP agree byte for byte across the corpus.
- [ ] `--check` on the current default branch exits `0`.
- [ ] Passing `--check` to another command exits `2`.

## Out of Scope

- New or configurable formatting rules.
- Type checking. That is `luam check`.
- Enforcing this in a pipeline, which is [39.04](39.04-conventions-gate.md).

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The command and the editor disagree on some construct | High | T-04 compares both across the whole corpus, not on samples |
| A file inside `node_modules` is rewritten | High | Excluded in T-01 and asserted in T-03 |
| `--check` exits `0` on a file it could not parse, hiding a problem | Medium | T-01 decides the failure rule explicitly |
| A partial write leaves a file truncated | Medium | Write whole files; a file that differs is replaced, never patched |
