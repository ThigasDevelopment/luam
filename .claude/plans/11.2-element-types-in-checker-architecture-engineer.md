# 11.2 — Model MTA element types as classes in the checker

> File: `.claude/plans/11.2-element-types-in-checker-architecture-engineer.md`
> The checker already resolves members on a user class through
> `DeclarationRegistry`. This task feeds the MTA element classes into the same
> path instead of inventing a second one.

## Objective

Make `player:getName()` resolve to a typed method call, with the receiver's
element type known, inheritance followed, and an unknown member reported.

## Scope

- **In:** Registering the generated `ApiClass` set as ambient declarations,
  member resolution through the element hierarchy, the return type of a
  procedural function that yields an element.
- **Out:** The `oop` gate (11.3), completion and hover (11.4).

## Steps

- [x] Feed the generated OOP surface into the declaration registry the way
      milestone 6 feeds cross-file classes, so member lookup and the `__super`
      walk are the existing code paths.
- [x] Type a procedural function that returns an element with the element class
      rather than `any`, so `local player = getPlayerFromName(name)` gives a
      `Player` and not an opaque userdata.
- [x] Resolve a method call against the class and its superclasses, and report
      `check-unknown-member` naming the class for a member that does not exist.
- [x] Check argument count and types on an OOP method against the signature the
      procedural function declares.
- [x] Keep the environment rule: calling a server-only method from a client file
      is `check-environment-api`, with the same message shape the procedural
      form already produces.
- [x] Confirm the emitter is untouched. `player:getName()` emits
      `player:getName()`; the compiler never rewrites it into the procedural
      call.
- [x] Measure the cost of seeding the element classes per file, and cache per
      environment the way `builtinSymbols` already does if it shows up.

## Acceptance Criteria

- [x] `player:getName()` on a `Player` type checks with no diagnostic and
      returns `string`.
- [x] `player:getNam()` reports `check-unknown-member` and names `Player`.
- [x] A method inherited from `Element` resolves on a `Player`.
- [x] `getPlayerFromName('x')` is typed `Player`, and a wrong argument to an OOP
      method is `check-type-mismatch`.
- [x] A server-only method called from a client file is `check-environment-api`.
- [x] The generated Lua for a file using OOP calls is unchanged by the checker.
- [x] The cold build benchmark does not regress beyond the margin recorded in
      [performance.md](../docs/performance.md).
