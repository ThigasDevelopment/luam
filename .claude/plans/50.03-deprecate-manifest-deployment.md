# 50.03 - Deprecate the deployment fields in the resource manifest

## Objective

Make `.luam.server` the answer to "where does this deploy" without breaking a
single project that already answers it in `.luam.manifest`.

## Why not simply remove them

`transport` was removed outright and lives in `REMOVED_FIELDS`
([manifest-fields](../../packages/compiler/src/manifest/manifest-fields.ts)),
which is the right tool for a field that never worked. `serverPath` works, is
documented, is in the quick start, and is set by every project that has ever run
`luam dev`. Removing it in a minor would break all of them for a benefit they get
anyway from precedence. The fields keep working, lose to the workspace file, and
join `REMOVED_FIELDS` in a future major.

## Scope

- **In:** Precedence, one warning per manifest, and the resolution helper both
  modes share.
- **Out:** Moving the fields out of `MANIFEST_FIELDS`, which is a major-version
  change, and `development.logs`, which stays in the manifest as well as gaining
  a workspace default — see below.

## The rule

| Field | With a `.luam.server` above | With none |
|---|---|---|
| `serverPath` | workspace wins, warn once | manifest, as today |
| `resourcesDir` | workspace wins, warn once | manifest, as today |
| `development.server.executable` | workspace wins, warn once | manifest, as today |
| `development.logs` | workspace is the default, manifest overrides, no warning | manifest, as today |

`logs` is the one field that is not deployment. It tunes a relay injected into
one resource's generated code, so a resource is entitled to its own value; the
workspace file only supplies the default for resources that state none. That
distinction is the whole reason the table has a fourth row instead of three.

## Steps

- [ ] Add `resolveDeployment(resourceRoot, config, workspace)` in the CLI config
      layer, returning the effective server root, resources directory, executable
      and log settings. Every caller that reads `config.serverPath` today goes
      through it: `resolveServerTarget`, `startMtaServer`, `resolveServerLogPath`,
      `runDevCommand` and `runEnsureCommand`.
- [ ] Emit `config-deployment-moved` as a warning, once per manifest, naming
      every overridden field in one message and the path of the `.luam.server`
      that won. Three warnings for three fields in one file is three times the
      noise for one fix.
- [ ] Anchor the warning at the position of the first overridden field, through
      the same `PositionLookup` the other manifest diagnostics use, so the editor
      underlines the line to delete.
- [ ] Leave the fields in `MANIFEST_FIELDS` with their summaries updated to name
      `.luam.server` as the place they now belong.
- [ ] Add the migration entries to `REMOVED_FIELDS` **commented out**, with the
      major they are scheduled for, so the next person to open that file finds the
      decision instead of re-deciding it.
- [ ] Check `warningsAsErrors` against this warning deliberately: a project that
      promotes warnings and has not migrated would stop building. It should — that
      is what the option means — and the acceptance below states it so nobody
      treats it as a regression.

## Acceptance Criteria

- [ ] With a `.luam.server` above it, a manifest setting `serverPath` syncs to the
      workspace's server and warns once naming both files.
- [ ] A manifest setting `serverPath`, `resourcesDir` and
      `development.server.executable` warns exactly once, listing the three.
- [ ] A manifest setting none of them under a workspace warns nothing.
- [ ] With no `.luam.server` anywhere above, every one of those fields behaves
      byte-for-byte as it did before this milestone, and nothing warns.
- [ ] `development.logs` in a manifest overrides the workspace value silently;
      with no manifest value the workspace value applies.
- [ ] `warningsAsErrors = true` turns `config-deployment-moved` into a build
      failure, and the message says what to delete.
- [ ] `luam check` reports the warning too, not only `build`, `ensure` and `dev`.
- [ ] `pnpm -r test`, `pnpm typecheck` and `pnpm conventions` pass.
