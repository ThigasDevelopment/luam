# 45.16 - Decide what replaces instantiating a class the code names at runtime

> File: `.claude/plans/45.16-runtime-named-instantiation.md`

## Objective

Answer the one pattern in the ported resource that has no Luam spelling at all,
either with a language surface or with a recorded refusal and a documented
replacement.

## Reproduction

The resource's whole loading order rests on two moves. A class name is bound to a
factory value:

```lua
RedisAdapter = new "RedisAdapter"
DealershipBuyEvent = new "DealershipBuyEvent"
```

and the registry is then walked to construct everything by naming convention:

```lua
for name, value in pairs(_G) do
    if name:find("Adapter") then
        _G[name] = value(self)
    end
end

for name, value in pairs(_G) do
    if name ~= "Event" and name:sub(-#("Event")) == "Event" then
        self.events[name] = value
    end
end
```

Three modules do this: `Core.loadAdapters`, `EventsModule` and `ListenersModule`.

In Luam, `new` is an operator over a class **name**, resolved at check time. There
is no value that stands for a class and no way to instantiate one the program
names at runtime. The runtime library already exposes `getClass(name)` and
`getClasses()` — the LSP completes them and the catalog types them — so the
capability exists below the language and is unreachable from it.

## Context

CLAUDE.md is explicit that there is no framework: `Core`, `Listener`, `Command`
and auto-loading are reference sketches in `examples/framework`, not part of the
language. That settles whether Luam should ship the pattern. It does not settle
whether a resource that already has one can be ported, which is what this task is
about.

## Options Considered

| Option | Ports the resource | Keeps the type surface | Decision |
|---|---|---|---|
| Do nothing | No | — | Reject — the gap is real and undocumented |
| Type `getClass(name)` as an opaque table and document the pattern as untyped | Yes, with `any` at the boundary | Weakly | Candidate |
| An explicit registry the author writes: a table of class values, iterated normally | Yes | Yes | Candidate |
| A `classof Name` expression producing a first-class, constructible class value | Yes | Yes | Candidate — largest surface |
| Dynamic `new expression` | Yes | No — the constructor cannot be checked | Reject |

This plan chooses between the three candidates. It does not presume the answer.

## Scope

- **In:** The decision, an ADR recording it, and whichever of the three candidates
  it selects. The `examples/framework` sketches updated to the chosen form.
- **Out:** Auto-loading itself, which stays out of the language. Any change to
  `class.lua` beyond what the chosen option requires. Reflection over fields or
  methods.

## Steps

- [x] Write the three candidates against the reproduction and compare what each
      one checks: the constructor arity, the constructed type, and what a caller
      of `self.events[name]` sees.
- [x] Weigh the registry option first. It needs no language change, it is what a
      resource without `_G` scanning would write anyway, and the cost is that the
      author lists their classes once.
- [x] Weigh `classof Name` against 24.06's static members: a class value already
      exists in the checker for a static read, so the question is whether making
      it constructible is a small addition or a new concept.
- [x] Decide, and write `.claude/docs/adr/045-runtime-named-instantiation.md`
      recording the choice, the rejected options, and the boundary — what a ported
      resource has to rewrite and why.
- [x] Implement the chosen option, or, if the decision is the registry, ship only
      the documentation and the example.
- [x] Update `examples/framework` so the sketches show the supported form, since
      they are what a porting author copies.

## Acceptance Criteria

- [x] The three loading modules from the reproduction have one written, compiling
      Luam equivalent, checked in as a fixture.
- [x] The ADR names the rejected options and states the boundary in one paragraph.
- [x] `getClass` and `getClasses` are either used by the chosen form or documented
      as the untyped escape hatch, and their types match what the chosen form
      needs.
- [x] `examples/framework` compiles and shows the chosen form.
- [x] If a language surface is added, the emitted Lua for a project that does not
      use it is byte identical.
