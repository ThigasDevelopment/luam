# 45.18 - Document what porting a Lua resource to Luam actually costs

> File: `.claude/plans/45.18-porting-guide.md`

## Objective

Write the page a developer needs before converting an existing MTA resource: what
translates mechanically, what has to be restructured, and what Luam will not
accept at all.

## Context

`docs/en/guide/migration.md` exists. It does not cover what the port that produced
this milestone actually ran into, because none of it was known until the port was
run. The gap is not the language reference — it is the ordered list of decisions a
port forces, and there is no page that owns it.

## Scope

- **In:** A porting guide in both locales, the limitations reference where a shape
  has no equivalent, and the changelog.
- **Out:** A migration tool. Any promise about a shape whose owning task in this
  milestone has not landed.

## Steps

- [ ] Write the mechanical half first, as a table: `--` becomes `#`,
      `---@param x T` becomes `x: T`, `---@class X` with only fields becomes an
      `interface`, `---@field f fun(self: X, ...)` becomes a class method with no
      explicit `self`, `class "X" { }` becomes `class X { }`,
      `class "X" : extends "Y"` becomes `class X extends Y`,
      `X = new "X"` at the bottom of a file disappears and every call site becomes
      `new X(...)`, and `self:super(...)` becomes `super(...)`.
- [ ] Write the restructuring half: a `shared` module that branches on the side at
      runtime and what milestone 43 does with it; a class and its singleton
      instance sharing one global name, and why they need two names; a table keyed
      by a name the code computes; and a function returning several values.
- [ ] Write the refusals: instantiating a class the code names at runtime, per the
      decision 45.16 records, and auto-loading by walking `_G`. Say what to write
      instead, and link the ADR rather than restating it.
- [ ] Add a short section on what the port **finds**: the port in this milestone
      surfaced seventeen genuine defects in a resource that had been running —
      an optional field returned as required, a config key that never existed, a
      handler that validated everything and did nothing. Frame the diagnostics as
      the return on the work, because that is what justifies it.
- [ ] Give the recommended order: manifest and declaration files first, then
      `shared`, then `server`, then `client`, checking after each, and say why —
      a type declared in a file the checker has not seen yet warns instead of
      resolving.
- [ ] Record in the limitations reference every shape that still has no
      equivalent, each linked to its task.
- [ ] Add the changelog entry and keep both locales in parity.

## Acceptance Criteria

- [ ] The guide exists in `docs/en` and `docs/pt-br`, in parity, and every snippet
      in it compiles.
- [ ] Each of the three halves — mechanical, restructuring, refusals — is present,
      and the refusals link an ADR rather than restating it.
- [ ] The limitations reference names every unsupported shape with its task id.
- [ ] The guide states the recommended order and the reason for it.
- [ ] `pnpm docs:verify` passes.
