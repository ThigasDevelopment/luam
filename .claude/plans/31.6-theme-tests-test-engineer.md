# 31.6 - Prove the theme differentiates and stays readable

## Objective

Make the milestone's two claims — every element differentiated, and minimal
without becoming unreadable — assertions that fail a build rather than opinions
held in a review.

## Scope

- **In:** Coverage, distinctness, contrast, tokenization, and determinism tests
  across `packages/theme`, `packages/vscode`, and `packages/lsp`.
- **Out:** Visual regression by screenshot. It is expensive, brittle across
  platforms, and the properties worth protecting here are all computable.

## What Each Test Protects

Coverage catches a role nobody mapped. Distinctness catches two elements that
became the same colour. Contrast catches a minimal palette drifting into an
unreadable one. Tokenization catches a theme rule that is correct on paper and
never reached in practice. Determinism catches a hand-edited generated file.

## Steps

### T-01 - Coverage

**Agent:** test-engineer

- [ ] Walk both grammars, collect every `name` in every rule and capture, and
      assert each resolves to a theme rule under TextMate's longest-prefix
      matching. Not "a rule exists somewhere" — the rule that would actually win.
- [ ] Do the same for every semantic token type and modifier combination the
      31.3 legend can produce.
- [ ] Assert the reverse: no theme rule targets a scope neither grammar emits.
      A dead rule is a decision that silently stopped applying.

### T-02 - Distinctness

**Agent:** test-engineer

- [ ] For each confusion set in `constraints.ts`, assert every pair of members
      differs in hue, value step, or font style, in both modes.
- [ ] Where a pair differs only by value step, assert the pairwise contrast floor
      from R5. This is the test that stops the palette collapsing into one hue
      with three indistinguishable greys.
- [ ] Assert R2 mechanically: nothing marked as emitting Lua is cyan, nothing
      erased is violet, and the R6 environment directives are the only entries
      flagged as exceptions.

### T-03 - Contrast

**Agent:** test-engineer

- [ ] Assert every foreground against its background meets 4.5:1, and ambient
      roles meet 3:1, in both modes.
- [ ] Include the chrome pairs a user reads constantly: status bar text, tab
      labels, inlay hints, and the four diagnostic colours against both the
      editor and the panel background.
- [ ] Report the measured ratio on failure. A test that says only "too low"
      makes the next person recompute what it already knew.

### T-04 - Real tokenization

**Agent:** test-engineer

- [ ] Add `vscode-textmate` and `vscode-oniguruma` as dev dependencies and
      tokenize fixtures with the real engine rather than testing the regexes in
      isolation, which is all `grammar.test.ts` can do today.
- [ ] Build a fixture exercising every element in one file: both comment forms,
      all four string forms with interpolation and escapes, numbers, the
      directives, decorators, `class` with `extends` and `implements`, an
      `interface`, an `enum`, a `type` alias, a `declare`, `export http
      function`, methods, `self` and `super`, varargs, parameters with
      annotations, optional and union types, an MTA native call, a Lua stdlib
      call, table literals, and every operator family.
- [ ] Snapshot each token's scope stack and its resolved colour. The snapshot is
      the record of what the theme actually does, and a review of a colour change
      becomes a review of that diff.
- [ ] Add the same for a `.luam.manifest` fixture.

### T-05 - Semantic tokens

**Agent:** test-engineer

- [ ] Run the LSP over the same fixture and snapshot the decoded tokens with
      their types and modifiers, so the grammar snapshot and the semantic
      snapshot can be read against each other.
- [ ] Assert the Set 1 quartet — user function, method, MTA native, Lua stdlib —
      resolves to four different colours once both layers are applied. This is
      the single assertion that carries the milestone's headline claim.
- [ ] Assert `serverOnly` and `clientOnly` are produced in a `shared` file and
      that they resolve to distinct styles.

### T-06 - Determinism

**Agent:** test-engineer

- [ ] Regenerate every target in a temporary directory and assert byte equality
      with the committed files, for VS Code, Zed, Neovim, and `.tmTheme`.
- [ ] Run it in CI so a hand-edited theme file fails there rather than shipping.

## Acceptance Criteria

- [ ] Every test above exists and passes on both themes.
- [ ] A deliberately broken role — two Set 1 members given the same style — fails
      T-02, verified by trying it.
- [ ] A deliberately stale committed theme fails T-06, verified by trying it.
- [ ] `pnpm test` at the root runs the new suites, and CI runs the determinism
      check.
- [ ] Tokenization snapshots are committed and readable as a colour reference in
      their own right.
