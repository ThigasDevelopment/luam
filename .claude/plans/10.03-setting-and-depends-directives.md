# 10.03 - Add the `setting` and `depends` directives on the same mechanism

> File: `.claude/plans/10.03-setting-and-depends-directives.md`
> This task is the proof that the contribution channel generalises. If either
> directive needs a change between the parser and the manifest, 10.2 is wrong
> and should be fixed rather than worked around.

## Objective

Cover the two remaining manifest facts that belong to a source file rather than
to the project, and confirm that a new directive costs a parse rule, a
contribution kind, and a manifest element — nothing else.

## Scope

- **In:** `setting NAME = <literal>` mapping to `<setting>`, `depends "name"`
  mapping to `<include>`, their diagnostics, their manifest elements.
- **Out:** Reading a setting back from Luam with a type, `<aclrequest>`, export
  attributes such as `http`.

## Steps

- [x] Extend `isDirectiveStart` for `setting` followed by an identifier and
      `=`, and for `depends` followed by a string literal, keeping both usable
      as ordinary identifiers everywhere else.
- [x] Add `SettingDirective` and `DependsDirective` to the AST as statements
      that the emitter erases, like a type alias.
- [x] Restrict a setting value to a string, number, or boolean literal and
      report `check-setting-value-not-literal` otherwise — the value is written
      into XML at build time and cannot depend on runtime state.
- [x] Emit the setting name with the `*` prefix MTA uses for a publicly
      readable setting, and decide in the plan review whether a directive can
      opt out of it.
- [x] Report `check-depends-self` when a resource depends on its own name from
      `luam.json`, and `project-duplicate-setting` when two modules declare the
      same setting name with different values.
- [x] Collapse identical `depends` entries declared in several modules into one
      `<include>`.
- [x] Add `settingElement` and `includeElement` to `project/manifest.ts`, placed
      after the exports, each sorted by name.
- [x] Extend `ManifestContribution` with the two kinds and confirm no file
      between `compileModule` and `assembleResource` changes.
- [x] Document both directives and the `luam.json`-versus-directive rule from
      [ADR-007](../docs/adr/007-build-directives.md) in
      [language-design](../docs/language-design.md).

## Acceptance Criteria

- [x] `setting MAX_PLAYERS = 32` produces
      `<setting name="*MAX_PLAYERS" value="32" />` and emits no Lua.
- [x] `setting NAME = getPlayerCount()` reports
      `check-setting-value-not-literal`.
- [x] `depends "scoreboard"` produces `<include resource="scoreboard" />`, and
      the same dependency declared in three modules produces one element.
- [x] A resource depending on itself reports `check-depends-self`.
- [x] The diff for this task touches the parser, the checker, the AST, and
      `project/manifest.ts`, and no other file in the pipeline.
- [x] Manifest element order is info, scripts, exports, settings, includes,
      files, and is stable across rebuilds.
