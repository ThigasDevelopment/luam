# 30.05 - Correct the environments and arities the frozen catalog gets wrong

## Objective

Remove the diagnostics the catalog emits today that are simply wrong, including
the one the test suite currently asserts as correct behaviour.

## Root Cause

A frozen catalog is not only incomplete, it is inaccurate. Functions that gained
a second environment in a later MTA release are still declared one-sided, so the
checker rejects code MTA accepts. Measured on 2026-08-25: 24 such disagreements,
every one of them the same shape. `getPlayerSerial` has been shared since the
wiki marked it `{{Shared function}}`; `setWorldSpecialPropertyEnabled` records
its own change — "Added also as a server-side function. Previously only
available as a client-side function", MTA 1.6.0.

`catalog-coverage.test.ts` asserts the bug at lines 54 and 66: it expects
`getPlayerSerial` on the client and in a shared file to report
`check-environment-api`. The test was written to prove environment checking
works and reached for a name that was server-only at the time. Fixing the
catalog will fail that test, and the test is what is wrong.

## Scope

- **In:** The 24 environment corrections, the arity corrections 30.3 classified
  as upstream drift, and the tests that encode the current wrong answers.
- **Out:** New functions, which 30.4 already added. This task is only about
  entries that existed and were wrong.

## Steps

### T-01 - Correct the environments

**Agent:** architecture-engineer

- [ ] Apply the 24 corrections. All but one widen a declaration from one side to
      shared: `getPlayerSerial`, `getControlState`, `setControlState`,
      `getAllElementData`, `getElementByIndex`, `setWorldSpecialPropertyEnabled`,
      `isWorldSpecialPropertyEnabled`, `addVehicleSirens`, `removeVehicleSirens`,
      `breakObject`, `respawnObject`, and the rest of the measured set.
- [ ] Check `usePickup` separately. It is the only one narrowing — catalog says
      shared, the wiki lists it server-only — so it is the only correction that
      can reject code that compiles today.

### T-02 - Fix the tests that encode the bug

**Agent:** architecture-engineer

- [ ] Replace `getPlayerSerial` at `catalog-coverage.test.ts:54` and `:66` with a
      name that is genuinely server-only, so the test keeps proving environment
      checking rather than proving a stale declaration.
- [ ] Sweep the compiler and LSP suites for any other assertion that depends on
      a declaration this milestone corrects.

### T-03 - Correct the arities

**Agent:** architecture-engineer

- [ ] Apply the signature corrections 30.3 classified as upstream drift, among
      them `injectBrowserMouseDown` gaining `doubleClick` and
      `reloadBrowserPage` gaining `ignoreCache`.
- [ ] Widening an optional tail is safe. Flag separately any correction that
      raises the required-argument count, since that rejects existing code.

### T-04 - Prove no false negative was introduced

**Agent:** architecture-engineer

- [ ] For every widened declaration, assert it is now accepted in both
      environments, and that a still one-sided neighbour is still rejected.
- [ ] Removing a false positive must not remove the check. A declaration that
      widened to shared by mistake would silence a real diagnostic.

## Acceptance Criteria

- [ ] No shared function reports `check-environment-api` in any environment.
- [ ] The 24 measured disagreements are gone, and 30.2's allowlist no longer
      covers any of them.
- [ ] Environment checking is still proven by a test using a genuinely
      one-sided function.
- [ ] Every correction that could reject code compiling today is listed
      explicitly for review, with `usePickup` among them.
- [ ] `pnpm typecheck` and `pnpm test` pass.
