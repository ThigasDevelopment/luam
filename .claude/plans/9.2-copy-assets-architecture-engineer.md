# 9.2 — Copy assets and non-source files into the resource

> File: `.claude/plans/9.2-copy-assets-architecture-engineer.md`
> Overlaps 7.1. This task widens the emitted file set beyond `.lua`, which is
> the set 7.1 caches and diffs.

## Objective

Carry assets and other non-source files into the generated resource with their
relative path intact, declare them in the manifest so clients can download
them, and remove copied files whose source is gone.

## Scope

- **In:** Copying non-source files, `<file>` manifest entries, prune
  bookkeeping for copied files.
- **Out:** `config.lua` and `.env`, which have their own ownership rules (9.3).

## Steps

- [x] Collect non-source files from the project and add them to `ResourceBuild`
      alongside scripts and helpers.
- [x] Extend `resourceFiles` to copy them, preserving the relative path.
- [x] Pass `ManifestFile` entries to `generateManifest` from
      `assembleResource`, which currently never populates the parameter it
      already accepts.
- [x] Teach `pruneResource` to track copied files instead of assuming every
      removable file ends in `.lua`.
- [x] Decide and document which paths are copied: an `assets` convention, a
      config field, or everything that is not `.luam`.
- [x] Skip binary comparison in `isUnchanged` where reading a large asset as
      UTF-8 would be wrong.

## Acceptance Criteria

- [x] A file under `assets/images` reaches the resource at the same relative
      path and appears as a `<file>` entry.
- [x] A client script can load a copied asset in a running resource.
- [x] Deleting an asset from the source removes it from the build on the next
      run.
- [x] A binary asset survives a rebuild byte for byte.
- [x] An unchanged asset is not rewritten, and the build reports it as
      unchanged.

## Outcome

Copied paths come from two places. `assetDirs` in `luam.json`, defaulting to
`["assets"]`, holds files that get a `<file>` entry and are therefore downloaded
by clients. Non-source files found inside `sourceDirs` are copied at their
relative path but stay undeclared, so a server-side data file reaches the
resource without being transmitted.

Pruning does not keep a ledger. Its removable set is `.lua` files, `meta.xml`,
every `src` attribute of the previous `meta.xml`, and everything under a
configured source directory — which is precisely the tree the compiler mirrors.
A file the build never wrote, such as one an administrator dropped into the
output directory, survives.

"A client script can load a copied asset in a running resource" is asserted
through the `<file>` entry and the copied bytes. No Lua interpreter runs in the
test stack, so the load itself is not exercised.
