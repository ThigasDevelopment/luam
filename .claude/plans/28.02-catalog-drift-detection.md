# 28.02 - Fail the suite on MTA catalog drift

## Objective

Turn catalog drift from something discovered by accident into something the test
suite reports, so the gap can only shrink.

## Root Cause

Nothing in the repository compares the catalog to the API it claims to describe.
The 119 missing functions accumulated over three and a half years without a
single failing test, because an undeclared name degrades to `any` and never
blocks a build. Incompleteness is invisible by construction.

## Scope

- **In:** A drift report, a baseline allowlist, and suite failures for a new
  gap or a new environment disagreement.
- **Out:** Closing the gap. This task measures; 30.4 and 30.5 close it. The
  baseline starts at the 119 already known and is expected to fail nothing on
  the day it lands.

## Steps

### T-01 - Report the gap

**Agent:** test-engineer

- [ ] Compare the snapshot's function list to the catalog and report what is
      missing, split by environment. Baseline on 2026-08-25: 119 missing, 93
      client, 12 server, 14 shared.
- [ ] Group the report so a reviewer sees themes, not an alphabetical wall:
      engine streaming and IMG, Discord Rich Presence, PostFX, building
      functions, and HTTP server account for most of the current gap.

### T-02 - Fail on a new gap

**Agent:** test-engineer

- [ ] Record the known-missing names in a committed allowlist, each with the
      reason it is deferred.
- [ ] Fail the suite on any missing name the allowlist does not cover, so the
      count can only go down.
- [ ] Fail the suite when the allowlist names a function the catalog now
      declares, so the file cannot rot into a lie.

### T-03 - Fail on an environment disagreement

**Agent:** test-engineer

- [ ] Compare each declaration's environment against list membership and fail on
      a disagreement the allowlist does not cover.
- [ ] Seed the allowlist with the 24 measured disagreements, which 30.5 removes.
      All 24 are the same shape: the wiki says shared, the catalog says one
      side, because the function gained the other side in a later MTA release.

### T-04 - Report freshness

**Agent:** test-engineer

- [ ] Derive the highest MTA version named by a `{{New feature/item}}` template
      in the snapshot — present on 396 pages — and report it as the MTA release
      the catalog now covers.
- [ ] Print it beside the snapshot date so a reviewer can tell staleness from
      incompleteness.

## Acceptance Criteria

- [ ] The suite fails when the snapshot declares a function the catalog lacks
      and the allowlist does not cover it.
- [ ] The suite fails when an allowlist entry is no longer missing.
- [ ] The baseline allowlist holds exactly the 119 names and 24 environment
      disagreements measured on 2026-08-25, and the suite passes with it.
- [ ] The report names the covered MTA release.
- [ ] `pnpm typecheck` and `pnpm test` pass.
