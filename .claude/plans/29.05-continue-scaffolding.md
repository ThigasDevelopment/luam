# 29.05 - Fold loop scaffolding so `continue` adds no line

## Objective

Place the scaffolding that lowers `continue` on lines the loop already occupies, so a loop containing a `continue` produces as many lines of Lua as it has of Luam.

## Context

Lowering `continue` wraps the loop body in a `repeat` block ended by `until true`, and both keywords take a line of their own. Measured cost: a simple loop gains one line, a loop that also contains a `break` gains three because of the sentinel that carries the author's `break` past the wrapper, and a single-line loop grows from one line to five. Everything below the loop shifts by the same amount.

The lowering itself is sound and stays. The sentinel preserves the meaning of the author's `break`, and the checker already rejects the one case the wrapping would break: a `continue` that would hide a local from an outer `until` condition, reported as `check-invalid-continue`. `continue` is also required to be the last statement in its block, which keeps the transformation well defined.

## Scope

- **In:** Placing `repeat`, `until true`, the sentinel declaration, and the sentinel test on the loop's existing header and closing lines, for every loop form that supports `continue`.
- **Out:** Removing `continue` from the language, and changing the semantics of the lowering.

## Steps

### T-01 - Define the folded form per loop kind

**Agent:** architecture-engineer

- [x] Specify the folded output for a numeric `for`, a generic `for`, and a `while` loop.
- [x] Specify the folded output when the loop also contains a `break` and needs the sentinel.
- [x] Confirm each folded form parses under Lua 5.1, including the case where `until true` is followed by an `if` statement on the same line.

### T-02 - Emit the folded scaffolding

**Agent:** architecture-engineer

- [x] Prepend `repeat` to the loop body's first line rather than opening a new line, and leave the loop header byte-identical to the source.
- [x] Append `until true` to the loop body's last line, followed by the sentinel test when one exists, and leave the loop's `end` byte-identical to the source.
- [x] Place the sentinel declaration on the body's first line, before `repeat`.

### T-03 - Confirm the one-line loop case

**Agent:** architecture-engineer

- [x] Verify a loop authored entirely on one line still emits on one line.
- [x] The header no longer carries scaffolding, so a multi-line header needs no special case.

## Outcome

The scaffolding placement changed in both build modes: `repeat` rides the first
line of the loop body, `until true` and the sentinel test ride its last line, and
the raised sentinel shares a line with the author's `break`. The loop's own
header and `end` are copied through unchanged, so the loop stays recognizable.
The lowering adds no line in either mode.

Placement decided during execution. The first draft put the scaffolding on the
loop's header and closing lines, which was line-neutral but rewrote the two lines
that make a loop readable at a glance. Anchoring on the body instead is
line-neutral too and leaves `for ... do` and `end` exactly as written:

```lua
for index = 1, 10 do
    repeat if (index == 2) then
        break;
    end

    print (index); until true
end
```

Line fidelity for the loop as a whole is a development-mode contract. A minified
build still replaces a `continue` loop with canonical Lua, which re-lays out the
body; narrowing that replacement is out of reach for a loop, because the
scaffolding belongs to the loop and not to any statement inside it. In a
development build the loop is edited surgically instead, and the whole loop keeps
its authored lines.

## Acceptance Criteria

- [x] The scaffolding for a loop containing a `continue` adds no line, in both build modes.
- [x] A development build of a loop containing a `continue` emits the same number of lines as it was authored with.
- [x] A loop containing both `continue` and `break` keeps the sentinel semantics and adds no line.
- [x] `check-invalid-continue` still rejects the cases it rejects today.
- [x] Generated Lua for every existing `continue` fixture remains semantically equivalent.
- [x] `pnpm typecheck` and `pnpm test` pass.
