# 20.1 — Bundle the production resource into one script per environment

> File: `.claude/plans/20.1-bundled-production-output-architecture-engineer.md`

## Objective

Give `luam build` a production output of at most three scripts, while `luam
ensure` and `luam dev` keep writing the mirrored tree that makes a running
resource debuggable.

## Scope

- **In:** A second output layout, its selection through configuration and CLI
  flags, bundle assembly and ordering, the manifest it produces, pruning across
  a layout switch, and the diagnostics that guard it.
- **Out:** Identifier renaming and whitespace stripping, position mapping
  (20.2 and 20.3), any change to what `ensure` and `dev` write today, and any
  change to `config.lua`, `.env`, or asset handling.

## Options Considered

| Option | Correctness | Size | Debuggability | Decision |
|---|---|---|---|---|
| One layout for both commands | Unchanged | Pays for the authored tree on every start and join | Best | Reject |
| One file for the whole resource | Breaks the `type` separation MTA loads scripts by | Larger, once runtime guards are added back | Worst | Reject |
| Two bundles with `shared` inlined into both | Correct | Duplicates shared on disk, identical client download | Equal to three | Reject |
| Three bundles, one per environment | Preserves the running semantics exactly | Smallest | Recovered by 20.3 | Accept |

## Behavior Contract

`luam build` writes `meta.xml`, `config.lua` when the project has one, `.env`
when the project declares one, `src/shared.lua`, `src/server.lua`,
`src/client.lua`, and the declared assets at their authored paths. A bundle
whose environment contributes no helper and no module is neither written nor
declared. No `lib/` directory and no mirrored source tree appear in the output,
and `src/` holds nothing but the bundles.

The bundle directory is the literal `src`, independent of `sourceDirs`.
`config.lua` stays at the resource root because ADR-004 gives it another owner,
`.env` because the `env` helper opens it at that path, and the assets because
resource code addresses them by the path they were authored at.

`luam ensure` and `luam dev` produce byte-identical output to what they produce
today.

`--bundle` and `--no-bundle` select the layout on `build` and on `ensure`, and
`output.bundle` in `luam.json` sets the project default for `build`. The command
default is `bundle` for `build` and `tree` for `ensure` and `dev`.

Manifest order in the bundle layout is `config.lua`, `src/shared.lua`,
`src/server.lua`, `src/client.lua`, each with the `type` and `cache` attributes
its members carry today. Within a bundle, the environment's runtime helpers come first in
`helperDepth` order, then the modules in the order `sourceEntries` resolves,
honouring `loadOrder`.

Each module and each helper is wrapped in `do ... end`. Nothing is wrapped in a
function.

A module ending in a top-level `return` fails the build with
`project-bundle-toplevel-return`, naming the file and the position. A bundle
name that collides with an asset path fails with
`project-bundle-output-collision`.

Building the same project twice with no source change writes nothing the second
time. Switching a target directory between layouts removes the other layout's
files.

## Steps

- [x] Add `OutputLayout` (`'tree' | 'bundle'`) to the compiler resource module
      and thread it through `ResourceOptions`.
- [x] Add `output.bundle` to `LuamConfig`, `config-schema`, and
      `config-validation`, defaulting to `true`.
- [x] Add `--bundle` and `--no-bundle` to `parseArguments` as a tri-state, and
      resolve command default, config, and flag in `build-command` and
      `ensure-command`.
- [x] Add `BUNDLE_DIRECTORY` and `bundlePath(environment)` beside
      `LIBRARY_DIRECTORY` and `libraryPath`, resolving to `src/<environment>.lua`
      as a literal independent of `sourceDirs`.
- [x] Add `bundleResource` next to `collectScripts` in `resource-layout.ts`:
      group helpers and scripts by environment, wrap each member in `do ... end`,
      concatenate in manifest order, and return one `ResourceScript` per
      non-empty environment.
- [x] Detect a top-level `return-statement` per module during assembly and emit
      `project-bundle-toplevel-return`. Confirm that a top-level `...` needs no
      diagnostic: `do ... end` is a block, not a function, so the vararg stays
      the chunk's and MTA passes none in either layout.
- [x] Branch `assembleResource` on the layout: `tree` keeps `collectHelpers` and
      `collectScripts` as the manifest inputs, `bundle` passes the three bundles
      as `source` entries and emits no `library` group.
- [x] Extend `findDuplicateOutputs` to include bundle paths, so an authored
      `src/server.luam` is reported against the server bundle rather than
      overwriting it.
- [x] Extend `pruneResource` and `generatedRoots` so the bundle paths are
      removable whatever `sourceDirs` holds, and confirm a layout switch in
      either direction leaves no stale file and no empty `src/`.
- [x] Report the layout in the build summary so the terminal states which
      output was produced.

## Acceptance Criteria

- [x] `pnpm typecheck` and `pnpm test` pass.
- [ ] `luam build` on the template project writes exactly `meta.xml`,
      `src/shared.lua`, `src/server.lua`, `src/client.lua`, and the declared
      assets at their authored paths, with no `lib/` directory, no mirrored
      module tree, and nothing under `src/` but the bundles.
- [x] The generated `meta.xml` declares the three bundles with the same `type`
      and `cache` attributes their members carry in the tree layout.
- [x] A resource with no client module produces no `src/client.lua` and no
      client `<script>` entry.
- [x] The bundle paths are unchanged when `sourceDirs` is set to something other
      than `src`.
- [x] An authored `src/server.luam` fails the bundle build with
      `project-bundle-output-collision` instead of overwriting the bundle.
- [ ] `luam build --no-bundle` reproduces the tree output byte for byte.
- [ ] `luam ensure` and `luam dev` output is byte-identical to the output before
      this task.
- [x] A file-level `local` in one module is `nil` when read from another module,
      in both layouts.
- [ ] A module with 200 file-level locals compiles and loads in the bundle
      layout.
- [ ] `error(message, 2)` reports the caller's position identically in both
      layouts.
- [x] A top-level `return` fails with `project-bundle-toplevel-return` and no
      output is written.
- [x] Building twice with no change writes nothing the second time, and
      switching layouts in a target directory leaves no file from the other
      layout.
