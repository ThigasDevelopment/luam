# 36.07 - Verify the reorganized pipelines

## Objective

Prove the reorganization preserved every check it was supposed to preserve, and
lock the invariants the threat model depends on, so a later edit cannot quietly
reopen a gap.

## Problem

A workflow change is normally verified by watching it run once. That catches a
syntax error and nothing else. It does not catch a check that silently stopped
running, a permission that widened, an action that drifted back to a floating
tag, or a secret that became reachable from a fork.

## Scope

- **In:** A static assertion suite over the workflow files, a behavioral
  comparison against the pre-reorganization run, and a rehearsal of the fork
  path end to end.
- **Out:** Testing what the checks themselves verify. The compiler, CLI and LSP
  suites already cover that and are not duplicated here.

## Steps

### T-01 - Assert the workflow files

**Agent:** test-engineer

- [x] Parse every file in `.github/workflows` and assert each job declares
      `permissions`, and that no job exceeds the budget the contract set.
- [x] Assert every third-party action is pinned to a full commit SHA.
- [x] Assert no workflow reachable from a fork pull request references a secret.
- [x] Assert the required-check names in branch protection all exist as jobs.
- [x] Assert no verification step is defined in more than one workflow.

### T-02 - Compare behavior

**Agent:** test-engineer

- [ ] Record the job set and outcomes of a pre-reorganization run, and assert
      the post-reorganization run over the same commit produces the same
      verification result.
- [ ] Confirm the advisory jobs are absent from the pull request path and
      present where [36.03](36.03-merge-gate-and-signal.md) placed them.
- [ ] Confirm a deliberate break in a type, a test, and the smoke build still
      fails the gate.

### T-03 - Rehearse the fork path

**Agent:** test-engineer

- [ ] Open a pull request from a real fork and confirm it runs to completion
      with no secret and a read-only token.
- [ ] Confirm the first-time contributor gate holds the run until approval.
- [ ] Confirm a fork run cannot write a cache key a trusted run reads.

## Acceptance Criteria

- [x] The static suite fails when a job loses its `permissions` block, when an
      action is unpinned, and when a fork-reachable job gains a secret. Each is
      proven by a deliberate regression.
- [ ] The post-reorganization run verifies the same things as the run before it,
      compared job by job.
- [ ] A broken change fails the gate; a change that only trips an advisory job
      does not.
- [ ] The fork rehearsal passes from a real fork, not a branch in the
      repository.
- [ ] The suite runs in CI and blocks a merge, because a pipeline invariant that
      is not enforced is a comment.
