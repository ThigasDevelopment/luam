# 09.04 - Type `process.env` in the checker

> File: `.claude/plans/09.04-type-process-env.md`

## Objective

Turn a mistyped environment key from a `nil` at runtime into a compile error,
and make `process.env` unreachable from client and shared files through the
environment checker rather than through convention.

## Scope

- **In:** A record descriptor with named members, a `project` API source, the
  `process` declaration built from `.env`.
- **Out:** Validating that a deployed `build/.env` matches the declared types.
  That needs the compiler to emit declared types alongside the file.

## Steps

- [x] Add `RecordDescriptor` to `packages/mta-types/src/type-descriptor.ts`
      holding named members, with a `record` constructor beside `arrayOf` and
      `optionalOf`.
- [x] Resolve member access on a record in the checker, and report an unknown
      member with the declared names.
- [x] Add `project` to `ApiSource` so a diagnostic can name `.env` as the
      origin instead of implying an MTA API.
- [x] Build the `process` declaration from the keys in `.env`, typed by the
      quoting rule, with `environment: 'server'`.
- [x] Surface record members in LSP completion and hover.

## Acceptance Criteria

- [x] `process.env.DB_HOST` type checks against the type declared in `.env`.
- [x] A misspelled key is a compile error listing the declared keys.
- [x] `process.env` in a client file is a diagnostic, and so is `process.env`
      in a shared file.
- [x] `PORT=3306` types as `number` and `PORT="3306"` as `string`.
- [x] A project with no `.env` compiles, and `process` is simply undeclared.
- [x] Completion offers the declared keys after `process.env.` in a server
      file and offers nothing in a client file.
