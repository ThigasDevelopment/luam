# 50.10 - Document the workspace and the session

## Objective

Describe the workspace, the `.luam.server` file and the session vocabulary in
both documentation languages, and retire the paragraphs that exist only to
apologise for the arrangement this milestone replaces.

## What has to stop being true

[The CLI reference](../../docs/en/tooling/cli.md) currently explains that
`luam server` and `luam ensure` in separate terminals are separate processes and
that standalone `ensure` therefore only syncs.
[Daily development](../../docs/en/guide/daily-development.md) tells the reader to
type `refresh`, `stop` and `start` themselves. Both stay true for a single
resource directory and stop being the whole story for a workspace; a page that
describes only the old arrangement now describes the harder half of the product.

## Scope

- **In:** A new reference page for the file, the session vocabulary in the CLI
  and daily-development pages, the field table, the new diagnostics, both
  changelogs, and the navigation — all in `en` and `pt-br`.
- **Out:** A migration guide. Nothing breaks, so there is nothing to migrate; the
  deprecation warning names the fix in one line and that is the right size for it.

## Steps

- [ ] Add `docs/en/reference/server-file.md` and its `pt-br` twin, modelled on
      [formatter-file](../../docs/en/reference/formatter-file.md): what the file
      is, where it is looked for, the field table with types, defaults and rules,
      the resource discovery rule, and the precedence table from 50.03.
- [ ] Add the session to [the CLI reference](../../docs/en/tooling/cli.md) under
      `luam dev`: the workspace form, the five verbs with one line each, the
      leading-space escape, and that `--start-server` is a usage error there.
      Keep the single-resource form exactly as it is documented today.
- [ ] Rewrite the "Getting the restart" section of daily-development around the
      session for a workspace, and keep the manual-console instructions for a
      single resource directory. Two arrangements, both real, named as such.
- [ ] Add the workspace layout to
      [project-layout](../../docs/en/guide/project-layout.md): the
      `resources/.luam.server` beside `resources/resource-a/.luam.manifest` shape,
      one level, and what makes a child a resource.
- [ ] Extend [configuration-fields](../../docs/en/reference/configuration-fields.md)
      with a server-file section, and mark `serverPath`, `resourcesDir` and
      `development.server` as superseded by it, with the row pointing at the new
      page.
- [ ] Document every new diagnostic in
      [diagnostics](../../docs/en/reference/diagnostics.md):
      `server-parse-error`, `server-unknown-field`, `server-invalid-value` and
      `config-deployment-moved`, each with its cause and its fix.
- [ ] Add the entries to `CHANGELOG.md` and to both documentation changelogs, and
      add the new page to both `reference/index.md` files and to the VitePress
      navigation for both locales.
- [ ] Capture the session transcript as a real capture, not an illustration. If a
      captured output is not achievable for an interactive session, mark it as an
      illustration in the prose the way the rebuild sample in daily-development
      already is.
- [ ] Run `pnpm docs:verify`. Parity moves from 65 pages per locale to 66, and the
      snippet, output, layout and link checks all have to pass with the new page.

## Acceptance Criteria

- [ ] Both locales have a `server-file` reference page with the same headings and
      the same tables.
- [ ] The CLI reference documents the workspace `luam dev`, the five verbs and
      the escape, and no longer implies that a shared server is unreachable.
- [ ] Daily development describes both arrangements and says which is which.
- [ ] Every new diagnostic appears in the diagnostics reference in both locales.
- [ ] `pnpm docs:verify` passes, including parity at 66 pages per locale.
- [ ] `pnpm docs:obsolete` passes: no page outside a release history still
      describes the deployment fields as the only way to name a server.
