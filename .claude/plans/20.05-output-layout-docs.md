# 20.05 - Document the two output layouts and position resolution

> File: `.claude/plans/20.05-output-layout-docs.md`

## Objective

Give a developer one page that explains why `build` and `ensure` now produce
different shapes, and how a position reported by MTA becomes a position in their
own source.

## Scope

- **In:** The output-layout reference, the `luam trace` entry in the CLI
  reference, the `output.bundle` and `output.map` entries in the configuration
  reference, the debugging guide, and the map file format.
- **Out:** Translation of the new pages beyond what the existing docs pipeline
  requires, and any change to the ADRs themselves.

## Behavior Contract

The documentation states which command produces which layout, what the
production resource contains, and what has to be kept for a production trace to
stay resolvable. It does not describe bundling as an optimization the developer
tunes; it describes it as what shipping means.

## Steps

- [x] Add an output-layout page to the reference: the two layouts side by side,
      the resulting resource directory, the manifest each produces, and the
      command defaults.
- [x] Document `--bundle`, `--no-bundle`, `--no-map`, `output.bundle`, and
      `output.map`.
- [x] Document `luam trace`: the argument forms, standard input, `--map`, the
      exit codes, and a worked example from an MTA error to an authored line.
- [x] Add a debugging section covering both layouts: what `luam dev` prints, and
      what to do with a trace from a production server.
- [x] Document the map file: where it is written, that it is never inside the
      resource, that it has to be kept with the release, and the consequence of
      resolving against the map of a different build.
- [x] Document the two new diagnostics and how to fix each.
- [x] Record `config.lua` and `.env` as unbundled in the configuration
      reference, pointing at ADR-004 for the reason.
- [x] Update the CLI, template, and root READMEs where they describe the build
      output.

## Acceptance Criteria

- [x] The reference states the layout each of `build`, `ensure`, and `dev`
      produces, and how to override it.
- [x] A reader can go from an MTA error line in a bundled production resource to
      the authored line by following the documented steps only.
- [x] The map file's location, lifetime, and failure mode are documented.
- [x] Every flag, configuration key, and diagnostic added in this milestone
      appears in the reference.
- [x] Every example is verified against the built CLI rather than written from
      the plans.
