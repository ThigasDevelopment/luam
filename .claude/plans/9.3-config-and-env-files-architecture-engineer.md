# 9.3 — Add resource configuration and environment files

> File: `.claude/plans/9.3-config-and-env-files-architecture-engineer.md`

## Objective

Give a resource two settings files with two different owners: `config.lua` for
structural configuration the author edits, and `.env` for deployment values the
server administrator edits, without either being destroyed by a rebuild.

## Scope

- **In:** `config.lua` passthrough, the three `.env` files, write-once
  generation of `build/.env`, the `env` runtime library, `process.env`.
- **Out:** Typing `process.env` in the checker (9.4). Until then it is `any`.

## Steps

- [x] Copy `config.lua` from the resource root verbatim and list it in the
      manifest as a shared script, ordered after libraries and before the
      developer's scripts.
- [x] Read `.env` at build time and layer `.env.local` over it for local runs.
- [x] Generate `build/.env` from the keys in `.env` on the first build, leaving
      sensitive values blank, and never overwrite it afterwards.
- [x] Confirm `.env` never receives a `<file>` manifest entry, so it is never
      transmitted to a client.
- [x] Port `examples/lib/env.lua` into `packages/runtime/lua` as a helper, and
      register it in `RUNTIME_HELPERS`.
- [x] Inject the helper only when a project has a `.env`, following the
      existing automatic-helper mechanism.
- [x] Add `.env.local` to the `luam init` gitignore template and `.env` to the
      scaffold.
- [x] Document the inverted naming — `.env` committed, `.env.local` ignored —
      wherever a developer first meets it.

## Acceptance Criteria

- [x] `luam build` on a project with a `.env` produces `build/.env` with the
      declared keys and blank sensitive values.
- [x] Editing `build/.env` and rebuilding leaves the edit intact.
- [x] Deleting `build/.env` and rebuilding regenerates the skeleton.
- [x] `.env` never appears as a `<file>` entry in a generated `meta.xml`.
- [x] A server script reads `process.env.KEY` and gets the value from
      `build/.env`, coerced by the quoting rule: unquoted numbers and booleans
      keep their Lua type.
- [x] Reading an undeclared key from `process.env` raises an error naming the
      file, and assigning to any key raises an error.
- [x] `process` is undefined in a client script.
- [x] Editing `config.lua` in the source changes the built copy; the compiler
      does not parse it and reports no diagnostics from it.
