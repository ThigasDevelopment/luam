# 36.03 - Separate the merge gate from the advisory signal

## Objective

Make a red check mean the change is broken. Today two jobs can fail a pull
request for reasons the pull request did not cause, which teaches contributors
to ignore red.

## Problem

Two concrete defects in `ci.yml`:

- **`audit` is non-deterministic.** `pnpm audit --audit-level moderate --prod`
  fails when a new advisory is published upstream, on a branch that changed no
  dependency. The same commit passes on Monday and fails on Tuesday.
- **`benchmark` blocks on `needs: test` but proves nothing.** It runs
  `test:bench` on every pull request, spending a runner on a number nobody
  compares against a baseline. A benchmark without a threshold is a report, not
  a gate.

The serial `typecheck → test → build` chain also delays the first useful signal:
a type error and a broken smoke test are found minutes apart when they could be
found together.

## Scope

- **In:** Which jobs block a merge, which report, the trigger for the advisory
  jobs, a scheduled dependency audit, and the `needs` graph.
- **Out:** The content of any check. Nothing this task touches changes what a
  check verifies, only whether it can block and when it runs.

## Steps

### T-01 - Move the non-deterministic jobs off the gate

**Agent:** github-engineer

- [ ] Move the production dependency audit to a scheduled workflow that opens an
      issue on a finding, and keep a pull request audit that runs only when a
      manifest or the lockfile changed.
- [ ] Take `benchmark` off the pull request path. Run it on `develop` pushes and
      on demand, and record the result rather than failing on it.

### T-02 - Flatten what does not need to be serial

**Agent:** github-engineer

- [ ] Run `typecheck` and the test matrix concurrently. Keep `build` behind the
      tests, because the smoke test consumes what the build produces.
- [ ] Keep `fail-fast` for the Node matrix and confirm the concurrency group
      still cancels superseded runs on the same ref.

### T-03 - Declare the required checks

**Agent:** github-engineer

- [ ] Name the required-check set in the repository's branch protection for
      `main` and `develop`, matching the contract from
      [36.01](36.01-pipeline-contract.md).
- [ ] Document which jobs are advisory and where their output is read.

## Acceptance Criteria

- [ ] A pull request that changes no dependency cannot fail because of a newly
      published advisory.
- [ ] A dependency advisory is still surfaced, on a schedule, as an issue with
      the affected package and severity.
- [ ] `benchmark` does not run on a pull request and cannot block a merge.
- [ ] `typecheck` and the tests start together; the first failure is reported
      without waiting for the other.
- [ ] Branch protection lists exactly the required checks, and every other job
      is documented as advisory.
- [ ] A genuinely broken change still fails, verified on a branch that breaks a
      type, a test, and the smoke build.
