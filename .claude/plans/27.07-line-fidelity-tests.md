# 27.07 - Cover development output with line-fidelity tests

## Objective

Define and enforce the invariant this milestone is measured by: a development build produces one line of Lua for every line of Luam, and copies through unchanged every statement Lua 5.1 already accepts.

## Scope

- **In:** A reusable fidelity assertion, fixtures covering every construct in the milestone, release-output regression guards, and a check that no comment carrying source text reaches a release build.
- **Out:** Executing generated Lua. Verification is static unless an approved Lua 5.1 harness already exists in the repository.

## Steps

### T-01 - Build the fidelity assertion

**Agent:** test-engineer

- [x] Add a helper that compiles a source, splits both sides into lines, and reports the first index where the count or the content diverges.
- [x] Make the failure message show the authored line beside the generated line, since a bare count mismatch is not diagnosable.
- [x] Let a test declare which lines are expected to differ, so an intentional lowering is not silently accepted.

### T-02 - Cover the milestone constructs

**Agent:** test-engineer

- [x] Fixture per construct: interface, type alias, class, enum, compound assignment, native extension, `new`, template literal, `continue`, and `continue` combined with `break`.
- [x] Fixture per placement: at top level, nested inside a call, nested inside a loop, and authored on a single line.
- [x] Assert equal line counts for every fixture in development mode.

### T-03 - Guard the release path

**Agent:** test-engineer

- [x] Snapshot release output for every fixture and assert it is unchanged except for the orphan semicolon repair.
- [x] Assert no release output contains a comment carrying source text.
- [x] Assert an erased declaration never leaves a line consisting only of a semicolon, in either mode.

### T-04 - Guard the position map

**Agent:** test-engineer

- [x] Verify that a generated position still resolves to the authored position through the resource map after every change in this milestone.
- [x] Cover a file where a construct was folded onto an existing line, since that is where a mapping is most likely to drift.

## Acceptance Criteria

- [x] Every fixture compiles to the same number of lines it was authored with, in development mode.
- [x] Every line that Lua 5.1 already accepts is byte-identical between source and development output.
- [x] Release snapshots are unchanged except where 29.1 repaired invalid output.
- [x] Position resolution through the resource map is correct for every fixture.
- [x] `pnpm typecheck` and `pnpm test` pass.
