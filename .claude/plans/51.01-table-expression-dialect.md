# 51.01 - Make the manifest one table expression

## Objective

Make the manifest file a single table constructor, so it is one value rather than
a program that accumulates assignments, without giving up the purity guarantee
that lets the editor evaluate it in process.

## Why this replaces the ADR-015 allowlist

ADR-015 permits two statements — a `local` declaration and an assignment to a
field — and excludes everything else, `return` included. This replaces the
allowlist with no statements at all. Its safety reasoning is untouched: the
guarantee is stated as "an expression grammar with no calls and no loops cannot
diverge, cannot perform I/O, and cannot observe anything but the values it was
handed", and a table constructor is such an expression. Purity stops being a
property asserted about a list of permitted statements and becomes visible in the
shape of the file.

What the allowlist actually bought was a closed global scope, in which a
misspelled field is an unknown *name*. That check moves rather than disappears: a
misspelled key in a table literal checked against a record descriptor is the same
caret, from the machinery 41.01 built for key completion.

## There is no `local`

The file is the object, explicitly and only. ADR-015's
`local password = env.LUAM_MTA_PASSWORD` idiom is removed rather than relocated:
an intermediate value is written where it is used, or is not written, and
`env.SOME_KEY` may appear once per use.

That is the whole specification of the file, which is the point. A manifest with
no statements has nothing to explain about where a value may appear, nothing to
check about statement order, and one shape to complete against.

## Scope

- **In:** The file grammar, the evaluation entry point, the closed-scope
  replacement, and the diagnostics for a file that is not one table.
- **Out:** What the sections are (51.02), and reading the old assignment form,
  which 51.08 owns.

## Steps

- [ ] Change the manifest parse entry point to expect one table constructor as
      the whole file, with nothing before or after it.
- [ ] Remove `local` from the manifest dialect, and report it as
      `config-unexpected-statement` naming the inline form as the replacement.
- [ ] Make `analyzeManifest` evaluate that expression as the manifest value.
      `mode`, `env` and `root` stay in scope as free identifiers and keep their
      types; nothing about the expression language changes.
- [ ] Replace the closed global scope with record checking against
      `MANIFEST_RECORD`. An unknown key is `config-unknown-field` anchored at the
      key, not at the value, so the caret sits where the fix goes.
- [ ] Add `config-manifest-not-a-table` for a file that is not one table
      constructor, and `config-trailing-content` for anything after it. Both name
      the shape the file should have, in full: this is a diagnostic a user hits
      once and then never again.
- [ ] Keep evaluation total: a duplicated key is `config-duplicate-field` at the
      second key rather than last-write-wins.

## Acceptance Criteria

- [ ] A file that is one table constructor evaluates, and its sections are
      readable.
- [ ] A `local` declaration anywhere in the file is rejected, and the message
      shows the inline form.
- [ ] A function expression, a call, a loop or an `if` anywhere in the file is
      rejected with the code the dialect raises today.
- [ ] A misspelled top-level key reports `config-unknown-field` with the caret on
      the key.
- [ ] A misspelled key inside a section reports the same, and names the section.
- [ ] A file that is empty, is two tables, or has content after the table each
      report their own code with a message that shows the expected shape.
- [ ] `env.KEY` inside the table resolves, and `mode` and `root` still resolve.
- [ ] The evaluator makes no call, opens no file and starts no process, verified
      by the existing purity test.
