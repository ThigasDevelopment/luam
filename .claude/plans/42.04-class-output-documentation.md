# 42.04 - Record what the class body and a hover now show

## Objective

Bring the reference pages and the changelog in line with the three repairs, in both locales, so the documented layout and the generated file agree.

## Context

The output-layouts page already claims the behaviour 42.01 delivers: "A class field with no
default | `name = nil`, on the line the field was written on". Nothing there needs to
change, which is exactly why it has to be re-read rather than assumed — the row must be
confirmed to describe the source-preserving path, and the row about `new` must state plainly
that a lowered statement keeps its trailing semicolon.

The language-server page describes what hover answers, and does not currently say that a
property of a typed table or a class field is one of them.

The `docs/scripts/limitations-contract.ts` gate checks the limitations page against the
compiler, so any limitation wording touched here has to survive it.

## Scope

- **In:** `docs/en` and `docs/pt-br` for output layouts and the language server, the root
  `CHANGELOG.md` and both locale changelogs, and the roadmap rows for milestone 42.
- **Out:** New pages. Any wording about lowering granularity, which no task in this
  milestone changes.
