# 09.05 - Design and implement `.d.luam` declaration files

> File: `.claude/plans/09.05-declaration-files.md`
> [ADR-005](../docs/adr/005-declaration-files.md) is `Proposed`. The design step
> below closes its open questions and moves it to `Accepted` before any code.

## Objective

Let a project describe types for Lua the compiler does not own — starting with
`config.lua` — in a file that contributes nothing to the generated resource.

## Scope

- **In:** Closing the ADR-005 open questions, declaration syntax, discovery,
  checker and LSP resolution.
- **Out:** Verifying that a declaration matches the Lua it describes. The
  compiler asserts; it does not check the target.

## Steps

- [x] Resolve the ADR-005 open questions and move the ADR to `Accepted`:
      declaration syntax and how much of the type grammar it reuses; what a
      declaration binds to; discovery by name pairing or explicit reference;
      precedence against a symbol real source also declares.
- [x] Exclude `.d.luam` from the glob feeding the emitter and route it to the
      checker.
- [x] Resolve declarations through `environmentFromPath` like any other source
      file, so a declaration under `src/server` is server-only.
- [x] Merge declared symbols into the global scope the checker builds.
- [x] Report a symbol declared twice, and a declaration whose environment
      conflicts with its use.
- [x] Index declarations in the LSP for completion, hover, and definition.

## Acceptance Criteria

- [x] A `.d.luam` file produces no output and never appears in the generated
      resource.
- [x] `config.lua` paired with a declaration gives typed access to its table,
      and a misspelled member is a compile error.
- [x] A declaration under `src/server` used from a client file is a diagnostic.
- [x] A declaration under `src/shared` resolves from all three environments.
- [x] Hover and completion resolve declared symbols in the editor.
- [x] A symbol declared both in a declaration file and in real source reports
      the precedence rule chosen in the design step.

## Outcome

The ADR-005 open questions are resolved in the ADR itself, which is now
`Accepted`. The one grammar addition is `declare <name>: <type>`; table shapes
come from `interface`, so the type grammar is untouched.

"Report a symbol declared twice" became a precedence rule instead of a
diagnostic. The declaration wins for typing and real source is checked against
it, so `declare RESOURCE_NAME: string` paired with `RESOURCE_NAME = 1` is
`check-type-mismatch`. A separate conflict error was implemented first and then
removed: it could not distinguish the intended pairing from a mistake, and it
misfired across environments, where a server declaration and a client global of
the same name are unrelated.

Declaration files export their globals through `AmbientDeclarations`, which
gained a `globals` list carrying the declared name, type, and position. This is
the only way a global crosses a module boundary with a type; an ordinary global
is still `any` elsewhere in the project.
