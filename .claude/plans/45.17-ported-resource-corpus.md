# 45.17 - Keep a ported Lua resource as a compiler corpus

> File: `.claude/plans/45.17-ported-resource-corpus.md`

## Objective

Turn the port that produced this milestone into a fixture, so the next real
resource does not have to rediscover the same fourteen gaps.

## Context

Every task in milestone 45 came from one exercise: converting a 3,600-line MTA
resource, annotated for the Lua language server, into Luam and reading the
diagnostics. The first run reported 56 errors and 2 warnings across 24 files, and
each one was either a defect, a missing surface, or a real bug in the resource.
No unit fixture in the suite produced any of them, because unit fixtures are
written against the feature under test and a real resource is written against
none of them.

The value is the shape, not the source. The corpus keeps the shapes and owes the
original nothing.

## Scope

- **In:** A fixture project under `packages/compiler/tests/fixtures` reproducing
  every shape milestone 45 names, a baseline of its diagnostics, and a CLI test
  that compiles it end to end.
- **Out:** The original resource's assets, its business logic and its third-party
  exports. Any dependency on a live MTA server, a database, or a network.

## Steps

- [x] Build the fixture as a real project — `.luam.manifest`, `config.lua`, a
      `.d.luam` for it, `src/server`, `src/client`, `src/shared` — not a pile of
      snippets, so discovery, environment resolution, manifest generation and the
      bundle layout are all exercised.
- [x] Carry one occurrence of every shape in the milestone: the element-typed map
      initialised `{}`, the `nil` deletion, the `unpack` spread, the quoted key,
      the optional `fun` parameter, the generic interface, the cross-file alias,
      the annotated global, the incremental record, the widened literal, the
      optional catalog argument, the shadowed API, the class receiver, the
      reserved parameter name and the authored tuple.
- [x] Record the expected diagnostics as a baseline file, so a change in count,
      code, position or message is a visible diff and not a silent pass.
- [x] Keep the negative half deliberately: the fixture must still report the
      genuine defects a resource of this shape has — a missing return, an
      arithmetic on an optional, an unknown member — so the corpus proves the
      checker stayed useful and not merely quiet.
- [x] Add a CLI test running `check` and `build` over the fixture and asserting
      the exit codes each command promises, plus emitter and manifest baselines.
- [x] Record in the fixture's README which task each shape belongs to, so a
      failing baseline names the plan to read.

## Acceptance Criteria

- [x] The fixture exists, compiles, and its diagnostic baseline is checked in.
- [x] Every task from 45.02 to 45.15 has at least one shape in the corpus, named
      in the README.
- [x] Before its owning task lands, each shape fails; after, it passes — proven by
      the baseline diff in that task's commit.
- [x] `check` and `build` both run over the fixture with the documented exit
      codes, and the emitter and manifest baselines are asserted.
- [x] The suite adds no network, database or server dependency.

## Outcome

The corpus is two fixtures, not one. `ported-resource` carries the positive half —
every shape 45.02 to 45.16 delivered — and compiles with **no** diagnostics, so
`check` and `build` both return `EXIT_OK` and the emitter and manifest baselines
mean something. `ported-defects` carries the negative half — the shapes that must
still report (45.13, 45.14) and the genuine defects a resource of this shape has —
with its expected output checked in as `diagnostics.txt`; `check` and `build` both
return `EXIT_DIAGNOSTICS` over it. One fixture could not have both, because a
project that reports errors does not build.

The acceptance line "before its owning task lands, each shape fails; after, it
passes — proven by the baseline diff in that task's commit" could not be honoured
as written: milestone 45 was executed in one pass, so the corpus was authored
after 45.02–45.16 had all landed. The per-task proof lives in each task's own
tests, which were written failing first; the corpus is the regression net, not the
record of the fix.
