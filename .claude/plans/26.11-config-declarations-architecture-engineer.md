# 26.11 - Derive declarations from static config.lua data

## Objective

Generate reviewable `.d.luam` declarations from a deliberately small static `config.lua` subset without turning the Luam compiler into a general Lua analyzer.

## Options Considered

| Option | Coverage | Maintenance | Decision |
|---|---|---|---|
| Parse and analyze arbitrary Lua 5.1 | High in theory | A second frontend and checker | Reject |
| Keep declarations entirely manual | Universal | Repetitive | Preserve fallback |
| Infer literal configuration data only | Useful subset | Bounded | Accept |

## Scope

- **In:** CLI command, restricted table parser, inference rules, generated declaration format, overwrite safety, watch integration if justified, diagnostics, and documentation.
- **Out:** Functions, metatables, loops, calls, module loading, arbitrary expressions, code execution, and making `config.lua` a Luam source file.

## Steps

### T-01 - Define the static subset

**Agent:** architecture-engineer

- [ ] Accept only literals, nested table constructors, keyed fields, and explicitly documented array forms.
- [ ] Define mixed tables, duplicate keys, nil, numeric keys, unsupported expressions, and inferred union behavior.
- [ ] Select a generated-file marker and deterministic naming contract.

### T-02 - Build the safe extractor

**Agent:** architecture-engineer

- [ ] Parse without evaluating Lua and enforce file size, nesting depth, collection size, and path containment limits.
- [ ] Generate a `.d.luam` file through the existing declaration syntax and formatter.
- [ ] Refuse to overwrite an unmarked user-authored declaration.

### T-03 - Integrate the workflow

**Agent:** cli-engineer

- [ ] Add an explicit command with check and write modes; do not run it implicitly during normal compilation.
- [ ] Report unsupported constructs with source positions and direct users to manual declarations.

### T-04 - Verify safety and output

**Agent:** test-engineer

- [ ] Cover nested records, arrays, mixed tables, duplicate keys, unsupported syntax, malformed files, limits, deterministic output, and overwrite protection.

## Acceptance Criteria

- [ ] The command never executes or imports `config.lua`.
- [ ] Supported literal data produces deterministic declarations accepted by the existing checker.
- [ ] Unsupported dynamic content fails with a manual `.d.luam` migration path.
- [ ] Normal `check` and `build` continue copying/assembling `config.lua` without treating it as source.
