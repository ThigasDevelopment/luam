# 29.4 - Preserve authored class and enum layout

## Objective

Give class and enum declarations a surgical emission path so a development build keeps the author's indentation, spacing, and line breaks instead of replacing the whole declaration with canonical output.

## Context

`canPreserveStatement` has no case for a class or enum declaration, so both fall through to the default and are always replaced by canonical emission. The measured effect on a representative sample: an authored five-line enum collapses to a single line, and a class body loses the space before a parenthesis and the semicolons written inside it. The class header and closing line already match what the author wrote.

## Options Considered

| Option | Layout fidelity | Risk of divergence | Decision |
|---|---|---|---|
| Keep canonical emission and pad the line count | Poor, the shape is still lost | None | Reject |
| Reformat canonical output to imitate the source | Approximate and fragile | High | Reject |
| Emit targeted edits over the authored text | Exact | Must reproduce every lowering | Accept |

## Scope

- **In:** Surgical edits for a class declaration and an enum declaration in development builds: the quoted class name, the implicit `self` parameter, member separators, the `extends` form, and a multi-line enum body.
- **Out:** Generated members, the builder, and decorators, when their shape has no authored counterpart. Those keep canonical emission and must be detected rather than guessed at.

## Steps

### T-01 - Define what a surgical class edit must produce

**Agent:** architecture-engineer

- [x] Enumerate every transformation the canonical class emitter performs today: quoted name, `extends` form, implicit `self`, member separators, generated members, builder, and required helpers.
- [x] Mark which transformations are local edits over authored text and which require synthesized code.
- [x] Specify that a declaration needing any synthesized member falls back to canonical emission for the whole declaration.

### T-02 - Emit a class through targeted edits

**Agent:** architecture-engineer

- [x] Add a class case to `canPreserveStatement` that accepts only declarations composed entirely of local edits.
- [x] Produce edits for the header, the `self` parameter, and the member separators, leaving all other bytes untouched.
- [x] Keep helper registration identical to the canonical path.

### T-03 - Emit an enum through targeted edits

**Agent:** architecture-engineer

- [x] Replace the header with the assignment form and quote each member in place, keeping the authored line breaks and indentation.
- [x] Keep member names quoted, because the runtime helper uses each element as a table key and an unquoted member would yield an empty enum.
- [x] Preserve the single-line form when the author wrote the enum on one line.

### T-04 - Keep the reachability gate

**Agent:** architecture-engineer

- [x] Confirm an unreferenced enum is still erased, and that its erasure preserves the line count.
- [x] Confirm a shared enum kept through project references still emits.

## Acceptance Criteria

- [x] A development build of a multi-line enum produces a multi-line enum on the same lines, with quoted members.
- [x] A development build of a class keeps the authored spacing and inner semicolons, and still receives the quoted name, the `self` parameter, and the member separators.
- [x] A class requiring generated members, a builder, or any decorator falls back to canonical emission without a partial edit. A field with an annotation and no value is blanked together with its separator, so the surviving table has no stray entry.
- [x] Release output is unchanged.
- [x] `pnpm typecheck` and `pnpm test` pass.
