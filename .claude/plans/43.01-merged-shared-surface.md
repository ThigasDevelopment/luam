# 43.01 - Merge the server and client surfaces in a shared file

> File: `.claude/plans/43.01-merged-shared-surface.md`

## Objective

Let a `shared` file see every MTA API, so a module that decides its own side at
runtime can be written in one file without fighting the checker.

## Context

The reported `Network` class asks which side it is on with
`isElement(localPlayer)`, stores the answer in `self.isClient`, and branches on
that field between `triggerServerEvent` and `triggerClientEvent`. On the current
tree that file produces six `check-environment-api` diagnostics and would run
correctly as written.

The decision the author already made cannot be recovered by the compiler: the
branch tests a class field, not an expression, so no control-flow narrowing —
over a compiler-provided `isClient`, or over the author's own existence test —
would accept this file without restructuring the class. A mechanism that does not
answer the case that motivated it is not worth its cost, so the check itself
gives way instead.

## Options Considered

| Option | Accepts the reported file | Cost | Decision |
|---|---|---|---|
| Narrow the environment along control flow | No — the branch tests a stored field | High | Reject |
| Compiler-provided `isClient` / `isServer` globals | No — same reason, and adds language surface | Medium | Reject |
| Merge both surfaces in a shared file, keep a warning | Yes | Low | Accept |
| Merge both surfaces and report nothing | Yes, but a misplaced file loses all checking | Low | Reject |

The last row matters because `shared` is also the fallback environment: a file
whose path does not resolve — the reported one included — is `shared` by default.
Reporting nothing would mean a client module written outside `src/client` gets no
environment checking at all.

## Scope

- **In:** The shared symbol table carrying every declaration, the environment
  diagnostics becoming warnings in a shared file, and the same treatment for
  events, project declarations and MTA OOP members.
- **Out:** Import direction, which does not change. Any narrowing, any new global,
  any change to the emitted Lua or to the manifest. Server and client files, which
  keep reporting an error.

## Steps

- [x] Build the shared surface as the shared declarations plus the server and
      client ones: `globalsFor('shared')` in `packages/mta-types/src/catalog.ts`
      returns the union, with each declaration keeping the side it was declared
      for, and `builtinSymbols` carries them into the shared scope with their real
      types.
- [x] Keep a declaration that exists on both sides resolving to its shared form,
      so nothing that already worked changes signature.
- [x] In `environment-checks.ts`, report `check-environment-api` and
      `check-environment-event` as warnings when the file is `shared`, keeping the
      error in a `server` or `client` file. The message names the side the API
      belongs to and states that the file must decide the side at runtime.
- [x] Apply the same rule to the MTA OOP member checks and to project
      declarations, so `client` and `source` in a shared file behave like
      `localPlayer`.
- [x] Leave the import rules untouched: a `shared` module importing a `server` or
      `client` module is still an error, because an import resolves when the chunk
      loads and no runtime branch can undo it.

## Acceptance Criteria

- [x] The reported `Network` class compiles with no error; each side-restricted
      name carries a warning that names its side.
- [x] `localPlayer` in a shared file has type `Player`, and `triggerServerEvent`
      carries its catalog signature instead of falling back to `any`.
- [x] A `server` file using `dxDrawText` and a `client` file using
      `outputChatBox(..., player)` still report errors, unchanged.
- [x] A `shared` file importing a `client` module is still an error.
- [x] The emitted Lua, the line map and the generated manifest are unchanged.
- [x] `luam build` succeeds on a project whose only environment findings are these
      warnings, and `luam check` reports them.
