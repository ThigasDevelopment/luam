# 19.03 - Emit one-line Lua 5.1 production scripts

> File: `.claude/plans/19.03-production-lua-minifier.md`

## Objective

Make `luam build` write compact single-line Lua 5.1 scripts that MTA can load,
without changing the readable development output produced by `ensure` and `dev`.

## Scope

- **In:** A deterministic lexical Lua minifier, production-only writer
  integration, map handling, incremental writes, and failure safety.
- **Out:** Identifier mangling, dead-code elimination, bytecode compilation,
  minifying XML/assets/environment files, or modifying authored Luam source.

## Steps

- [x] Define a Lua 5.1 token scanner that recognizes identifiers, keywords,
      numbers, operators, short strings, long bracket strings, line comments,
      and long bracket comments.
- [x] Emit the smallest safe separator between adjacent tokens. Never join token
      pairs when their concatenation changes Lua tokenization.
- [x] Remove comments and unneeded whitespace while preserving literal bytes in
      strings and long bracket strings.
- [x] Apply minification after resource assembly and before writing only for the
      `build` production path. Keep compiler emission and `ensure`/`dev` output
      structured and readable.
- [x] Minify every generated `.lua` script, including bundles, helpers, and
      `config.lua`; leave `meta.xml`, assets, and `.env` untouched.
- [x] Preserve script order, environment separation, `do ... end` bundle guards,
      manifest declarations, helper substitutions, and `loadOrder`.
- [x] Mark a production map as line-imprecise, or reject its positional use in
      `trace` with an actionable message, rather than returning an incorrect
      source line for MTA's generated `line 1` stack traces.
- [x] Run minification before any write or prune operation so a scanner failure
      leaves the previous production resource intact.

## Acceptance Criteria

- [x] Every generated Lua file from `luam build` contains no newline character.
- [x] The minified output is accepted by a Lua 5.1 parser and by MTA-compatible
      integration fixtures.
- [x] String literals, long bracket literals, comments adjacent to operators,
      numeric literals, and keyword boundaries preserve runtime behavior.
- [x] Rebuilding unchanged source does not rewrite unchanged minified files.
- [x] A compilation or minification failure writes no partial production output.
- [x] `luam ensure` and `luam dev` produce the same readable output as before
      this milestone.
