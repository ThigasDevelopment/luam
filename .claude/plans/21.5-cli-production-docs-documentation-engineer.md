# 21.5 — Document the rebuilt CLI and production output

> File: `.claude/plans/21.5-cli-production-docs-documentation-engineer.md`

## Objective

Publish one accurate English contract for the rebuilt CLI and explain the
debugging consequences of one-line production Lua.

## Scope

- **In:** CLI reference, output-layout reference, examples, migration notes, and
  links to the applicable ADRs.
- **Out:** New commands or undocumented behavior introduced solely for docs.

## Steps

- [x] Update the command reference with per-command options and examples.
- [x] Document the production split: `build` emits minified Lua while `ensure`
      and `dev` emit readable tree output.
- [x] Document that production files are one line, valid Lua 5.1, and do not use
      identifier mangling in this release.
- [x] Explain the line-only MTA trace limitation and direct users to `ensure` or
      `dev` for source-level debugging.
- [x] Document stream behavior, non-interactive options, exit codes, and the
      migration behavior for scripts that used globally accepted irrelevant flags.
- [x] Link the CLI reference to the decision records and output-layout details.

## Acceptance Criteria

- [x] Documentation names every supported command and its valid options.
- [x] `build`, `ensure`, and `dev` output differences are explicit and include
      concrete command examples.
- [x] Documentation makes no claim that a one-line production MTA trace can be
      resolved to an exact source line without a generated column.
- [x] All user-facing text is English and matches the implemented CLI help.
