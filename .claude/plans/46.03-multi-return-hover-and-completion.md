# 46.03 - Answer hover and completion with the destructured type

> File: `.claude/plans/46.03-multi-return-hover-and-completion.md`

## Objective

Give the symbol a multi-return `local` declares the type it actually holds, so
hover, completion detail and the document outline stop disagreeing with the
checker that produced them.

## Context

`collectLocal` in `packages/lsp/src/symbols/statement-collector.ts` repeats the
same pairing the hint does, and it feeds more surfaces: the `type` carried on the
symbol and the `detail` string every consumer of the symbol index renders. In
`local a, b, c = triple()`, hovering `a` answers the whole tuple and hovering `b`
answers `local b` with no type — the checker, meanwhile, declared `b` as `string`
and narrows on it correctly.

The `detail` string raises a question the hint does not have. It is built as
`local <name>: <type> = <value text>`, and after the fix three names would each
claim `= triple()`. Repeating the call on all three suggests each name received
the call's whole result, which is the misreading being repaired.

## Options Considered

| Option | Reads correctly | Decision |
|---|---|---|
| Show the value text only on the first name an expanded expression covers | Yes — `local b: string` says what `b` is without claiming it holds the call | Accept |
| Repeat the value text on every expanded name | No — three names each claiming `= triple()` | Reject |
| Drop the value text whenever any expression expands | No — loses it for the first name, which does read correctly | Reject |

## Scope

- **In:** The type and the detail of a symbol declared by a `local`, and every
  surface that reads them: hover, completion detail, document symbols, workspace
  symbols.
- **Out:** The hover chain itself and the member hover 44.02 owns. Only what
  `collectLocal` records changes.
- **Out:** `generic-for` variables, which record no type today.

## Steps

- [x] Rewrite `collectLocal` over the 46.01 helper so `type` is the distributed
      element and `widenInferred` runs per element.
- [x] Keep the annotation ahead of the inferred type where a declarator carries
      one, exactly as today.
- [x] Render the value text only for the first name an expanded expression covers,
      per the decision above, and leave a single-value `local` unchanged.
- [x] Confirm the byte-count suffix follows the same rule, so it is not repeated
      once per name.
- [x] Verify no other consumer of the symbol index assumed one declarator per
      value expression.

## Acceptance Criteria

- [x] Hovering `a`, `b` and `c` in `local a, b, c = triple()` answers `number`,
      `string` and `boolean`.
- [x] Hovering `only` in `local only = triple()` answers `number`.
- [x] Completion offering `b` in scope carries `string` as its detail.
- [x] Hover on `b` shows no `= triple()`, and hover on `a` still shows it.
- [x] The reported catalog case answers `number` on all three names.
- [x] The hover, completion, document-symbol and workspace-symbol suites pass
      untouched.
