# 8.1 — Choose the upstream MTA declaration source

> File: `.claude/plans/8.1-catalog-source-adr-architecture-engineer.md`

## Objective

Decide where the full MTA declaration set comes from and how it enters the
repository, so the catalog stops being hand written.

## Scope

- **In:** Source evaluation (`multitheftauto/mtasa-lua-types`, MTA Wiki
  scraping, MTA Wiki API), license and attribution, snapshot vs fetch strategy,
  refresh cadence, ADR-003.
- **Out:** Writing the generator and importing the declarations.

## Steps

- [x] Evaluate `multitheftauto/mtasa-lua-types` for coverage, signature quality,
      environment tagging, and update frequency.
- [x] Evaluate scraping `Category:Server functions` and `Category:Client
      functions` from the Wiki, including how reliable the syntax sections are.
- [x] Record the license of the chosen source and the attribution the repository
      must carry.
- [x] Decide between a vendored snapshot committed to the repository and a fetch
      step, and define how a refresh is triggered.
- [x] Treat the downstream data as untrusted input: it is parsed, never
      executed, and the generator validates it before emitting
      ([security-baseline](../skills/security-baseline/SKILL.md)).
- [x] Write ADR-003 with the decision and its consequences.

## Acceptance Criteria

- [x] ADR-003 is accepted and lists the options that were rejected and why.
- [x] The source license and required attribution are recorded in the repository.
- [x] The snapshot or fetch strategy is decided, including where the raw data
      lives and how a refresh is run.
- [x] A sample of the source proves it carries the environment of every
      function, not only its signature.
