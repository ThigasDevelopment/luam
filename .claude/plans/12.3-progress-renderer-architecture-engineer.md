# 12.3 — Render build phases with a progress bar and a final report

> File: `.claude/plans/12.3-progress-renderer-architecture-engineer.md`
> The pipeline is synchronous, so nothing animates on a timer. The renderer
> paints when the build hands it an event, and throttles so painting never
> costs more than the work it describes.

## Objective

Show the build advancing through its phases while it runs, and close with a
report that says what was produced, how long each phase took, and what the cache
saved.

## Scope

- **In:** The phase renderer, the progress bar for counted phases, the final
  report, the fast path for a build too short to animate, and the watch-mode
  separator.
- **Out:** Diagnostic layout (12.4).

## Steps

- [x] Render each phase as a line that starts pending and resolves to success or
      failure, using the symbols from 12.1.
- [x] Draw a bar only for a phase that has a unit count. A single step gets a
      marker, never a fake percentage.
- [x] Throttle repainting to at most once every 50 ms and always paint the final
      state of a phase, so a 300-file compile does not spend more time drawing
      than compiling.
- [x] Add the fast path: a run that finishes under roughly 150 ms prints the
      finished report directly, with no intermediate frame. A warm rebuild is
      around 1 ms and must not flicker.
- [x] Fall back to one plain line per phase when the stream is not a TTY. No
      carriage returns and no repainting ever reach a redirected log or a CI
      transcript.
- [x] Paint progress on stderr so that redirecting stdout keeps the report
      clean.
- [x] Close with the report: files compiled, modules reused from cache, files
      written, unchanged, and removed, the output directory, and the duration
      per phase alongside the total.
- [x] In `ensure --watch`, print a separator and a timestamp before each rebuild
      so consecutive runs do not merge in the scrollback.
- [x] Extend the report with the sync and restart phases when `ensure` runs
      them.

## Acceptance Criteria

- [x] `luam build` on a large project shows each phase advancing, with a counted
      bar for compile and write.
- [x] A warm rebuild prints the report with no intermediate frame.
- [x] Output piped to a file contains no escape sequence and no carriage return,
      and one line per phase.
- [x] A build that fails marks the phase that failed and prints no later phase.
- [x] The report totals match the numbers the command reports today.
- [x] Each rebuild under `--watch` is separated and timestamped.
- [x] Painting overhead on a 300-file build stays under 5 ms in total.
