# 1.2 — Implement lexer with tokens and positions

> File: `.claude/plans/1.2-lexer-architecture-engineer.md`

## Objective

Deliver a lexer that turns typed Lua source text into a token stream with line
and column positions, including Luam comments, strings, numbers, template
strings, and the `~=` operator.

## Scope

- **In:** Token types, identifiers, keywords, literals, operators (`~=`,
  `==`, `..`, `#`, `+`, `-`, `*`, `/`, `%`, `^`), Luam comments (`#`,
  `#* *#`), template strings, source positions.
- **Out:** No parsing or semantic analysis.

## Steps

- [x] Define `Token` and `TokenKind` types in `src/lexer/`.
- [x] Scan the `~=` operator token; report `!=` as a lexical error that
      suggests `~=`.
- [x] Implement whitespace, comment, number, string, and identifier scanning.
- [x] Skip `#` and `#* *#` comments; report Lua, `//`, and `/*` comments as lexical
      errors that suggest Lua comment syntax.
- [x] Implement template string scanning that preserves `${...}` segments.
- [x] Track line and column for every token and produce lexical diagnostics.

## Acceptance Criteria

- [x] Lexer snapshots match for fixtures covering all literal and operator forms.
- [x] Template strings tokenize into a literal with interpolation segments.
- [x] `#` and `#* *#` comments are skipped; unterminated block comments
      produce a diagnostic with a position.
- [x] `!=`, `//`, and `/*` produce lexical error diagnostics.
- [x] Unterminated strings produce a diagnostic with a position.
