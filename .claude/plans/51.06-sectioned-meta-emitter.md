# 51.06 - Emit the sectioned resource manifest

## Objective

Generate a `meta.xml` whose root element, five sections, entry order and
attribute rules match the file a resource author writes by hand, from the ordered
lists the manifest now carries.

## The root element

The root element is the resource name — the project folder — not `<meta>`. MTA
reads the children of the root node and does not check its name, confirmed by the
project owner from production use, the same way ADR-008 confirmed that MTA
expands a wildcard rather than requiring enumerated entries. ADR-008 assumed
`<meta>`, and this reverses that assumption.

Because the permissiveness is observed behaviour rather than documented
behaviour, this milestone verifies it against a real server before the change
ships, and the acceptance below says so.

## The sections

| Comment | Contents |
|---|---|
| `INFO` | the info element, then one `<include>` per `info.dependencies` entry |
| `ENVIRONMENT` | `<oop>`, then `<min_mta_version>` |
| `SCRIPTS` | runtime helpers, then vendored libraries, then the `scripts` list in order |
| `FILES` | the `files` list in order |
| `EXPORTS` | one `<export>` per `export` in the source |

A section with no entry emits no comment. The orphan rule from ADR-008 stands, so
an empty `EXPORTS` section leaves nothing behind.

## The element rules

Unchanged from ADR-008, restated because they are what the authored file shows:

- A `server` script or export carries no `type`, because `server` is MTA's default
  and an attribute equal to the default is omitted.
- A `client` or `shared` script carries `type` and `cache="false"`,
  unconditionally, in development and production alike.
- A wildcard is emitted literally. MTA expands it.
- Info attribute order is `author`, `type`, `version`, `description`, then any
  extra key of `info.author` in the order it was written.

## Scope

- **In:** `generateManifest` rewritten around ordered sections, the root element,
  the info extra attributes, and `<min_mta_version>` taking two values.
- **Out:** `<settings>`, `<aclrequest>`, `<map>`, `<config>`, `<html>`,
  `<sync_map_element_data>`, `<download_priority_group>`, `download` on `<file>`
  and `minversion`/`maxversion` on `<include>`. Every one of them needs a consumer
  and a field before it can be emitted, which is its own milestone.

## Steps

- [ ] Take the resource name from the project folder and emit it as the root
      element, escaped, with a matching close tag. Reject a folder name that is
      not a valid XML element name, naming the folder and the rule.
- [ ] Rewrite `generateManifest` to take the five sections as ordered inputs and
      to stop sorting anything. Sorting is what erased the authored order.
- [ ] Keep `escapeXml` and the attribute writer as they are; the formatting
      contract of ADR-008 — four spaces, double quotes, self-closing with a
      leading space — is unchanged.
- [ ] Emit the info element from `info.author.name`, the fixed `type`, `version`,
      `description`, then the extra author keys.
- [ ] Emit `<oop>` from `environment.oop` whenever the field is written, `true` or
      `false`. The current emitter writes the element only when true; the authored
      file states it either way, and a resource that says `false` is stating a
      decision.
- [ ] Emit `<min_mta_version>` from `environment.version.server` and
      `environment.version.client` independently, so two pinned values are two
      attributes and `'latest'` resolves per side through the existing cache and
      offline fallback.
- [ ] Order `<export>` elements `shared`, `server`, `client` and then by name, and
      emit a blank line where the side changes. Exports come from source and have
      no authored order, so this is the one section the emitter groups itself.
- [ ] Delete `ScriptGroup` and `GROUP_COMMENTS`. Helpers and libraries keep their
      fixed position at the head of `SCRIPTS`; everything else is authored order.

## Acceptance Criteria

- [ ] The `heaven-roleplay` fixture and the `bcg` fixture each generate their
      authored file byte for byte.
- [ ] The root element is the resource folder name, and a real MTA server starts a
      resource whose generated file carries it — recorded as a manual verification
      in the milestone, because no test in this repository runs MTA.
- [ ] A section with no entries emits neither comment nor blank line.
- [ ] `oop = false` emits `<oop>false</oop>`; an absent `oop` emits nothing.
- [ ] `version = { server = '1.6.0', client = 'latest' }` emits a pinned server
      value and a resolved client value, and an offline build with no cache omits
      the element and warns, as ADR-008 requires.
- [ ] Two `<export>` sides are separated by one blank line; one side is not.
- [ ] Every existing manifest snapshot in the suite is regenerated and reviewed,
      not accepted wholesale.
