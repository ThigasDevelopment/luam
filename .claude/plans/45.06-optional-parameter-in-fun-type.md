# 45.06 - Take an optional parameter in a fun type

> File: `.claude/plans/45.06-optional-parameter-in-fun-type.md`

## Objective

Let a `fun` type spell an optional parameter, so a callback contract can say that
its argument may be missing without falling back to `any`.

## Reproduction

```luam
declare newPromise: fun(executor: fun(resolve: fun(v: any): void, reject: fun(reason?: any): void): void): Promise
# parse-unexpected-token: Expected ")" but found ":".
```

The parser reads `reason?` as an unnamed optional **type** — parameter names are
optional in a `fun` type — and then expects the list to close. The same body
written as an interface method is accepted:

```luam
interface Cbs {
    run(done?: fun(): void): void   # accepted
}
```

So the form exists in the language and is missing in exactly one position.

## Root Cause

The `fun` parameter list allows a bare type, a `name: Type` pair, and `...`. With
names optional, `reason?` is ambiguous at the `?` and the parser commits to the
type reading before it sees the `:` that would disambiguate. The interface member
parser does not have the ambiguity, because a member always carries a name.

## Scope

- **In:** `name?: Type` in a `fun` type parameter list, everywhere a `fun` type is
  written: an annotation, an alias body, a member type, a `declare`, and a nested
  `fun`.
- **Out:** An optional marker on an unnamed parameter, which stays `Type?` and
  keeps its current meaning. Optional parameters on a declared function, which
  already work.

## Steps

- [x] Give the `fun` parameter parser one token of lookahead past a `?`: an
      identifier followed by `?` followed by `:` is a named optional parameter;
      anything else keeps the current reading.
- [x] Reject `name?: Type?` as `parse-redundant-optional`, matching the rule a
      declared parameter already follows.
- [x] Carry the optionality into the function descriptor so it reaches
      assignability: a parameter marked optional lowers the callee's required
      arity, and a caller may omit it.
- [x] Confirm the nested case parses — an optional parameter inside a `fun` that
      is itself a parameter of another `fun`, which is the reproduction.
- [x] Keep `fun(Type?)` meaning what it means today, and add a test that pins the
      two spellings apart.

## Acceptance Criteria

- [x] The reproduction compiles and `newPromise` keeps its full signature.
- [x] A call that omits an optional parameter of a `fun`-typed value is accepted;
      one that omits a required parameter still reports `check-argument-count`.
- [x] `fun(name?: Type?)` reports `parse-redundant-optional`.
- [x] `fun(Type?)` behaves exactly as it does today.
- [x] Hover on a `fun`-typed value prints the optional marker on the name.
