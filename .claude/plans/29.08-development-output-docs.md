# 29.08 - Document the development output contract

## Objective

State what a developer can rely on when reading generated Lua, and correct the documentation that currently describes behavior this milestone changes or that was never written down.

## Context

Several behaviors are only discoverable by reading the compiler. An enum that nothing reads is erased with no diagnostic, because it declares a module global and unused reporting only covers locals and parameters. Reachability is matched by identifier name, so an enum consumed dynamically or from a hand-written Lua file disappears. `luam trace` and the automatic rewriting of MTA console records in `luam dev` already resolve generated positions back to source positions, and neither is prominent in the documentation.

## Scope

- **In:** The development output contract, the enum reachability rules, the erasure of compile-only declarations, and a visible entry point for position resolution. English and Portuguese in parallel.
- **Out:** New product behavior. This task documents what the milestone shipped.

## Steps

### T-01 - Write the development output contract

**Agent:** documentation-engineer

- [x] State the rule: generated Lua is the source with Luam constructs removed or lowered, and nothing else changed.
- [x] List what is rewritten and what is copied through.
- [x] State that the contract applies to development builds and that release builds bundle and minify.

### T-02 - Correct the enum documentation

**Agent:** documentation-engineer

- [x] Record that erasure of an unread enum is silent and that no compiler option reports it.
- [x] Record that reachability is matched by identifier name, so dynamic or cross-resource consumption is not seen by the build.
- [x] Record that a surviving enum is a global, so declaration order across files matters at load time.
- [x] Record that member names stay quoted in generated Lua and why.
