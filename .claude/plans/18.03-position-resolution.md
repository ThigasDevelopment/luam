# 18.03 - Resolve runtime positions back to Luam source

> File: `.claude/plans/18.03-position-resolution.md`

## Objective

Turn a position reported by MTA into the `.luam` file, line, and symbol that
produced it, live in `luam dev` and offline for a trace pasted from a production
server.

## Scope

- **In:** The bundle-level map, the map file `luam build` writes, position
  resolution in the development log stream, and the `luam trace` command.
- **Out:** Column precision, remote log collection, any change to what the
  resource ships, and any change to the emitter map itself.

## Options Considered

| Option | Works in production | Ships anything | Decision |
|---|---|---|---|
| Resolve only what the running build holds in memory | No, a production trace has no running build | No | Reject |
| Write the map inside the resource directory | Yes | Yes, and it undoes ADR-010 | Reject |
| Write the map beside the resource in `outDir` and resolve from it | Yes | No | Accept |

## Behavior Contract

`luam build` writes `<outDir>/<name>.luam-map.json`, beside the resource
directory and never inside it. It carries a format `version`, the resource name,
the layout it was built with, and for each generated file the modules it
contains, the generated line each module's block starts at, and that module's
mappings. Paths are relative to the project root and ordering is stable, so two
builds of the same sources produce the same bytes. `--no-map` suppresses it.

`luam ensure` and `luam dev` hold the map in memory and write no map file.

`luam dev` resolves the position on every log record it prints. A record that
resolves is shown as the `.luam` path, the source line, and the enclosing symbol
when the map carries one. A record that does not resolve is shown exactly as it
is shown today.

`luam trace <file>:<line>` resolves one position against the map file, printing
the `.luam` path, line, and symbol, and exits non-zero when the position falls
outside every mapping. It accepts a full MTA log line as well as a bare
`file:line`, reads more than one position from standard input, and takes
`--map <path>` for a map that is not at the default location. It needs no
compilation and no server.

A map whose `version` is unknown, or which does not cover the file being
resolved, produces a diagnostic that says so rather than a wrong line.

## Steps

- [x] Define the map file shape and its `version` in the compiler, reusing the
      `SourceLineMapping` encoding from 20.2.
- [x] Have the bundle assembly from 20.1 record, per bundle, each member's
      module path and starting line, and compose it with the module maps into
      one resource map.
- [x] Produce the same resource map in the tree layout, where each generated
      file holds exactly one module starting at line 1.
- [x] Add the map to `BuildOutcome` and write it from `build-command` under
      `outDir`, guarded by `--no-map` and `output.map`.
- [x] Add a resolver that takes a generated file and line and returns the source
      path, line, and symbol, with a binary search over the sparse pairs.
- [x] Feed the ensure and dev runners the in-memory map and resolve positions in
      `development-log-reporter` before formatting.
- [x] Add `trace` to `CommandName`, `COMMANDS`, `USAGE`, and `dispatch`, with
      `--map`, argument parsing for `file:line` and for a pasted log line, and
      standard input support.
- [x] Report an unknown map version and an uncovered position as distinct
      diagnostics.

## Acceptance Criteria

- [x] `pnpm typecheck` and `pnpm test` pass.
- [x] `luam build` writes the map under `outDir` and nothing new inside the
      resource directory; the resource is byte-identical with and without the
      map.
- [x] Two builds of unchanged sources produce byte-identical map files.
- [x] `luam build --no-map` writes no map file and an unchanged resource.
- [ ] A runtime error in a bundled resource, given to `luam trace`, resolves to
      the authored file, the authored line, and the enclosing symbol.
- [x] `luam trace` resolves a full pasted MTA log line and a bare `file:line`
      identically, and reads several positions from standard input.
- [x] `luam trace` on a position outside every mapping exits non-zero with a
      diagnostic and prints no position.
- [x] `luam trace` against a map with an unknown `version` reports the version
      rather than resolving.
- [ ] `luam dev` prints `src/server/<module>.luam:<line>` for a server error
      raised in a module with blank lines above the failure, and the line is the
      authored one.
- [x] `luam dev` prints an unresolvable record exactly as it does today.
