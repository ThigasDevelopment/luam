# 30.3 - Parse wiki signatures into the generator model

## Objective

Turn the snapshot's syntax sections into the generator's declaration model at a
measured accuracy the milestone can hold itself to, so the wiki can replace a
source that no longer moves.

## Root Cause

ADR-006 rejected the wiki because "the syntax sections are prose written by many
hands, with inconsistent optional-parameter notation". That was an estimate, not
a measurement. Measured on 2026-08-25 across all 1383 pages: every one carries a
`<syntaxhighlight lang="lua">` block naming the function inside its Syntax
section, and a 120-line prototype with no per-page tuning reached 99.0% parsed,
98.2% agreement on total arity and 96.1% on required arity against the existing
catalog. The notation is inconsistent in exactly two ways, and both are
mechanical.

## Scope

- **In:** Locating the signature, parsing arity and optionality, mapping wiki
  types to descriptors, extracting OOP and version metadata, and an accuracy bar
  enforced by a test.
- **Out:** Switching the generator over to this parser (30.4). This task lands a
  parser and its measurements; the emitted catalog does not change yet.

## Steps

### T-01 - Locate the signature

**Agent:** architecture-engineer

- [ ] Read only the Syntax section. A page's Example section also names the
      function, and taking the first match anywhere on the page picks the wrong
      block on 1243 of 1383 pages.
- [ ] Read per-side blocks from `<section name="Server" class="server">`, which
      is how a shared page carries a different signature per environment.
- [ ] Join a signature that wraps across lines. 14 pages fail without this, all
      of them wide signatures: `dxDrawText`, `dxDrawImageSection`,
      `processLineOfSight`, `setPedAnimation`, and similar.

### T-02 - Parse arity and optionality

**Agent:** architecture-engineer

- [ ] Support both optional notations the wiki uses: `f( a [, b ] )` and
      `f( a, [ b ] )`. Normalizing the second into the first before splitting
      raised measured required-arity agreement from 83.8% to 96.1%.
- [ ] Split parameters on commas at paren depth zero, and mark a parameter
      optional by the bracket depth at its first character, so a bracket that
      opens mid-list is counted correctly.
- [ ] Recognise `...` as variadic rather than as a parameter.

### T-03 - Map wiki types to descriptors

**Agent:** architecture-engineer

- [ ] Map the scalar spellings: `int` and `float` to number, `bool` to boolean,
      `string` to string, `table` to table, `var` to any.
- [ ] Map an element spelling to a named descriptor through the existing element
      hierarchy, and a `a / b` union spelling to a union descriptor.
- [ ] Read a multi-return head — `float, float, float getElementPosition` — as a
      tuple. The wiki states these directly, where the upstream declarations
      collapse many of them.

### T-04 - Extract OOP and version metadata

**Agent:** architecture-engineer

- [ ] Parse `{{OOP|...}}`, present on 873 pages, into the existing OOP surface
      model: the method name, the property name, and the counterpart setter.
- [ ] Parse the MTA version out of `{{New feature/item|_|1.6.0|_|...}}`, present
      on 396 pages, and carry it on the declaration. 30.2 consumes it as the
      freshness signal.
- [ ] Record `{{Deprecated}}` (14 pages) and `{{Needs_Checking}}` (5 pages) so a
      reviewer can see them, without acting on either yet.

### T-05 - Hold a measured accuracy bar

**Agent:** architecture-engineer

- [ ] Use the current 1294-entry catalog as a regression baseline and report
      parse rate, arity agreement, and environment agreement against it.
- [ ] Reach at least 99% agreement on total arity, which T-01's line joining is
      expected to deliver from the measured 98.2%.
- [ ] Triage every remaining disagreement into one of two buckets, with no
      third: a parser defect to fix, or genuine drift where the wiki is right
      and the frozen catalog is wrong. `injectBrowserMouseDown` gaining
      `doubleClick` and `reloadBrowserPage` gaining `ignoreCache` are the second
      kind, and 30.5 acts on them.

## Acceptance Criteria

- [ ] At least 99% of snapshot pages yield a parsed signature.
- [ ] Every unparsed page is listed with the reason it failed.
- [ ] Total-arity agreement against the baseline is at least 99%.
- [ ] Every disagreement is classified as a parser defect or as upstream drift,
      and the classification is committed alongside the parser.
- [ ] The parser is pure: same snapshot in, same model out, no network, no clock.
- [ ] `pnpm typecheck` and `pnpm test` pass.
