# 28.04 - Make the wiki snapshot the primary catalog source

## Objective

Invert the sources: the wiki snapshot becomes what the catalog is generated
from, and `mtasa-lua-types` is demoted to a tiebreaker for the fields the wiki
states vaguely.

## Root Cause

The generator's whole input is a package that stopped being published in
February 2023. Every downstream stage — normalizer, emitters, printer — is
source-agnostic already, so the freeze is confined to two files:
`upstream-source.ts` and `declaration-parser.ts`.

## Options Considered

| Option | Freshness | Fidelity | Decision |
|---|---|---|---|
| Keep upstream primary, bump on release | None; `1.1.1` is final | High | Reject |
| Wiki snapshot primary, upstream as tiebreaker | Tracks the wiki | 99%+ measured in 30.3 | Accept |
| Parse `mtasa-blue` C++ registrations | First-hand | Arity without named types; GPL-3.0 | Reject |
| Hand-maintain the gap in overrides | Manual | High | Reject as primary; keep as escape hatch |

## Scope

- **In:** Swapping the generator's input, the tiebreaker rule, override
  precedence, and a reviewed regeneration of the whole catalog.
- **Out:** Correcting the entries this exposes as wrong (30.5) and automating
  the refresh (30.6).

## Steps

### T-01 - Swap the input

**Agent:** architecture-engineer

- [ ] Point `catalog-generator.ts` at the 30.3 parser reading the 30.1 snapshot.
- [ ] Leave the normalizer, emitters, and printer untouched. If any of them
      needs a change, that is a signal the model boundary was wrong and the
      parser should absorb it instead.

### T-02 - Keep upstream as a tiebreaker

**Agent:** architecture-engineer

- [ ] Keep `mtasa-lua-types` as a devDependency, consulted only where the wiki
      gives a type the model cannot narrow: a bare `table` with no element type,
      and `var`.
- [ ] Never let the tiebreaker introduce a declaration the wiki does not list,
      so a name cannot re-enter the catalog from a dead source.
- [ ] Record which declarations took a tiebreaker value, so the dependency's
      remaining influence stays countable and can be removed later.

### T-03 - Preserve override precedence

**Agent:** architecture-engineer

- [ ] Apply `catalog-overrides.ts` after the parse, unchanged, so every existing
      hand-written correction still wins.
- [ ] Report an override that now matches what the wiki says, since it has
      become dead weight.

### T-04 - Regenerate and review

**Agent:** architecture-engineer

- [ ] Regenerate and split the diff into three parts: functions added, existing
      signatures changed, and environments changed.
- [ ] Review the second and third parts entry by entry. A new function is cheap
      to accept; a changed existing signature can break code that compiles today.

## Acceptance Criteria

- [ ] The catalog declares every function the snapshot lists, at least 1383.
- [ ] Running generation twice from one snapshot produces no diff.
- [ ] No generated declaration originates from the tiebreaker alone.
- [ ] Every override still applies, and any override the wiki made redundant is
      reported.
- [ ] Every changed existing signature and environment appears in the review
      diff, categorised.
- [ ] Compiler packages make no network call, and a build with no network
      succeeds.
- [ ] `pnpm typecheck` and `pnpm test` pass.
