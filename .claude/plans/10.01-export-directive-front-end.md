# 10.01 - Parse, check, and erase the `export` directive

> File: `.claude/plans/10.01-export-directive-front-end.md`
> First half of the directive: the front end recognises `export`, rejects the
> forms MTA cannot honour, and emits Lua that is unchanged by it. The manifest
> half is 10.2.

## Objective

Let a source file mark a function as callable from other resources, with the
mistakes MTA fails silently on turned into diagnostics, and with no effect on
the emitted Lua.

## Scope

- **In:** Lookahead in the parser, `isExported` on `FunctionDeclaration`,
  checker rules, the contribution type on `CompileResult`, erasure in the
  emitter.
- **Out:** Manifest emission and pipeline plumbing (10.2), further directives
  (10.3), editor support (10.4).

## Steps

- [x] Leave `KEYWORDS` in `lexer/token.ts` untouched. `export` reaches the
      parser as an identifier, per [ADR-007](../docs/adr/007-build-directives.md).
- [x] Add `isDirectiveStart` to `parser/statement.ts`, recognising an
      `identifier` `export` followed by the `function` keyword, and route it to
      `parseFunctionDeclaration` with the directive recorded.
- [x] Add `isExported: boolean` to `FunctionDeclaration` in `parser/ast.ts` and
      set it in `parser/function-expression.ts`. Every existing construction
      site sets `false`.
- [x] Report `parse-export-local` when `export` precedes `local function`,
      with a message naming the reason: MTA resolves an export against the
      resource's globals.
- [x] Collect exports in the checker beside `declaredGlobals`, keyed by name
      with the declaration position, and expose them on the check result.
- [x] Report `check-export-not-top-level` for an `export` inside any block, and
      `check-export-member` for `export function a.b()` — MTA names a single
      global in the manifest.
- [x] Report `check-export-in-declaration-file` for an `export` in a `.d.luam`
      file, which emits nothing to export.
- [x] Add `directives: SourceDirectives` to `CompileResult` in
      `packages/compiler/src/index.ts`, populated from the check result on both
      the `emitCode: false` and the full pass. The plan called for a bare
      `exports` field; it is one level deeper so 10.3 can add its two kinds
      without changing `CompileResult`, `CompiledModule`, or anything between
      `compileModule` and `assembleResource`.
- [x] Confirm the emitter ignores `isExported`: the Lua for an exported
      function is byte-identical to the same function without the directive.
- [x] Document the syntax and the rules in
      [language-design](../docs/language-design.md).

## Acceptance Criteria

- [x] `export function f() {}` in `src/server/main.luam` compiles with no
      diagnostics and emits `function f()` with no marker of any kind.
- [x] `local export = 1` and `export = getPlayers()` still compile — `export` is
      a usable identifier everywhere except before `function`.
- [x] `export local function f() {}` reports `parse-export-local`.
- [x] `export` on a function nested in an `if` or a function body reports
      `check-export-not-top-level`.
- [x] `export function a.b() {}` reports `check-export-member`.
- [x] `CompileResult.directives.exports` lists the name and position of every
      exported function, and is empty for a file that uses none. The side is
      resolved from `CompileResult.environment` by `toContributions` in 10.2
      rather than duplicated on the checker result.
- [x] A file that exports nothing produces output identical to before this task,
      verified by the existing emitter snapshots.
