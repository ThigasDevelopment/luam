# 50.02 - Give the CLI a workspace context

## Objective

Let a command run from a directory that holds a `.luam.server` and no
`.luam.manifest`, and give it one command context per resource discovered there,
without changing what any command does inside a resource directory.

## What is in the way

Every command that needs a project calls `createProjectContext`
([cli-runtime](../../packages/cli/src/cli/cli-runtime.ts)), which loads exactly
one manifest from the root and returns `EXIT_USAGE` when there is none. A
workspace root has no manifest, so today every command fails there with
`No manifest found at "…/resources/.luam.manifest"` — a true sentence about the
wrong file.

## Scope

- **In:** A workspace context beside the project context, the rule that decides
  which one an invocation gets, `luam server` and a non-interactive
  `luam ensure <resource>` at a workspace root, and the diagnostics for a root
  that resolves to neither.
- **Out:** The session and its verbs (50.04–50.06), and the manifest deprecation
  warning (50.03).

## The rule

Resolution is by directory, decided once, and reported when it fails:

1. The root holds a `.luam.manifest` → **project mode**, exactly as today. A
   `.luam.server` above it still supplies the deployment values.
2. The root holds no manifest but a `.luam.server` is found by walking up from it
   → **workspace mode**, and the workspace root is the directory holding that
   file, not the working directory.
3. Neither → the error names both files and both fixes, replacing today's
   manifest-only message.

`--manifest` forces project mode; it names a manifest, and a flag that names one
file cannot select a mode that has none.

## Steps

- [ ] Add `WorkspaceContext` in `cli-runtime`: the workspace root, the loaded
      server config, the discovered resources, the logger and the reporter. It is
      not a `CommandContext` — it has no `config` — and nothing should pretend it
      is one.
- [ ] Add `createWorkspaceContext(runtime, command, options)`: find the file,
      load it, report its diagnostics through `reportManifestDiagnostics`, and
      return `EXIT_USAGE` when it is invalid. A workspace whose file does not
      parse is not a workspace.
- [ ] Add `resourceContext(workspace, name)`: load that resource's manifest with
      the existing `loadManifest`, apply the workspace deployment values to the
      resulting config, and return a `CommandContext` whose `root` is the
      resource directory. Every existing command path keeps working because it
      still receives exactly the context it receives today.
- [ ] Report an unknown resource name against what was discovered: name the
      workspace root and list the resources found, five at most, the way
      `config-unmatched-source` lists files.
- [ ] Point `luam server` at the workspace context when the root has no manifest.
      `startMtaServer` takes `root` and a `LuamConfig` today; give it a narrower
      input — the resolved server root, executable and log path — so a command
      that starts a server no longer needs a resource to exist.
- [ ] Add `luam ensure [resource...]` at a workspace root: resolve each name to a
      resource context and run the existing `runEnsureCommand` once per resource
      with `watch: false`. No session, no owned console, so it syncs and does not
      restart — the same contract standalone `ensure` has today. With no name it
      is a usage error that lists the resources.
- [ ] Leave `createProjectContext` untouched. A resource directory resolves the
      way it always has.

## Acceptance Criteria

- [ ] `luam server` runs from a directory holding only a `.luam.server` and
      resource subdirectories.
- [ ] `luam ensure resource-a` at a workspace root builds and syncs that resource
      once and exits `0`; a failing build exits `1` and syncs nothing.
- [ ] `luam ensure nope` names the workspace root and lists the discovered
      resources.
- [ ] `luam ensure` inside `resource-a/` behaves exactly as it does today, and
      picks up `serverPath` from a `.luam.server` above it.
- [ ] A directory with neither file reports an error naming both files and both
      fixes.
- [ ] `--manifest` still selects project mode from any directory.
- [ ] A `.luam.server` that does not parse stops the command with `EXIT_USAGE`
      and the file's own diagnostics.
- [ ] `pnpm -r test`, `pnpm typecheck` and `pnpm conventions` pass.
