# 50.05 - Open a workspace session with `luam dev`

## Objective

Make `luam dev` at a workspace root start the one MTA server the directory
shares, attach no resource, and hand the terminal to a session that reads both
vocabularies.

## Why it attaches nothing

The set of resources a developer is touching changes hourly. A session that
compiles every resource in the directory to open costs the most in exactly the
case the workspace exists for — a folder with twenty resources and two under
work. Opening the session is a server start and a log follow; the first build
happens when the developer says which resource they mean.

## Scope

- **In:** The workspace form of `luam dev`: process, readiness, log stream,
  session loop, exit and shutdown semantics, and the report a session prints when
  it opens.
- **Out:** The verbs themselves (50.06). This task wires a session that
  recognises them and holds the state they mutate.

## The shape

```
$ luam dev
Started the MTA server at "…/server" and waited for readiness in 4.2 s.
Watching nothing yet. Type "ensure <resource>" to attach one, "help" for the rest.
Resources here: resource-a, resource-b.
[14:22:09][server][info] Server started and is ready to accept connections
```

`luam dev` inside a resource directory is untouched, `--start-server` and all.

## Steps

- [ ] Add the workspace branch to the `dev` registration: workspace context when
      the root has no manifest, project context otherwise, decided by 50.02's
      rule.
- [ ] Reject `--start-server` at a workspace root as a usage error, the way
      `luam dev --bundle` is rejected today. The session always owns the server;
      a flag that says "also do the thing you always do" reads as though there is
      a mode where it does not.
- [ ] Start the server through `startMtaServer` with the resolved workspace
      deployment values from 50.03, and wait for readiness before the session
      accepts a verb. A verb typed during startup is buffered by 50.04's line
      buffer and executed once the server is ready, not dropped.
- [ ] Hold session state: the workspace, the discovered resources, and a map from
      resource name to its attached record — context, ensure runner, watcher, and
      the outcome and timestamp of its last build. This map is what 50.06 mutates
      and `list` reads.
- [ ] Follow the server log once for the session. `parseMtaLogLine` takes one
      resource name today; give it the attached set, prefix each attributed record
      with the resource that produced it, and keep passing unattributed engine
      output through as plain server output, exactly as it behaves now.
- [ ] Serialise builds across the session. One rebuild at a time, per-resource
      queueing as the current `watchLoop` does per project, so two resources saved
      together produce two ordered reports and two ordered console writes rather
      than interleaved ones.
- [ ] Keep the exit semantics of `dev --start-server`: an unexpected server exit
      stops the session and returns `EXIT_DIAGNOSTICS`; `Ctrl+C` writes MTA's
      `shutdown` with the bounded kill fallback and returns `EXIT_OK`.
- [ ] Close every watcher on shutdown. A session that leaves an `fs.watch` behind
      keeps the process alive after the server is gone.

## Acceptance Criteria

- [ ] `luam dev` at a workspace root starts exactly one MTA process, waits for
      readiness, and reports the server path, the resources discovered, and that
      nothing is attached.
- [ ] Nothing is compiled, written or watched until a resource is attached.
- [ ] `luam dev --start-server` at a workspace root is a usage error naming the
      reason.
- [ ] `refresh` typed into the session reaches the MTA console and its output
      appears in the log stream.
- [ ] An unexpected server exit ends the session with `EXIT_DIAGNOSTICS` and a
      message naming the code or signal.
- [ ] `Ctrl+C` shuts the server down and closes every watcher; the process exits
      and leaves no handle open.
- [ ] `luam dev` inside a resource directory behaves exactly as it does today,
      with and without `--start-server`.
- [ ] `pnpm -r test`, `pnpm typecheck` and `pnpm conventions` pass.
