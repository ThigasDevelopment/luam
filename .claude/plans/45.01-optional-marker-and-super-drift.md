# 45.01 - Reconcile the internal language design with the optional marker and super rules

> File: `.claude/plans/45.01-optional-marker-and-super-drift.md`

## Objective

Make `.claude/docs/language-design.md` state the two rules the compiler actually
enforces, so the document a porting author reads first stops teaching forms that
do not compile.

## Reproduction

Both snippets are copied from `language-design.md` on the current tree and both
are rejected:

```luam
local player: Player? = nil
# parse-optional-position: Write optional locals as "name?: Type", not "name: Type?".

class VIPPlayer extends Player {
    constructor = function (name: string, level: number)
        self:super(name)
        # check-invalid-super: Call "super(...)" directly instead of "self:super(...)".
    end
}
```

`docs/en/language/classes.md` and `docs/en/language/types.md` are already
correct, and the changelog records both changes. Only the internal design
document is stale, and it is the document the porting work reads.

## Root Cause

- `parseNamedAnnotation` (`packages/compiler/src/parser/type-annotation.ts:266`)
  applies `parse-optional-position` to `field`, `local` and `parameter` alike.
  Milestone 32.07 unified the marker position; the design document still carries
  the pre-32.07 sentence "Locals and parameters still use optional types because
  they do not declare fields", plus two examples that use the rejected form.
- `checkExpression` (`packages/compiler/src/checker/expressions.ts:281`) rejects a
  `self:super(...)` receiver. The design document's Classes section still shows
  it in two snippets and describes it in prose.

The implementation is the intent in both cases. The document changes, not the
compiler.

## Scope

- **In:** The Variables, Function Types, Classes and Interfaces sections of
  `.claude/docs/language-design.md`, and any other internal document repeating
  either form.
- **Out:** Any compiler change. Any change to `docs/en` or `docs/pt-br`, which are
  already correct. The `fun` type's own optional-parameter gap, which is 45.06.

## Steps

- [x] Replace every `name: Type?` declaration example in `language-design.md` with
      `name?: Type`, and delete the sentence exempting locals and parameters.
      State the one rule: the marker attaches to the name, everywhere a name is
      declared.
- [x] Keep `Type?` where it is still correct — a type position that declares no
      name, such as a return type, an alias body, or a type argument — and say so
      explicitly, so the correction does not overshoot.
- [x] Replace `self:super(...)` with `super(...)` in the Classes section, in both
      the source snippet and the generated-Lua snippet, and record that
      `self:super(...)` is `check-invalid-super`.
- [x] Sweep the rest of `.claude/docs` and `.claude/skills` for either form and
      correct what is found.
- [x] Add a check to the documentation drift job so a snippet in
      `.claude/docs/language-design.md` that does not compile fails the build,
      the way `docs:snippets` already guards the public manual.

## Acceptance Criteria

- [x] Every Luam snippet in `.claude/docs/language-design.md` compiles.
- [x] The document states the marker rule once, with the type-position exception
      named.
- [x] `super(...)` is the only parent-call form the document shows.
- [x] The drift check fails when a non-compiling snippet is reintroduced.
- [x] `docs/en` and `docs/pt-br` are unchanged.
