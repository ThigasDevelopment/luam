# 41.01 - Complete a typed table literal by the keys its type still allows

## Objective

Make completion inside a table literal that carries a type annotation offer the
keys that type still allows — all of them, only them, and nothing else — so the
list answers the question the developer is actually asking at that position.

## Scope

- **In:** `constructionMembers` in `packages/lsp/src/features/type-shape.ts`,
  the key-position test in `packages/lsp/src/features/table-literal.ts`, and how
  `completionAt` orders `tableKeyItems` against the rest of the list in
  `packages/lsp/src/features/completion.ts`.
- **In:** The completion rows of [editors](../../docs/en/tooling/editors.md) and
  its `pt-br` counterpart, which today describe member completion and say
  nothing about a table literal.
- **Out:** The checker. `check-type-mismatch` on the reported source is correct
  and stays exactly as it is — see Context.
- **Out:** The single-line reach of `annotationBefore`. A literal whose
  `: Type =` sits on an earlier line, or one nested inside another literal,
  resolves to no members today and keeps resolving to none; every step below is
  conditioned on members being found, so none of them changes that case.
- **Out:** A literal with no annotation, one passed as a call argument, an
  array-style literal, and a class or interface body. All four already yield no
  key items and must keep offering the scope.

## Context

The reported source:

```lua
type Base = {
    id: string
}

type SQLite = Base & {
    type: "sqlite"
    path: string
}

type Mysql = Base & {
    type: "mysql"
    host: string
    port: number
}

type Teste = SQLite | Mysql

local data: Teste = { type = "sqlite", path = "teste" }
```

The diagnostic on the last line is right, and no step here touches it:

```
check-type-mismatch: Variable "data" expects "SQLite | Mysql" but received
"{ type: 'sqlite', path: 'teste' }". Key "id" is missing from "SQLite".
```

`SQLite` intersects `Base`, `Base` requires `id`, the literal has none, so no
member of the union matches. Adding `id` compiles clean, and the discriminant
already narrows: with `type = "sqlite"` written, the checker asks for the keys
of `SQLite` and not those of `Mysql`.

What was wrong is the editor. Three defects, measured at the same positions:

| Position | Before | After T-01 and T-02 |
|---|---|---|
| `= { type = "` | `sqlite` | `sqlite`, `mysql` |
| `= { path = ` | `id`, then the scope | the scope alone |
| `= { ` | `id`, `path`, `host`, `port`, then ~740 more | unchanged — T-03 |

T-01 and T-02 have landed and are recorded below as done. The third row is what
remains: in a position where only a key can go, the list is led by the right
answers and then buried under every type name, every scope symbol, every MTA
global and every keyword. The two useful entries are the first two of roughly
seven hundred and fifty.

The current behaviour is not an oversight — `keeps the scope items available
after the keys` in `packages/lsp/tests/shape-completion.test.ts` fixes it
deliberately. Overturning it is a decision, which is why T-03 records one before
T-04 writes code.

## Steps

### T-01 - Type a shared key as the union of the members that still match

**Agent:** architecture-engineer

- [x] `constructionMembers` merged the candidate shapes first-one-wins, so a key
      declared by more than one union member kept only the first member's type
      and `expectedStringType` saw `'sqlite'` where the type is
      `'sqlite' | 'mysql'`.
- [x] Collect every candidate's type for a key and fold them with `createUnion`,
      which already flattens and deduplicates, so a key shared by two members
      that declare it identically is unchanged.
- [x] Confirm the discriminant offers both values inside the quotes, and that
      the `detail` of the key item reads `type: 'sqlite' | 'mysql'`.

### T-02 - Stop offering keys where a value is expected

**Agent:** architecture-engineer

- [x] `tableKeyItems` fired anywhere inside the braces, so `{ path = ` offered
      the sibling keys as if a key could follow the `=`.
- [x] Add `isTableKeyPosition` to `table-literal.ts`: scan back from the offset
      to the opening brace, balance nested brackets, stop at a `,` or a newline,
      and report a value position on a pending `=` that is not part of `==`,
      `~=`, `<=` or `>=`.
- [x] Guard `tableKeyItems` with it, and leave `tableLiteralMembers` alone —
      `expectedStringType` calls it from inside the value and needs the members
      there.

### T-03 - Decide what a key position offers, and record it

**Agent:** architecture-engineer

- [x] Decide between the current merge — keys first, then the whole list — and
      keys alone. Keys alone is what TypeScript does at the same position and
      what makes the list readable; the merge costs nothing to keep and never
      hides a candidate.
- [x] Weigh the one case the merge serves: a developer who wants a name from the
      scope while the cursor sits where a key goes. They are one character away
      from a value position, where the scope is offered in full.
- [x] Record the decision in this file before T-04 writes code, so the test
      rewritten in T-06 and the documentation row in T-07 follow one answer.

**Decision: keys alone.** A key position takes an identifier the type names and
nothing else, so a list of roughly seven hundred and fifty entries answers a
question nobody asked there. The merge only ever served a developer reaching for
a scope name where a key goes; they reach it by typing the `=` that puts them in
a value position, which offers the scope in full and is one character away. The
guard stays `keys.length > 0`, so every position that yields no key items — no
annotation, a call argument, an array-style literal, a class or interface body,
an annotation on an earlier line — falls through to exactly the list it builds
today. This is what T-06 asserts and what T-07 documents.

### T-04 - Return the keys alone from a key position

**Agent:** architecture-engineer

- [x] In `completionAt`, replace the `tableKeyItems` spread with an early return
      taken when it yields at least one item.
- [x] Place it after the `onlyStringLiterals` early return and before the final
      spread, so string-literal completion inside the quotes keeps winning.
- [x] Keep the `keys.length > 0` guard as the thing that preserves every
      out-of-scope case: each of them yields no key items and falls through to
      the list built today.

### T-05 - Walk the positions that must not change

**Agent:** architecture-engineer

- [x] `local one: SQLite = { sender = ` — value position, scope in full.
- [x] `local t = { ` — no annotation, scope in full.
- [x] `outputChatBox({ ` — call argument, scope in full.
- [x] `class Adapter {` and an interface body — scope in full, `static` and the
      `constructor` snippet still offered where they are today.
- [x] `local data: Config = { kind = "` — the two discriminant values, and no
      scope, as T-01 left it.

### T-06 - Cover the decision and every position from T-05

**Agent:** test-engineer

- [x] Rewrite `keeps the scope items available after the keys` to assert the
      decision from T-03 instead of the behaviour it replaces, keeping the name
      honest about what it now fixes.
- [x] Assert the key list is exactly the remaining keys — narrowed by a written
      discriminant, and with an already-written key absent.
- [x] Assert one test per position in T-05, each naming the reason that position
      keeps the scope.

### T-07 - Say what the editor does in a table literal

**Agent:** documentation-engineer

- [x] Add a row to the feature table in
      [editors](../../docs/en/tooling/editors.md): inside a literal annotated
      with a record type, the keys that type still allows, narrowed by a written
      discriminant, with the written ones removed.
- [x] Mirror it in `docs/pt-br/tooling/editors.md`, in the same table position.
- [x] Do not document the single-line reach of the annotation as a rule. It is a
      limitation to lift, not a contract to publish.

### T-08 - Verify it in the installed extension

**Agent:** architecture-engineer

- [x] The tests cover the item list, not the experience. Rebundle, repackage and
      reinstall the VSIX, then `Developer: Reload Window` — the server process
      does not restart otherwise.
- [x] Type the source from Context and confirm the list at `= { ` is short, that
      `id` is in it, and that the diagnostic disappears when `id` is written.
- [x] Grep a distinctive new string in `dist/server/luam-lsp.cjs` to prove the
      build that is running is the build that was just made.

The VSIX was rebundled, repackaged and reinstalled, and
`~/.vscode/extensions/luam.luam-0.19.5/dist/server/luam-lsp.cjs` carries
`const keys = tableKeyItems(analysis, offset)`, which the previous build did
not. Every position of the reported source was walked through the language
service and matches the Acceptance Criteria exactly. Confirmed in the editor at
`local data: Teste = {}` with the cursor between the braces: five entries, the
whole global surface gone. `Developer: Reload Window` was not enough on the
window that was open — it took `Developer: Restart Extension Host`, and the two
shapes it exposed, braces the editor closed for you and a cursor on the line
after the opening brace, are now covered by their own tests.

## Acceptance Criteria

- [x] At `local data: Teste = { `, the list is exactly `id`, `type`, `path`,
      `host`, `port` — no type names, no scope symbols, no MTA globals, no
      keywords.
- [x] With `type = "sqlite"` written, the same position offers exactly `id` and
      `path`, and `host` and `port` are absent.
- [x] With `id` also written, it offers exactly `path`.
- [x] Inside the quotes of `type = "`, both `sqlite` and `mysql` are offered
      before either is chosen.
- [x] The `detail` of a key declared by more than one matching member reads the
      union of its types.
- [x] Every position in T-05 still offers the scope, each proven by its own test.
- [x] The checker is untouched: the diagnostic on the reported source is
      byte-identical before and after, and the compiler suite passes with no
      change to any snapshot.
- [x] `packages/lsp` passes in full, and `tsc --noEmit` is clean for the package.
- [x] `docs/en` and `docs/pt-br` describe the same behaviour, and it is the
      behaviour the tests assert.
