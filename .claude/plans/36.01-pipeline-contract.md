# 36.01 - Inventory the pipelines and define their contract

## Objective

Establish what every workflow is for, what may block a merge, and what each one
is allowed to touch, so the reorganization that follows moves code against a
written contract instead of taste.

## Scope

- **In:** An inventory of the four workflows and the composite action, one role
  per workflow, the required-check set, the permission and secret budget per
  job, and an ADR recording the contract.
- **Out:** Any change to workflow behavior. This task decides; the tasks after
  it move code.

## Steps

### T-01 - Inventory the current surface

**Agent:** github-engineer

- [x] Record for `ci.yml`, `docs.yml`, `release.yml`, `catalog-refresh.yml` and
      `.github/actions/setup`: triggers, jobs, the `needs` graph, `permissions`,
      secrets read, and wall-clock.
- [x] Mark every step duplicated across two or more workflows.
- [x] Mark every action reference not pinned to a commit SHA. Today only
      `catalog-refresh.yml` pins; the other three use floating `@v4`.

### T-02 - Define the contract

**Agent:** github-engineer

- [x] Assign each workflow one role: merge gate, publication, or scheduled
      maintenance. A workflow serving two roles is a finding, not a design.
- [x] Name the required checks, and state which jobs are advisory and why.
- [x] State the permission budget: every job declares `permissions`, default
      `contents: read`, elevation only where the job needs it.
- [x] State the pinning rule: third-party actions by commit SHA with the version
      in a trailing comment, first-party by path.

### T-03 - Record the decision

**Agent:** github-engineer

- [x] Write an ADR for the pipeline contract, claiming the next free number from
      [the ADR index](../docs/adr/README.md).
- [x] Link the ADR from the roadmap milestone section.

## Acceptance Criteria

- [x] Every workflow, job, trigger, permission and secret appears in one table,
      with duplicated steps and unpinned actions marked.
- [x] Each workflow has exactly one role.
- [x] The required-check set is named, and every job outside it is labelled
      advisory with a reason.
- [x] The permission and pinning rules are written as rules, not examples.
- [x] An ADR records the contract with a status.
- [x] No workflow file changed in this task.
