# 37.04 - Document the return rule and generic functions

## Objective

Make both manual trees describe what milestone 37 changed, so a reader is not
told that a return annotation is checked only where a `return` is written, and
so generic functions are discoverable rather than found by trying.

## Scope

- **In:** The English and Portuguese pages for functions, types, diagnostics and
  limitations, plus both changelogs and the root `CHANGELOG.md`.
- **Out:** New recipes. A generic utility may deserve one; that is a separate
  decision once the feature ships.

## Context

`docs/en/language/functions.md` does not contain the word "generic", because
until 37.02 there was nothing to say. `docs/en/reference/diagnostics.md` lists
131 codes and gains one. `limitations.md` gains an entry for what single-pass
inference cannot bind, and its contract file has to agree.

The limitations page is generated against `docs/scripts/limitations-contract.ts`,
so an entry added to the page without a matching contract entry fails
`pnpm docs:limitations`. Both trees are parity-checked, so an English page
without its Portuguese counterpart fails `pnpm docs:parity`.

## Record

### T-01 - The return rule

- `docs/*/language/functions.md`, under **Return types**: a declared return type
  has to be produced on every path, the failing example, both repairs named, the
  list of annotations that tolerate falling through, and the two exceptions —
  a loop that cannot fall through is not reported, and `error(...)` is.
- `docs/*/reference/diagnostics.md` gains `check-missing-return` at **error**,
  matching the severity 37.01 T-02 decided on a zero blast radius.
- The **Common errors** table on both function pages gains a row for it.
- Limitations gains **`error(...)` does not end a path**, labelled
  **Design boundary** — not **Planned** — because 37.01 T-01 recorded it as
  needing a never-returning type the language does not have, not as pending
  work. `limitations-contract.ts` gains `error-is-not-a-terminator`, pointed at
  the plan that records the decision.

### T-02 - Generic functions

- A **Generic functions** section on `docs/*/language/functions.md`: the syntax,
  inference at the call site, explicit arguments, constraints, the function
  expression and class method forms with shadowing, and erasure.
- Cross-links in both directions. `types.md` (generic aliases) and `classes.md`
  (generic classes) each name the other two forms, so the three read as one
  feature.
- Limitations gains **A type parameter only in the return position is `any`**,
  labelled **Design boundary**, pointed at ADR-032 — the rule is inherited from
  the erasure model, not introduced here. `limitations-contract.ts` gains
  `return-position-inference`.

**A stale claim was found and fixed.** `docs/*/language/types.md` said "Generic
**classes** are not supported — see Limitations", which stopped being true when
ADR-032 shipped in 0.13.0. It now names classes and functions as the other two
forms. This is exactly the sentence T-02's last bullet asked to look for.

### T-03 - Changelogs and verification

`CHANGELOG.md` records generic functions under **Added** and the return rule
under **Fixed**, since a declared return type not being enforced was a hole
rather than a missing feature. Both `docs/*/changelog.md` record the manual
changes under `Unreleased`.
