# 37.04 - Document the return rule and generic functions

## Objective

Make both manual trees describe what milestone 37 changed, so a reader is not
told that a return annotation is checked only where a `return` is written, and
so generic functions are discoverable rather than found by trying.

## Scope

- **In:** The English and Portuguese pages for functions, types, diagnostics and
  limitations, plus both changelogs and the root `CHANGELOG.md`.
- **Out:** New recipes. A generic utility may deserve one; that is a separate
  decision once the feature ships.

## Context

`docs/en/language/functions.md` does not contain the word "generic", because
until 37.02 there was nothing to say. `docs/en/reference/diagnostics.md` lists
131 codes and gains one. `limitations.md` gains an entry for what single-pass
inference cannot bind, and its contract file has to agree.

The limitations page is generated against `docs/scripts/limitations-contract.ts`,
so an entry added to the page without a matching contract entry fails
`pnpm docs:limitations`. Both trees are parity-checked, so an English page
without its Portuguese counterpart fails `pnpm docs:parity`.

## Steps

### T-01 - The return rule

**Agent:** documentation-engineer

- [ ] State in `docs/en/language/functions.md`, and its `pt-br` counterpart, that
      a declared return type must be produced on every path, and that an optional
      annotation is how a function is allowed to end without a value.
- [ ] Add `check-missing-return` to `docs/*/reference/diagnostics.md` with its
      severity, matching the decision recorded in 37.01 T-02.
- [ ] Add a limitations entry for the `error(...)` false positive, labelled
      **Planned** or **Design boundary** according to what 37.01 T-01 recorded,
      and add the matching entry to `docs/scripts/limitations-contract.ts`.

### T-02 - Generic functions

**Agent:** documentation-engineer

- [ ] Add a generic functions section to `docs/*/language/functions.md`: the
      syntax, inference at the call site, explicit arguments, and constraints.
- [ ] Cross-link it from `docs/*/language/types.md`, which describes generic
      aliases, and from `docs/*/language/classes.md`, which describes generic
      classes, so the three forms read as one feature.
- [ ] Add a limitations entry stating that a parameter appearing only in a return
      position is `any`, with the matching contract entry.
- [ ] Confirm no page still implies that only aliases and classes take type
      parameters.

### T-03 - Changelogs and verification

**Agent:** documentation-engineer

- [ ] Add the milestone 37 entry to `CHANGELOG.md` and to both
      `docs/*/changelog.md`.
- [ ] Run `pnpm docs:verify` and confirm parity, limitations, snippets, outputs,
      examples, layout and the build all pass.

## Acceptance Criteria

- [ ] Both trees describe the return rule and generic functions, and
      `pnpm docs:parity` passes.
- [ ] `pnpm docs:limitations` passes with both new entries.
- [ ] `check-missing-return` appears in both diagnostics references.
- [ ] Every example added to a page compiles, proven by `pnpm docs:examples` and
      `pnpm docs:snippets`.
- [ ] `pnpm docs:verify` passes end to end.

## Out of Scope

- New recipes.
- Translating anything beyond the pages this milestone touches.
