# 44.05 - Show the fields of a value's type on hover

> File: `.claude/plans/44.05-hover-type-shape.md`

## Objective

Answer a hover on a typed value with the fields that type declares, so
`parameter props: NetworkProps` stops being a name the author has to go look up.

## Reproduction

Confirmed on the current tree through `LanguageService.hover`:

```luam
type Props = {
    event: string;
    secret?: string;
}

interface Shape {
    size: number;
}

class Box {
    width: number = 1;
}

function take(props: Props, shape: Shape)
    local box = new Box();
end
```

| Hover | Answer today | Missing |
|---|---|---|
| `props` | `parameter props: Props` | the two fields |
| `shape` | `parameter shape: Shape` | `size: number` |
| `box` | `local box: Box = new Box();` | `width: number` |

Hovering the declaration of `Props`, `Shape` or `Box` does expand the body. Only
a value typed by one of them does not.

## Root Cause

`bodyText` (`packages/lsp/src/features/declaration-shape.ts:40`) expands a body
only for the `class`, `interface` and `enum` kinds, and `summaryText` is called
with the declaration under the cursor — a `parameter` or a `local`, whose kind is
in neither set. Nothing walks from the value to its type. `isContainer` has the
same limit, so `containerShape` — the helper behind the `**Instance**` block that
`member-hover.ts` already prints — never resolves a type alias either.

## Scope

- **In:** A shape block under the signature when the hovered value has a type with
  fields, sourced from the checker's type for a record and from the symbol index
  for a class or interface, and the same source feeding the existing
  `**Instance**` block in `member-hover.ts`.
- **Out:** New content for a primitive, a function or an opaque type; any change to
  the checker; and expanding a nested field's own type, which stays one level.

## Steps

- [ ] Add a shape resolver that takes a `Type` and returns its fields: a `record`
      renders from the type itself, so a `type` alias and an inline object literal
      type both work; a `named` type resolves through the symbol index the way
      `containerShape` does today, extended to reach an alias declaration.
- [ ] Render an optional field with its `?`, keep the declared order, and reuse
      the existing `MEMBER_LIMIT` with the `# N more` line so a wide type does not
      fill the screen.
- [ ] Print the block under the signature, headed the way `member-hover.ts` heads
      its instance block, so both hovers read the same.
- [ ] Return nothing extra for `any`, `unknown`, `table`, a primitive, a function
      and a type whose fields cannot be resolved — the hover keeps exactly the text
      it prints today.
- [ ] Point `shapeOf` in `member-hover.ts` at the new resolver, so a member whose
      type is an alias gets the block a member whose type is a class already gets.

## Acceptance Criteria

- [ ] Hovering `props` answers `parameter props: Props` followed by
      `event: string` and `secret?: string`.
- [ ] Hovering a value typed by an interface, by a class, and by an inline object
      type each answers with that type's fields.
- [ ] Hovering `props.password` — a member whose type is a record — answers with
      the member type from 44.02 and, where that type has fields, its shape.
- [ ] A value typed `string`, `number`, `any`, `table` or a function hovers exactly
      as it does today.
- [ ] A type with more fields than the limit shows the limit and the `# N more`
      line, and no hover exceeds it.
- [ ] Every hover fixture in the suite keeps its current answer, or is updated
      because it gained the block.
