# 47.03 - Type Promise, async returns and await

## Objective

Make `Promise<T>` a type the checker resolves, so an async function's return and
an `await` carry real types instead of `any`, and misuse is a diagnostic rather
than a runtime surprise.

## Scope

- **In:** The `Promise` built-in generic type, `new Promise(executor)`, the
  return type of an async function, the type of an `await`, and four
  diagnostics.
- **Out:** Inferring `T` from the executor's `resolve` calls. An explicit type
  argument or `Promise<any>` is enough for this milestone.

## Steps

- [x] Register `Promise` as a built-in generic type with one parameter, seeded
      where the runtime globals are declared, reusing the substitution in
      `checker/generic-class.ts` and `checker/type-substitution.ts`.
- [x] Type the runtime surface in `mta-types/src/luam-runtime.ts` beside
      `Threads` and `Async`: `next` and `catch` on an instance, and the statics
      `all`, `race`, `resolve`, `reject`, `settle` and `delay`.
- [x] Give `Promise` the native-constructor shape, so `new Promise(executor)`
      lowers like `new Threads(...)` and the bare `Promise.new(...)` is rejected
      by the existing `check-native-constructor` rule.
- [x] An async function's annotation is the **inner** type:
      `async function f(): number` has signature return `Promise<number>`. Apply
      it in `buildFunctionType` and `checkFunctionBody` so an omitted annotation
      wraps the inferred type the same way.
- [x] `await p` where `p` is `Promise<T>` has type `T`. A rejection raises rather
      than widening the type, so nothing about the result becomes optional and
      `local variable = await f()` binds the value.
- [x] Report `check-await-outside-async` when `await` is used outside an async
      function. The parser leaves the word as an identifier there, so this fires
      on the unresolved reference it produces in operator position.
- [x] Report `check-await-non-promise` when the operand's type is not
      `Promise<T>`, naming the type it found.
- [x] Report `check-async-return-annotation` when an async function is annotated
      `Promise<...>` directly, hinting that the annotation is the inner type.
- [x] Warn `check-sleep-outside-async` on a direct `sleep` call in a non-async
      named function declaration or at module top level. Keep it narrow: a
      function *expression* is exempt, because it may be a `Threads` job and the
      checker cannot prove otherwise.
- [x] Add hover text for every new member in `runtime-documentation.ts`.

## Acceptance Criteria

- [x] `local variable = await otherAsyncFn()` types `variable` as the async
      function's declared return — not as a boolean, not as `any`.
- [x] `async function f(): number` reports `Promise<number>` on hover at the call
      site, and `f():next(...)` resolves `next`.
- [x] `new Promise(...)` is accepted and `Promise.new(...)` is rejected, matching
      `Threads` and `Async`.
- [x] Each of the four diagnostics fires on its own case and on nothing else. The
      `sleep` warning stays silent inside `threads:add(function() ... end)`.
- [x] `Promise.settle(p)` types as the existing tuple `(boolean, T)`, so a
      multi-return local destructures it.
- [x] The four codes are documented in both diagnostics references and
      `pnpm docs:verify` passes.
