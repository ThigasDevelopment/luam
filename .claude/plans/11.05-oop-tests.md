# 11.05 - Cover the OOP API with catalog, checker, manifest, and editor tests

> File: `.claude/plans/11.05-oop-tests.md`
> Tests live in each package's `tests/` folder, never beside the source.

## Objective

Prove that the OOP surface is generated rather than typed by hand, that it
resolves through the same paths user classes use, that it disappears entirely
when `oop` is off, and that it never changes the emitted Lua.

## Scope

- **In:** Generator drift, checker resolution and diagnostics, the `oop` gate,
  manifest output, LSP completion and hover, and a fixture resource written in
  the OOP style.
- **Out:** Running the generated Lua. No MTA server and no Lua interpreter take
  part.

## Steps

- [x] Generator tests: the OOP surface regenerates with no diff, a hand edit
      fails the drift test, and every method maps to a declared procedural
      function.
- [x] Checker tests: a method resolves, an inherited method resolves, an unknown
      member is `check-unknown-member`, a wrong argument is
      `check-type-mismatch`, and a server-only method in a client file is
      `check-environment-api`.
- [x] Gate tests: the same source checks clean with `oop` on and reports
      `check-oop-disabled` with it off, and the message names the procedural
      function.
- [x] Emitter test: a file using OOP calls emits the calls verbatim, compared
      string to string.
- [x] Manifest tests: `<oop>true</oop>` sits above `<info>` when enabled, and a
      project with the flag off produces a manifest identical to the milestone 10
      snapshot.
- [x] Cache test: flipping `oop` rechecks every module.
- [x] LSP tests: completion after `:` on an element, inherited members,
      environment scoping, hover text, and nothing offered with the flag off.
- [x] Add a fixture resource written against the OOP API and snapshot its
      compiled output and manifest.
- [x] Confirm `pnpm typecheck`, `pnpm build`, and `pnpm test` pass.

## Acceptance Criteria

- [x] Every diagnostic code introduced by milestone 11 has a test that fires it
      and a test that does not.
- [x] A project that does not enable `oop` produces the same manifest and the
      same Lua as before the milestone.
- [x] The suite passes with no skipped tests.
