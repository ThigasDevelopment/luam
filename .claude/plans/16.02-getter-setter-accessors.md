# 16.02 - Expand `@Getter` and `@Setter` into class methods

> File: `.claude/plans/16.02-getter-setter-accessors.md`
> This is the task that makes decorators mean something. The expansion lives in
> the checker's class pass and nowhere else, because the accessor's *name*
> depends on the field's resolved type and only the checker has one.

## Objective

Turn `@Getter` and `@Setter` into real accessor methods on the class, named the
way Java names them — `isEnabled` for a boolean, `getName` for anything else —
typed by the checker and emitted as ordinary Lua.

## Design

### Where the expansion runs, and why there

A boolean field produces `is`, always — including a field typed through an alias
or through an imported declaration:

```lua
type Flag = boolean

class Player {
    @Getter
    admin: Flag
}

player:isAdmin()
```

That rules out a syntactic rule and it rules out a pass that runs before the
checker. Only `resolveAnnotation` follows an alias chain, unwraps an optional,
and consults the ambient and project registries, and it only exists inside a
`CheckContext`.

So the expansion happens in `checker/classes.ts`, inside `registerMembers`, at
the exact point where `fieldType` has already produced the field's `Type`. That
is the earliest moment the correct name is knowable, and it is still early
enough for everything downstream: interface conformance, method bodies, the
emitter, and the LSP symbol index all run after it.

### The generated members are a side table, not an AST rewrite

The pass does **not** splice methods into `statement.members`. It returns them in
a map the check result carries:

```
generatedMembers: ReadonlyMap<ClassDeclaration, ClassMethodDeclaration[]>
```

`emit` and `buildSymbolIndex` each take that map and append the entries for the
class they are visiting, the same way they already take `types` and
`references`. The parse tree stays what the author typed, which is the parser's
whole contract, and a consumer that re-checks a program it already checked — the
LSP does this on workspace load — cannot end up with accessors generated twice
and a phantom `check-decorator-conflict` on the second run. Threading one extra
parameter into two consumers is the cheaper half of that trade.

The generated nodes carry the *field's* position, so go-to-definition on
`player:getName()` lands on `admin: Flag`, and are marked `isSynthetic: true` so
16.3 can keep them out of the document outline.

### The naming rule

`base` is the field name with its first character upper-cased.

| Field | Getter | Setter |
|---|---|---|
| `name: string` | `getName` | `setName` |
| `health: number = 100` | `getHealth` | `setHealth` |
| `admin: boolean` | `isAdmin` | `setAdmin` |
| `admin: Flag` where `type Flag = boolean` | `isAdmin` | `setAdmin` |
| `enabled?: boolean` | `isEnabled` | `setEnabled` |
| `spawned = true` | `isSpawned` | `setSpawned` |
| `isAdmin: boolean` | `isAdmin` | `setAdmin` |
| `island: boolean` | `isIsland` | `setIsland` |

A boolean field whose name already begins with `is` followed by an upper-case
letter keeps the name it has: `isAdmin` produces `isAdmin`, never `isIsAdmin`,
and its setter drops the prefix to `setAdmin`. `island` does not qualify — the
prefix only counts when an upper-case letter follows it. This is Lombok's rule
and it is what the author expects to type.

A field is boolean when its resolved type is `boolean`, after unwrapping
optionality and following aliases. `enabled?: boolean` counts. A union that merely
contains `boolean` does not. `any` does not, so a field with neither annotation
nor default produces `get`.

### The generated signatures

Names come from the resolved type; **signatures reuse the field's annotation
node verbatim**. `admin: Flag` produces:

```lua
isAdmin(): Flag {
    return self.admin
}

setAdmin(value: Flag): void {
    self.admin = value
}
```

The author wrote `Flag`, so the hover says `Flag`. A field with no annotation
produces an accessor with none, which the checker infers exactly as it infers
the field. The setter returns `void`; it does not return `self`, because a
chaining convention is a decision the language has not made.

Accessors are ordered after every authored member, so constructors and methods
stay above compiler-generated entries and fixture snapshots remain stable.

### Diagnostics

All four are stage `checker`, reported from the class pass.

- `check-unknown-decorator` — `@Foo` names a decorator the compiler does not
  have. The message lists the ones it does.
- `check-decorator-target` — `@Getter` or `@Setter` on a method or a
  constructor. Accessors are generated from fields.
- `check-decorator-conflict` — the generated name is already taken, whether by a
  hand-written member or by another field that generates the same name
  (`admin: boolean` and `isAdmin: boolean` both want `isAdmin`). The message
  names the field, the decorator, and the method it would have generated.
  Nothing is generated for that field.
- `check-duplicate-decorator` — the same decorator written twice on one target.
  A class-level decorator overlapping a field-level one is *not* a duplicate; it
  is deduplicated in silence, because that is the ordinary way to say "all
  fields, and this one explicitly".

## Scope

- **In:** The expansion in the checker, class-level and field-level
  `@Getter`/`@Setter`, the type-driven naming rule, the four diagnostics, the
  `generatedMembers` map, and its two consumers.
- **Out:** Editor behaviour (16.3), tests (16.4), any decorator other than these
  two, and accessor visibility — there is no `private` in Luam, so there is
  nothing for a generated accessor to widen.

## Steps

- [ ] Add `checker/decorators.ts` with `expandClassDecorators(context, statement,
      fieldTypes)`, returning the generated members and reporting the four
      diagnostics. A `KNOWN_DECORATORS` map holds the expansions, so a third
      decorator is a new entry rather than a new branch.
- [ ] Add `checker/accessor-names.ts` with the naming rule as a pure function of
      the field name and a boolean flag. It is the one place the rule exists.
- [ ] Add `isBooleanType(type)` to `checker/types.ts`: unwraps optionality,
      follows the alias chain, and answers only for the `boolean` primitive.
- [ ] Add `isSynthetic: boolean` to `ClassMethodDeclaration`, `false` for every
      parsed method.
- [ ] Restructure `registerMembers` in `checker/classes.ts` so field types are
      computed first and kept, then the decorators are expanded against them,
      then every member — authored and generated — is registered in
      `info.members`. Registration order stays declaration order.
- [ ] Collect the authored member names *before* generating anything, so a
      conflict is detected whether the hand-written method sits above or below
      the field.
- [ ] Expand class-level decorators onto every `class-field` member before the
      field-level ones, deduplicating the union. A class decorator never applies
      to a method or to the constructor.
- [ ] Build the accessor bodies as ordinary AST nodes — a `return` of a member
      expression, an assignment to a member expression — never as text.
- [ ] Check the generated method bodies alongside the authored ones in
      `checkClassDeclaration`. They are trivial, and checking them is what proves
      the generated signature and the field agree.
- [ ] Carry `generatedMembers` on the check result, and thread it into
      `emit(...)` and `buildSymbolIndex(...)`. `emitMembers` appends a class's
      generated entries after every authored member.
- [ ] Verify the expansion runs for `.d.luam` files: a declared class with
      `@Getter` contributes the accessor to the ambient surface other modules
      see.

## Acceptance Criteria

- [ ] `@Getter` on `name: string` makes `player:getName()` check as
      `() -> string`, and the generated Lua contains
      `getName = function(self) return self.name end`.
- [ ] `@Setter` on `name: string` makes `player:setName(1)` a
      `check-type-mismatch` and `player:setName('a')` pass.
- [ ] **A field whose type resolves to `boolean` produces `is`, never `get`.**
      That holds for `boolean`, for `enabled?: boolean`, for an alias chain ending in
      `boolean`, for an alias declared in another file, and for a field inferred
      boolean from a `true`/`false` default.
- [ ] Every remaining row of the naming table holds, including `isAdmin`
      producing `isAdmin`/`setAdmin` and `island` producing `isIsland`.
- [ ] The generated signature shows the annotation the author wrote: `admin: Flag`
      hovers as `isAdmin(): Flag`, not `isAdmin(): boolean`.
- [ ] A class-level `@Getter` generates one accessor per field and none for the
      constructor or for methods.
- [ ] A class-level `@Getter` plus a field-level `@Getter` on one of its fields
      generates one accessor and reports nothing.
- [ ] `@Getter` on a field whose class already declares `getName` reports
      `check-decorator-conflict` at the decorator, and no Lua is written.
- [ ] Two fields whose accessors collide report `check-decorator-conflict` once,
      naming both fields.
- [ ] `@Foo` reports `check-unknown-decorator`; `@Getter` on a method reports
      `check-decorator-target`; `@Getter @Getter` on one field reports
      `check-duplicate-decorator`.
- [ ] A generated accessor satisfies an interface member: a class with
      `@Getter name: string` and `implements Named`, where `Named` requires
      `getName(): string`, checks clean.
- [ ] An accessor generated on a parent class resolves on a child instance
      through the existing `extends` chain, with no change to `checker/members`.
- [ ] `self:getName()` inside another method of the same class checks.
- [ ] Checking the same program twice produces the same diagnostics and the same
      generated members — no duplicate accessors, no phantom conflict.
- [ ] Accessors are emitted after authored members, in declaration order, and
      rebuilding an unchanged project produces byte-identical Lua.
- [ ] A class using only decorators still requires exactly the `class` helper,
      and no decorator reaches the generated Lua.
- [ ] A `.d.luam` class with `@Getter` exposes the accessor to a module that
      imports it.
- [ ] `pnpm typecheck`, `pnpm build`, and `pnpm test` pass.
