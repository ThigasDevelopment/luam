# 24.03 - Build a per-reference dependency graph

## Objective

Recheck only files affected by a declaration change and recover from source create, delete, and move events without restarting the language server.

## Context

The cache currently fingerprints all declarations visible to an environment. A shared declaration change can therefore recheck unrelated files even though workspace startup and watched-file handling already discover unopened sources.

## Scope

- **In:** Resolved-symbol provenance, transitive type dependencies, graph lifecycle, semantic invalidation, rescans, benchmarks, and LSP integration.
- **Out:** Cross-project package resolution, persistent caches between editor processes, and speculative parallel checking.

## Steps

### T-01 - Measure the baseline

**Agent:** performance-engineer

- [x] Extend the 300-file and 1200-file fixtures with sparse and dense dependency topologies.
- [x] Record cold analysis, body edit, leaf declaration edit, shared root edit, memory, and published diagnostic counts.

### T-02 - Expose semantic dependencies

**Agent:** architecture-engineer

- [x] Have checking report the declaration owner for every resolved ambient name.
- [x] Include transitive edges through superclass, interface, alias, generic argument, and member types.
- [x] Distinguish body, signature, environment, removal, and ambiguity changes.

### T-03 - Integrate cache and LSP

**Agent:** performance-engineer

- [x] Maintain forward and reverse edges as files change or disappear.
- [x] Invalidate the changed file and reverse transitive closure only.
- [x] Add a full rescan command and reconcile missed watcher events without restarting the server.

### T-04 - Verify correctness and gains

**Agent:** test-engineer

- [x] Cover edge replacement, cycles, deletions, renames, environment visibility, and diagnostics cleared in dependents.
- [x] Compare every incremental result with a clean full analysis.

## Acceptance Criteria

- [x] A body-only edit analyzes and republishes only its file.
- [x] A declaration edit rechecks exactly its semantic reverse closure in test fixtures.
- [x] Incremental diagnostics equal a clean workspace analysis after every tested edit sequence.
- [x] Sparse-project declaration-edit latency improves by at least 20% or the graph is not adopted.
- [x] Memory remains bounded after repeated create/delete cycles.
