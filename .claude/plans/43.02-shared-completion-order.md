# 43.02 - Offer the shared surface first and the sides as complements

> File: `.claude/plans/43.02-shared-completion-order.md`

## Objective

Keep a shared file's completion list reading like a shared file — the shared APIs
as the standard list, the server and client ones appended as complements, each
labelled with the side it comes from.

## Context

Merging the surfaces doubles the list. Without an order and a label, the editor
stops telling the author which names are safe everywhere and which ones commit
the line to a side. The label is what replaces the error 43.01 demoted.

## Scope

- **In:** Completion order and labelling, hover, and the signature help that reads
  the same declarations, in a shared file only.
- **Out:** Any new diagnostic, any change to a `server` or `client` file, and any
  filtering that hides a side-restricted name.

## Steps

- [x] Rank a shared declaration above a side-restricted one in a shared file, so
      the standard surface stays at the top of the list and the sides follow.
- [x] Put the side in the item detail — `client`, `server` — and leave a shared
      item's detail as it is today, so the absence of a badge means "safe on both
      sides".
- [x] Hover a side-restricted API in a shared file with its full signature plus a
      line naming its side and stating that the file must decide the side at
      runtime.
- [x] Keep the completion, hover and signature surfaces reading one source, so an
      API cannot be labelled one way in the list and another way on hover.
- [x] Surface the warning from 43.01 with its own code, so an editor can style it
      apart from a type warning.

## Acceptance Criteria

- [x] In a shared file, typing `trigger` offers `triggerEvent` before
      `triggerClientEvent` and `triggerServerEvent`, and the last two carry their
      side in the detail.
- [x] `localPlayer` is offered in a shared file, marked `client`.
- [x] Hovering `triggerClientEvent` in a shared file shows the signature and the
      side note; in a server file it shows what it shows today.
- [x] A `server` and a `client` file offer exactly the list they offered before,
      in the order they offered it.
