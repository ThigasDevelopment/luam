# 36.05 - Add the community pull request pipeline

## Objective

Give a pull request from a fork a full, honest verification run that needs no
secret and no elevated token, so an outside contributor gets the same signal a
maintainer gets.

## Scope

- **In:** The fork-safe verification workflow, the cache policy for untrusted
  runs, the first-time contributor gate, labelling and triage automation that
  runs without elevation, and the maintainer path for the checks a fork cannot
  run.
- **Out:** Any workflow that publishes, deploys, or writes to the repository
  from a fork context. Those stay on the trusted path and are out of scope by
  the threat model.

## Steps

### T-01 - Build the fork-safe run

**Agent:** github-engineer

- [ ] Add the community pull request workflow, composed from the reusable units
      [36.02](36.02-reusable-workflows.md) extracted, so a fork run and a
      trusted run verify the same thing.
- [ ] Confirm every job it calls runs to completion with `contents: read` and no
      secret, and remove or gate any step that cannot.
- [ ] Use a read-only cache key for untrusted runs, per the cache policy.

### T-02 - Gate and label

**Agent:** github-engineer

- [ ] Require manual approval for a first-time contributor before any workflow
      runs, per the threat model.
- [ ] Add path-based labelling and a size label using the least privilege that
      works, and no write token on the fork-reachable path.
- [ ] Post the outcome so a contributor can act on it without a maintainer
      translating the log.

### T-03 - Route what a fork cannot do

**Agent:** github-engineer

- [ ] Identify the checks that need a token or a secret and cannot run on a
      fork; run them on the merge queue or after the maintainer pulls the branch
      into the repository.
- [ ] Add `CODEOWNERS` so a review is requested from the owner of the touched
      area.
- [ ] Confirm branch protection still lists only checks a fork run can satisfy,
      so an outside pull request is never blocked by a check it cannot execute.

## Acceptance Criteria

- [ ] A pull request from a fork runs typecheck, tests, build and smoke, and
      reports the same pass or fail a branch in the repository would.
- [ ] No job the fork pipeline reaches reads a secret or holds a write token.
- [ ] A fork run cannot write a cache key that a later trusted run reads.
- [ ] A first-time contributor's workflow does not start until a maintainer
      approves it.
- [ ] Every required check is one a fork run can satisfy.
- [ ] `CODEOWNERS` requests review from the right owner for a change in the
      compiler, the CLI, the LSP, the docs, and the workflows.
- [ ] A pull request that is genuinely broken fails from the fork exactly as it
      fails from a branch, verified with a deliberate break.
