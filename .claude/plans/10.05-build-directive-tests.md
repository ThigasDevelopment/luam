# 10.05 - Cover build directives with parser, checker, manifest, and CLI tests

> File: `.claude/plans/10.05-build-directive-tests.md`
> Tests live in each package's `tests/` folder, never beside the source.

## Objective

Prove that a directive changes the manifest and nothing else, that every
diagnostic it defines fires on the form it names, and that an incremental
rebuild does not lose a contribution.

## Scope

- **In:** Parser, checker, emitter, manifest, project-cache, and CLI build
  tests, plus a fixture resource that uses every directive.
- **Out:** Testing MTA itself; the generated manifest is verified against the
  documented element shape, not against a running server.

## Steps

- [x] Parser tests: `export function`, `setting`, and `depends` produce the
      expected nodes; `export`, `setting`, and `depends` as ordinary
      identifiers still parse as identifiers.
- [x] Checker tests, one per diagnostic code: `parse-export-local`,
      `check-export-not-top-level`, `check-export-member`,
      `check-export-in-declaration-file`, `check-setting-value-not-literal`,
      `check-depends-self`.
- [x] Emitter test: the Lua for an exported function is identical to the Lua for
      the same function without the directive, compared string to string rather
      than by snapshot.
- [x] Manifest tests in `packages/compiler/tests/resource.test.ts`: one export
      per environment, a shared export producing two entries, element ordering,
      and XML escaping of a name that needs it.
- [x] Project tests: `project-duplicate-export` across two modules,
      `project-duplicate-setting` with conflicting values, and the same name
      exported once per side being accepted.
- [x] Project-cache test: build, touch nothing, build again — every module is
      reused and the second manifest equals the first.
- [x] Project-cache test: change a file so only its export name changes, and
      confirm the manifest follows.
- [x] Add a fixture resource under `packages/compiler/tests/fixtures` that uses
      all three directives, and snapshot its `meta.xml`.
- [x] CLI test: `luam build` on that fixture writes a `meta.xml` containing the
      export, and `luam check` reports the directive diagnostics.
- [x] Confirm `pnpm typecheck`, `pnpm build`, and `pnpm test` pass.

## Acceptance Criteria

- [x] Every diagnostic code introduced by milestone 10 has a test that fires it
      and a test that does not.
- [x] A project with no directives produces the same manifest snapshot as before
      the milestone.
- [x] The fixture snapshot shows info, scripts, exports, settings, includes,
      files in that order.
- [x] A fully cached rebuild produces an identical manifest.
- [x] The suite passes with no skipped tests.
