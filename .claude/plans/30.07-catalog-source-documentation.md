# 30.07 - Record the catalog source change

## Objective

Write down which source the catalog now comes from, the evidence that overturned
the previous decision, and how the new source is attributed.

## Root Cause

ADR-006 is Accepted and says the catalog is generated from `mtasa-lua-types`,
refreshed by bumping a pin. After this milestone both halves are false. It also
rejected the wiki on a fidelity estimate that measurement contradicts. Leaving
it Accepted would make the authoritative record wrong, and a future reader would
re-derive the same rejected option.

## Scope

- **In:** A new ADR superseding ADR-006, the supersession marker on ADR-006, the
  package attribution, and the roadmap and code-graph updates.
- **Out:** User-facing documentation of individual new functions. The catalog is
  generated; the published reference follows from it.

## Steps

### T-01 - Write the superseding ADR

**Agent:** documentation-engineer

- [ ] Record the context that changed: `mtasa-lua-types` last published
      2023-02-05, `1.1.1` final, 119 functions missing, 24 environments wrong.
- [ ] Record the measurements that overturn ADR-006's rejection of the wiki:
      1383 of 1383 pages carry a parseable Syntax block, 99.0% parsed by an
      untuned prototype, 98.2% arity and 98.1% environment agreement against the
      catalog ADR-006 produced.
- [ ] State the decision precisely: the wiki snapshot is the source, the
      snapshot is committed, the network is confined to a scheduled workflow,
      and generation stays offline.
- [ ] State the consequences honestly, including the new one: the source is now
      first-hand but publicly editable, which is why 30.6 exists.

### T-02 - Mark ADR-006 superseded

**Agent:** documentation-engineer

- [ ] Change its status to Superseded, naming the new ADR.
- [ ] Leave its body intact. The rejected options and their reasoning are the
      record of why this took a measurement to settle.

### T-03 - Restate the attribution

**Agent:** documentation-engineer

- [ ] Update `packages/mta-types/README.md`: the wiki is now the direct source,
      not a source reached through a second-hand package.
- [ ] Determine and record the MTA wiki's content licence as published, and how
      the generated catalog relates to it. ADR-006 was careful to state the
      upstream licence conflict rather than resolve it; the same care applies to
      a source that is now first-hand. **Flag the licence question for the
      maintainer before this milestone ships.**
- [ ] Keep the existing statement that the catalog re-expresses factual API data
      in this project's own descriptor model and carries no upstream source text.

### T-04 - Amend the outbound HTTP rule

**Agent:** documentation-engineer

- [ ] `CLAUDE.md` states that outbound HTTP is allowed "in exactly one place, in
      the `cli`". This milestone adds a second: the `fetch-wiki` dev script and
      the workflow that runs it.
- [ ] Amend the rule to separate the two cases it was always conflating — what a
      shipped build may do, and what a maintainer's tooling may do. The
      invariant the rule exists to protect is unchanged and must be restated
      verbatim: compiler packages make no network call, and a build with no
      network succeeds.
- [ ] Note that dev-time network access already existed through `pnpm install`
      fetching the upstream declarations, as ADR-006 recorded. The change makes
      it explicit rather than introducing it.

### T-05 - Update the project records

**Agent:** documentation-engineer

- [ ] Add the Milestone 30 section to `roadmap.md` and keep every task status in
      step with its plan file.
- [ ] Mark `plans/26.02-catalog-refresh.md` superseded by this
      milestone, since its accepted option was bumping a package that will never
      be published again.
- [ ] Add and update the code-graph nodes each task names.

## Acceptance Criteria

- [ ] ADR-006 reads Superseded and names its replacement.
