# 16.4 — Cover decorators with fixtures, unit, and editor tests

> File: `.claude/plans/16.4-decorator-tests-test-engineer.md`
> The naming rule is a table of cases, and a table of cases is exactly what a
> test suite is good at. The risk this milestone carries is not "does it work"
> but "does it keep working for the odd field name", so the naming table is the
> centre of the suite.

## Objective

Lock the decorator grammar, the accessor naming rule, the generated Lua, and the
editor behaviour behind tests that fail loudly when any of the four drifts.

## Scope

- **In:** Lexer, parser, lowering, checker, emitter, fixture snapshot, LSP, and
  one end-to-end resource build.
- **Out:** Benchmarks. A lowering pass over class declarations is not a
  measurable cost next to checking, and inventing a benchmark for it would only
  create a number nobody acts on.

## Steps

- [ ] Extend `tests/lexer.test.ts`: `@` lexes as punctuation with a position, and
      a stray `@` no longer produces `lex-unexpected-character`.
- [ ] Extend `tests/parser.test.ts`: decorators above a class, above a field,
      above a method, several stacked on one target, `@Getter(true)` reporting
      `parse-decorator-arguments`, a decorator above a `local` reporting
      `parse-unexpected-decorator`, and — the recovery case — a broken decorator
      in the middle of a class body with the members after it still parsed.
- [ ] Add `tests/decorators.test.ts` for the expansion, driven by a table that
      covers every naming row: `name: string`, `health: number = 100`,
      `admin: boolean`, `isAdmin: boolean`, `enabled?: boolean`,
      `spawned = true`, `island: boolean` (a name that merely starts with the
      letters `is`, which must still produce `isIsland`), a single-character
      field `x: number`, and a field with no annotation and no default.
- [ ] Assert the type-driven half of the rule, which is the reason the expansion
      lives in the checker: `admin: Flag` with `type Flag = boolean` produces
      `isAdmin`, an alias chain two deep produces `is`, an alias declared in a
      `.d.luam` and used from another module produces `is`, and an alias
      resolving to `string` produces `get`. A union containing `boolean` and a
      field typed `any` both produce `get`.
- [ ] Cover the four diagnostics with one case each, asserting the code, the
      position lands on the decorator, and the message names the field and the
      method it would have generated.
- [ ] Cover the interactions: class-level applying to every field, class-level
      plus field-level deduplicating, a conflict with a method written *above*
      the field and one written *below* it, and two fields colliding on one name.
- [ ] Assert that checking one program twice yields identical diagnostics and
      identical generated members. This is the regression that the side-table
      design exists to prevent, and it is invisible in a single-pass test.
- [ ] Extend `tests/classes.test.ts`: an accessor inherited from a parent, an
      accessor satisfying an interface member, `self:getName()` inside a sibling
      method, and a setter argument checked against the field's type.
- [ ] Add `tests/fixtures/decorators.luam` exercising the full surface, and lock
      its lexer, parser, checker, and emitter snapshots through
      `tests/fixtures.test.ts`.
- [ ] Extend `tests/emitter.test.ts`: accessor placement after authored members,
      declaration order preserved, only the `class` helper required, and
      no `@` anywhere in the output.
- [ ] Add LSP tests: `@` completion inside a class and its absence outside,
      hover on `@Getter` naming the generated method, `player:` completing
      `getName`, go-to-definition landing on the field, and the outline excluding
      synthetic accessors.
- [ ] Add a grammar test in `packages/vscode/tests/grammar.test.ts` for the
      decorator scopes.
- [ ] Add one integration case to `tests/resource.test.ts`: a project whose class
      uses `@Getter`/`@Setter` builds, writes `class.lua`, and produces Lua that
      a Lua 5.1 parse accepts.

## Acceptance Criteria

- [ ] Every naming row above is asserted by name, both the getter and the setter.
- [ ] Every way a field can be boolean — direct, optional, aliased, aliased
      across files, inferred from a default — is asserted to produce `is`.
- [ ] Each of `check-unknown-decorator`, `check-decorator-target`,
      `check-decorator-conflict`, `check-duplicate-decorator`,
      `parse-unexpected-decorator`, and `parse-decorator-arguments` has a test
      that asserts the code and the position.
- [ ] The fixture snapshots are committed and regenerate byte for byte.
- [ ] A class with no decorators produces snapshots identical to the ones
      committed before this milestone, proving the pass is inert when unused.
- [ ] `pnpm typecheck`, `pnpm build`, and `pnpm test` pass across every package.
