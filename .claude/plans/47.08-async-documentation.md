# 47.08 - Document async, await and the promise runtime

## Objective

Record what the two new words mean, what they cost, and the two boundaries they
cannot cross, so nobody discovers either one from a runtime error.

## Scope

- **In:** The language reference, the diagnostics tables, the runtime library
  page, and the internal design documents.
- **Out:** A migration guide away from `Threads`. Nothing is being removed, and
  47.05 keeps every method working.

## Steps

- [x] Add an Async Functions section to
      [language-design](../docs/language-design.md): the syntax, that the body is
      a coroutine, that `await` returns the value and a rejection raises, and
      that the return annotation is the inner type.
- [x] Update the Reserved Words section there. `async` and `await` are
      contextual, not reserved, and the reason belongs in writing: reserving them
      would have broken `local async = new Async(100)`.
- [x] Document the two boundaries plainly, each with the error the reader will
      otherwise meet:
      - Lua 5.1 cannot yield across a C boundary, so no `await` inside `pcall`,
        `xpcall`, a `table.sort` comparator or a metamethod. Calling an async
        function *from* an MTA event handler is fine — the coroutine is created
        in Lua, so only Lua frames sit between resume and yield.
      - MTA's `setTimer` floor is 50ms, so `delay(0)` and `sleep(0)` resume on the
        next tick rather than the next frame. This is a change from the old
        `sleep(0)`, which yielded to the next pool pulse.
- [x] Add the four new codes to `docs/en/reference/diagnostics.md` and its
      pt-br mirror, and confirm `pnpm docs:verify` passes.
- [x] Update `docs/en/reference/keywords.md` and its mirror for the new `sleep`
      semantics: valid inside an async function and inside a `Threads` job, an
      error anywhere else.
- [x] Document the runtime surface — `new Promise`, `next`, `catch`, `all`,
      `race`, `settle`, `delay` — on the MTA resources page beside `Threads`.
- [x] Write down when to reach for which: a promise for work that waits, a pool
      for work that is long. Include the frame-budget reasoning from 47.05 so the
      choice is defensible rather than stylistic.
- [x] Fix `packages/runtime/README.md`, which still describes `threads` as
      `manual` with no language feature requiring it. It has been `reference`
      since 31.01, and after 47.01 it requires `promise`.
- [x] Add the milestone to [roadmap](../docs/roadmap.md) and move every 47 task's
      status in the same commit as its plan file.

## Acceptance Criteria

- [x] The language reference documents async functions, `await`, and both
      boundaries.
- [x] Reserved Words explains why the two words are contextual.
- [x] All four diagnostic codes appear in both locales and `pnpm docs:verify`
      passes.
- [x] The runtime page documents every new member with the same wording as the
      hover text.
- [x] The stale `manual` claim in the runtime README is gone.
- [x] No documentation still says `sleep` is valid only inside a `Thread`.
