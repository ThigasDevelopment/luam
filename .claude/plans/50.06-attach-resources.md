# 50.06 - Attach and detach resources from the session

## Objective

Give the session its five verbs, so a developer hangs a resource on the watch by
naming it and takes it off the same way.

## The vocabulary

| Verb | Argument | What it does |
|---|---|---|
| `ensure` | one resource name | Builds, syncs, starts it on the server, and watches it |
| `drop` | one attached name | Stops watching and syncing. Touches nothing on the server |
| `rebuild` | optional name | Forces a cycle for one attached resource, or all of them |
| `list` | — | The attached resources, each with its last outcome and age |
| `help` | — | The verbs, and the leading-space escape |

Five names, closed. Each one is a name taken from the MTA console's vocabulary
(50.04), so a sixth needs a reason at least as good as these.

## Scope

- **In:** The five verbs, the attached-resource lifecycle, and the reporting each
  one produces.
- **Out:** A verb for anything the server already does. `refresh`, `start` and
  `stop` reach the console unchanged; the session adds only what the CLI can
  answer and the server cannot.

## What `ensure` does

1. Resolve the name against the discovered resources. Unknown → name the
   workspace root and list what is there, five at most.
2. Already attached → do not build a second watcher. Run `rebuild` for it and say
   so; a developer who types `ensure` twice means "make sure", which is what the
   verb is called.
3. Build and sync through the existing `createEnsureRunner`, with the resource's
   own `ProjectCache`. A build that reports errors syncs nothing, stays attached,
   and keeps watching — the loop's existing contract.
4. On the first successful sync write `refresh` then `start <resource>` to the
   owned console. The resource may be newly deployed, and `start` on a running
   resource is what `stop`/`start` exists to avoid.
5. On every later sync that changed a file, `refresh`, `stop <resource>`,
   `start <resource>` — what `ensure-runner` already does when it holds a console.
   A sync that changed nothing restarts nothing.

## Steps

- [ ] Add a session command table: verb, arity, summary, handler. `help` renders
      it, so the vocabulary is described in one place and cannot drift from what
      is implemented.
- [ ] Implement `ensure` against the steps above, reusing `resourceContext` from
      50.02 and `createEnsureRunner` unchanged. The runner already reports build,
      sync and restart; the session adds only the line naming the resource.
- [ ] Implement `drop`: close the watcher, forget the runner and its cache, keep
      the last outcome for `list`, and say explicitly that what is on the server
      was left alone. A developer who expected `drop` to stop the resource should
      read that it did not, not discover it later.
- [ ] Implement `rebuild`: with a name, force a cycle for that attached resource;
      with none, for every attached resource in attachment order. Unattached name
      → the same error `ensure` gives, plus the suggestion to attach it.
- [ ] Implement `list`: one row per attached resource with the outcome of its last
      build, the file counts the runner already reports, and the age of that
      build. Nothing attached → the same sentence the session prints when it
      opens, so the two agree.
- [ ] Report every verb through the session reporter, not through `stdout`
      directly, so `--no-color` and the plain capability behave as everywhere
      else.
- [ ] A verb with the wrong arity reports its usage line rather than doing
      something approximate. `ensure` with no name lists the resources; `drop`
      with no name lists the attached ones.
- [ ] Guard against a resource whose directory disappears while attached: report
      it, drop it, and keep the session running.

## Acceptance Criteria

- [ ] `ensure resource-a` builds, syncs to
      `<serverPath>/<resourcesDir>/resource-a`, writes `refresh` then
      `start resource-a`, and reports the resource by name.
- [ ] Saving a file in `resource-a` rebuilds, syncs, and writes `refresh`,
      `stop resource-a`, `start resource-a`. A save that changes no output writes
      nothing to the console.
- [ ] A build that fails syncs nothing, writes nothing to the console, keeps the
      resource attached and watching, and leaves the running resource in place.
- [ ] `ensure resource-b` attaches a second resource; saving in either rebuilds
      only that one, and the two reports never interleave.
- [ ] `ensure resource-a` a second time rebuilds instead of attaching twice, and
      one save still produces one rebuild.
- [ ] `drop resource-a` stops rebuilding on save, says the deployed resource was
      left alone, and leaves `resource-b` attached and working.
- [ ] `rebuild` with no argument cycles every attached resource in order;
      `rebuild resource-b` cycles one.
- [ ] `list` reports both resources with their last outcome and age, and reports
      the empty case in the session's own words.
- [ ] `help` lists exactly the five verbs and the leading-space escape.
- [ ] `ensure nope` names the workspace root and lists the discovered resources.
- [ ] `pnpm -r test`, `pnpm typecheck` and `pnpm conventions` pass.
