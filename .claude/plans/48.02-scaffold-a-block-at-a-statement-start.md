# 48.02 - Scaffold a block from its opening keyword

## Objective

Offer the whole block from the word that opens it, so `if|` at a statement start
can complete to a header, an indented body and an `end`, without waiting for the
author to reach `then`.

## Scope

- **In:** Statement-start scaffolds for `if`, `for` in both forms, `while`,
  `repeat`, `do` and `function`, in the file 48.01 created.
- **Out:** `class`, `interface` and `enum`. Their bodies are brace blocks the
  editor already closes, and their members are typed, which makes a frozen
  scaffold worse than the member completion that already exists. Also out:
  `else` and `elseif`.

## Steps

- [ ] Extend `block-completion.ts` with a table of scaffolds, one row per
      opener, each carrying the label, the snippet, and nothing else. Keep the
      file inside the size convention; move the table to
      `block-snippet-table.ts` if it does not fit.
- [ ] Write the snippets to read like the language reference:
      - `if ${1:condition} then` / body / `end`
      - `for ${1:index} = ${2:1}, ${3:10} do` / body / `end`
      - `for ${1:key}, ${2:value} in pairs(${3:items}) do` / body / `end`
      - `while ${1:condition} do` / body / `end`
      - `repeat` / body / `until ${1:condition}`
      - `do` / body / `end`
      - `function ${1:name}(${2})` / body / `end`
      The body line is `    $0` in every one of them, four spaces and the final
      tab stop, so the cursor lands where the first statement goes.
- [ ] Label them `if .. then .. end`, `for .. do .. end`,
      `for .. in .. do .. end`, `while .. do .. end`, `repeat .. until`,
      `do .. end` and `function .. end`, each with `filterText` set to the bare
      keyword so the word being typed still matches.
- [ ] Offer them only where `isStatementStart` from
      [completion-context](../../packages/lsp/src/features/completion-context.ts)
      is true and no argument expectation is in force. A `function` scaffold
      inside a call would be the one defensible exception, and it already has a
      better answer in the event handler scaffold; leave it at statement start
      and record that here rather than discovering it twice.
- [ ] Rank a scaffold below the closers of 48.01 and below the plain keyword, and
      never preselect one. Opening a block is a choice; closing the block you
      just opened is not.
- [ ] Reuse the plain-text fallback from 48.01 for clients without snippets: the
      same block, no tab stops.

## Acceptance Criteria

- [ ] `if`, `for`, `while`, `repeat`, `do` and `function` typed at a statement
      start each offer their scaffold, with tab stops in the order a reader
      would fill them.
- [ ] `for` offers both the numeric and the generic form, as separate rows.
- [ ] No scaffold appears mid-expression, inside a call's arguments, in a type
      position, or after `.` or `:`.
- [ ] No scaffold is preselected, and the plain keyword is still in the list.
- [ ] `pnpm -r test`, `pnpm lint` and `pnpm typecheck` pass.
