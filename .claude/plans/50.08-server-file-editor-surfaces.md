# 50.08 - Give `.luam.server` its editor surfaces

## Objective

Make `.luam.server` look and behave in the editor exactly as `.luam.manifest` and
`.luam.formatter` do: its own language, icon, highlighting, hover, completion and
diagnostics.

## What this costs

Almost nothing, because 50.01 delivered the field table.
[manifest-field-table](../../packages/lsp/src/features/manifest-field-table.ts)
already dispatches on the path:

```ts
export function rootFields(path: string): readonly ManifestField[] {
    return isFormatterPath(path) ? FORMATTER_FIELDS : MANIFEST_FIELDS;
}
```

Hover, completion and the closed-set value lists follow from that one function.
The rest is the extension's declaration: a language id, a grammar, an icon pair
and an activation event.

## Scope

- **In:** The language contribution, grammar, icons, activation, client document
  selector, and the LSP dispatch for the new path.
- **Out:** The schema itself (50.01) and the documentation of the fields (50.10).

## Steps

- [ ] Extend `rootFields` and `fieldAt` to a three-way dispatch. Two `if`s reading
      two predicates is the point where a table keyed by file kind is worth more
      than a chain — the next file of this shape should cost one row.
- [ ] Make `analyzeDocument`
      ([document-analysis](../../packages/lsp/src/analysis/document-analysis.ts))
      recognise a `.luam.server` path and analyse it with `SERVER_SCHEMA`, so its
      diagnostics name the server file and its unknown-field message lists the
      server fields.
- [ ] Add the `luam-server` language to
      [the extension manifest](../../packages/vscode/package.json): filename
      `.luam.server`, the shared `manifest-language-configuration.json`, and an
      icon pair.
- [ ] Add `syntaxes/luam-server.tmLanguage.json` with scope
      `source.luam-server`, following `luam-manifest.tmLanguage.json` and
      highlighting the server file's own field names.
- [ ] Add the icons. Follow the existing `luam-manifest-{light,dark}.svg` pair. If
      no new artwork is available, point the contribution at the manifest icons
      explicitly rather than shipping a path that does not resolve — a missing
      icon is a broken tab, not a missing nicety.
- [ ] Add `workspaceContains:.luam.server` to `activationEvents`, so opening a
      workspace root with no `.luam` file still starts the extension.
- [ ] Add the language to the client's document selector in
      [language-client](../../packages/vscode/src/client/language-client.ts).
- [ ] Check the grammar against the theme contract. The Theme job in CI asserts
      that every scope the grammars emit has a rule; a new scope name that the
      theme does not define fails that gate.
- [ ] Extend the tokenization and file-icon tests to the new language, following
      the formatter's rows in
      [tokenization](../../packages/vscode/tests/tokenization.test.ts) and
      [file-icon](../../packages/vscode/tests/file-icon.test.ts).

## Acceptance Criteria

- [ ] Opening `.luam.server` shows the Luam Server language, its icon, and
      highlighting for strings, numbers, booleans, comments and field names.
- [ ] Hovering `serverPath` shows its summary, its type and that it is required;
      hovering `resourcesDir` shows its default.
- [ ] Completion at the top level offers exactly the server fields, and inside
      `logs` exactly the log fields.
- [ ] An unknown field is underlined with `server-unknown-field` and the message
      lists the server fields, not the manifest fields.
- [ ] The extension activates in a folder that holds a `.luam.server` and no
      `.luam` file.
- [ ] The theme contract job passes with the new scopes.
- [ ] `.luam.manifest` and `.luam.formatter` behave exactly as before.
- [ ] `pnpm -r test`, `pnpm typecheck` and `pnpm conventions` pass.
