# 49.06 - Report an assets mapping that matched nothing

## Objective

Give a glob in `assets` the same voice a literal path already has: when a mapping
copies nothing, say so, instead of finishing the build with `0 errors, 0
warnings` and a resource missing every file the author declared.

## What is actually broken

The glob engine is not. Measured against a project holding `assets/readme.txt`
and `assets/img/logo.png`, every shape resolves correctly and lands in
`meta.xml`:

| `from` | Result |
|---|---|
| `assets/**/*` | both files |
| `assets` | both files |
| `assets/**` | both files |
| `assets/*` | `readme.txt` only, as written |
| `assets/**/*.png` | `logo.png` only |
| `**/*.png` | `logo.png`, kept below `assets/assets/` because the pattern's root is the project |

What is broken is the silence around a mapping that finds nothing.
[asset-resolution](../../packages/cli/src/build/asset-resolution.ts) reports
`config-missing-asset` for a literal `from` that does not exist, and reports
nothing at all for a glob whose directory does not exist:

```
from = 'assets/logo.png'   -> error config-missing-asset: "assets/logo.png" is listed in "assets" but does not exist in "…".
from = 'assets/**/*'       -> Build passed: 1 file, 0 errors, 0 warnings.
```

`listProjectFiles` skips a start directory that is not a directory and returns
no error, so `collect` filters an empty list and the mapping evaporates. From
the terminal, a mapping that copied nothing is indistinguishable from a glob
engine that does not work.

## Scope

- **In:** A `config-empty-asset` warning in `asset-resolution`, and the
  scaffolded manifest, which currently ships a mapping that would trip it.
- **Out:** Changing what the patterns match. The table above is the intended
  behaviour and this task does not move any of it. Also out: the same question
  for `sources`, which 49.03 answers with `config-unmatched-source`.

## Why a warning and not an error

`luam init` writes `assets = { { from = 'assets/**/*', to = 'assets' } }` and
writes no `assets` directory, by design — the scaffold is a manifest and nothing
else. An error would fail the first build of every scaffolded project. A warning
says the true thing without breaking the flow, and the scaffold stops declaring
a mapping it does not create, so a fresh project is clean either way.

## Steps

- [ ] In `collect`, keep the literal branch exactly as it is. For the glob
      branch, count what survives `matchesPattern`.
- [ ] When the count is zero and `tree.errors` produced nothing for that
      mapping, push a `config-empty-asset` warning through `cliWarning`. Two
      cases, one code, wording that distinguishes them:
      - the pattern's root is not a directory — name the root and the project
        root, matching how `config-missing-asset` names them today;
      - the root exists and nothing matched — say the mapping matched no file
        under that root.
- [ ] Never report both `config-empty-asset` and a `config-missing-asset` from
      `tree.errors` for one mapping. An unreadable directory is already reported
      once.
- [ ] Leave `reject` and the collision codes untouched; an empty mapping cannot
      collide.
- [ ] Comment out the `assets` block in
      [the manifest template](../../packages/template/files/luam.manifest) with
      `#`, the manifest's line comment — `--` is `lex-foreign-comment` and would
      break the scaffold. Keep it as the example it already is, so the mapping is
      one uncomment away and the first build of a scaffolded project reports
      nothing.
- [ ] Confirm `luam check` reports the warning too; it shares this resolver, and
      a diagnostic that only `build` prints is half a diagnostic.

## Acceptance Criteria

- [ ] `from = 'assets/**/*'` in a project with no `assets` directory reports one
      `config-empty-asset` warning naming the mapping, and the build still
      passes.
- [ ] `from = 'assets/**/*.jpg'` in a project whose `assets` directory holds no
      `.jpg` reports the same code with the second wording.
- [ ] A mapping that matches at least one file reports nothing, and every row of
      the table above still resolves to exactly what it resolves to today.
- [ ] `from = 'assets/logo.png'` still reports `config-missing-asset` as an
      error.
- [ ] A scaffolded project builds with no warnings, and uncommenting the
      `assets` block after creating the directory copies the files.
- [ ] `warningsAsErrors` turns the new warning into a failure, and nothing else.
- [ ] `pnpm -r test`, `pnpm lint` and `pnpm typecheck` pass.
