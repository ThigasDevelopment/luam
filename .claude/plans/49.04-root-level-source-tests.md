# 49.04 - Cover the root-level layout in the tests

## Objective

Pin the flat layout end to end — discovered, sided by its directive, written into
the resource, watched, and diagnosed when it is not at the root — so a later
change to discovery cannot quietly go back to refusing a one-file resource.

## Scope

- **In:** CLI discovery, build, watcher and diagnostic tests, plus one language
  server test that locks the parity the milestone is built on.
- **Out:** New fixture resources under `examples/`. The existing fixture helpers
  already write a temporary tree, and a flat resource is three files.

## Steps

- [ ] Extend
      [manifest-domains.test.ts](../../packages/cli/tests/manifest-domains.test.ts),
      which already drives `discoverSources` against a fixture tree:
      - `index.luam` at the root, default `sources`, resolves to one file whose
        `environment` is left unset.
      - The same file with `#!client` still arrives unset from discovery; the
        side is the compiler's answer, not discovery's, and asserting it here
        would lock the wrong layer.
      - A root file that a pattern does name keeps its mapped side.
      - `index.test.luam` and a file in an unmatched subdirectory are absent.
- [ ] Add a build-level test beside the cases in
      [build-command.test.ts](../../packages/cli/tests/build-command.test.ts):
      a flat project builds, `meta.xml` declares the script `shared`, and the
      output is `index.lua`. Repeat it with `#!client` and assert both the
      `meta.xml` type and that no `env-path-directive-conflict` warning is
      reported.
- [ ] Cover both output layouts. The mirrored layout writes `index.lua` at the
      resource root; the bundled layout folds the file into the shared bundle.
      Assert the paths, not just the exit code.
- [ ] Cover the watcher: a save to a root `index.luam` schedules a rebuild, a
      write under `outDir` does not, `index.test.luam` does not, and a project
      whose patterns already cover the root opens one watcher.
- [ ] Cover the diagnostics as three separate tests, since they are three
      different states: an unmatched nested file reports
      `config-unmatched-source` naming it, a project with no source reports
      `config-no-sources`, and eight unmatched files name five and count three.
      Keep the assertions on code and content, not on exact punctuation.
- [ ] Update the two `config-no-sources` expectations in
      [check-command.test.ts](../../packages/cli/tests/check-command.test.ts) to
      whichever code that fixture now produces, and say in the test name which
      state is being covered.
- [ ] Cover the assets warning beside the discovery cases, in the suite that
      already drives `resolveAssets`: a glob whose root does not exist warns
      once, a glob whose root exists and matches nothing warns with the other
      wording, a glob that matches reports nothing, and a literal missing
      `from` still errors.
- [ ] Pin the pattern shapes the milestone promises not to change — `assets`,
      `assets/*`, `assets/**`, `assets/**/*`, `assets/**/*.png` and `**/*.png`
      — as one table-driven test over `resolveAssets`, so a later change to the
      matcher has to admit what it moves.
- [ ] Assert that the scaffolded manifest builds with no warnings, which is why
      49.06 comments its `assets` block out.
- [ ] Add one language server test: a document at the workspace root with no
      directive analyses as `shared`, and with `#!server` as `server`. It is the
      parity claim the milestone rests on, and nothing pins it today.

## Acceptance Criteria

- [ ] Discovery, build output, `meta.xml`, the watcher and all three diagnostic
      states each have a named test.
- [ ] Every `assets` pattern shape in the milestone's table has an asserted
      result, and each of the two `config-empty-asset` wordings has its own test.
- [ ] Both output layouts are asserted by path.
- [ ] The language server test locks root-level resolution.
- [ ] `pnpm -r test` passes with no snapshot churn outside the new cases.
