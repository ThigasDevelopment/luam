# 47.01 - Ship a promise runtime with an event-driven scheduler

## Objective

Give the runtime a value that arrives later and a way to suspend the coroutine
waiting for it, so `sleep` stops depending on a `Threads` pool being the thing
that resumes it.

## Scope

- **In:** `promise.lua` — the state machine, `spawn`, `await`, `settle`, `delay`,
  `next`/`catch`, `all`/`race`, the weak task registry, and moving `sleep` onto a
  dispatch. The helper registry entry and its ordering.
- **Out:** The `async` and `await` syntax (47.02), the `Promise` type (47.03),
  folding `Threads` onto this scheduler (47.05), and promise wrappers for
  `fetchRemote`, `dbQuery` or event round-trips.

## Steps

- [x] Write the state machine with a settle guard. `resolve` and `reject` move a
      promise out of `pending` once; a second call returns without re-firing, and
      the handler list is cleared after it fires.
- [x] Store settled values with `n = select('#', ...)` and read them with
      `unpack(values, 1, values.n)`, so a resolve carrying a trailing `nil` keeps
      its arity.
- [x] Wrap the executor. An error thrown inside `new Promise(...)`'s executor
      rejects the promise instead of leaving it pending forever.
- [x] `Promise.spawn(fn, ...)` creates the coroutine, registers it in a
      weak-keyed table (`__mode = 'k'`), resumes it immediately so the body runs
      synchronously up to its first suspension, forwards varargs, and settles the
      returned promise when the coroutine returns or errors.
- [x] Read the result of every `coroutine.resume`. A failed resume rejects the
      task's promise and reports the message. No resume discards its return.
- [x] `Promise.await(p)` returns the settled values on success and raises the
      rejection reason with `error(reason, 0)` on failure. A settled promise
      answers immediately; a pending one appends a waiter and suspends. A
      non-promise argument is returned unchanged.
- [x] The scheduler resumes a waiter with `(ok, ...)`, and `await` unwraps that
      through a helper rather than collecting it into a table, so varargs survive:
      `local function unwrap(ok, ...) if not ok then error((...), 0) end return ... end`,
      called as `return unwrap(coroutine.yield())`.
- [x] `Promise.settle(p)` exposes the same wait without the unwrap, returning
      `(true, ...)` or `(false, reason)`, for callers that want to branch on the
      outcome instead of raising.
- [x] `Promise.await` errors when `coroutine.running()` is nil or the running
      coroutine is not a registered task, rather than returning nil. This is what
      catches an `await` inside a `Threads` job, where the yield would otherwise
      be swallowed by `Threads:process`.
- [x] Resume a waiter only when `coroutine.status(co) == 'suspended'`, behind a
      re-entrancy guard so a settle triggered inside a settle cannot double-resume.
- [x] `Promise.delay(ms)` over `setTimer`, clamped to MTA's 50ms floor.
- [x] `promise:next(fn)` and `promise:catch(fn)`, chainable, for callers that are
      not async functions. `Promise.all`, `Promise.race`, `Promise.resolve`,
      `Promise.reject`.
- [x] Move `sleep` out of `threads.lua` into `promise.lua` and dispatch on
      `coroutine.running()`: a promise task waits on a timer, a `Threads`
      coroutine keeps today's busy-yield unchanged, anything else errors with an
      actionable message.
- [x] Register `promise` in `RUNTIME_HELPERS` declaring `Promise`, `delay` and
      `sleep`; `threads` requires it and declares only `Threads`. `helperDepth`
      then orders the files with no further change.

## Acceptance Criteria

- [x] Settling twice fires handlers once. A second `resolve` or `reject` is a
      no-op.
- [x] `resolve(1, nil)` awaited yields `1, nil`. Arity survives the round trip
      through both the already-settled path and the suspended path.
- [x] An error inside a spawned body rejects its promise and the message reaches
      the debug output. No failure is silent.
- [x] `await` outside a task errors with a message naming the cause, instead of
      returning nil.
- [x] A rejection raises its reason at the `await` site, and that error rejects
      the promise of the async function containing it, so it reaches `:catch()`
      at the end of the chain instead of being lost.
- [x] `Promise.settle` returns `(false, reason)` for the same promise that
      `Promise.await` raises on.
- [x] `sleep` inside a `Threads` job behaves exactly as it does today; inside a
      promise task it waits on a timer and consumes nothing while suspended;
      elsewhere it errors.
- [x] A promise that never settles leaves no strong reference to its coroutine.
- [x] `meta.xml` and the bundle both order `promise.lua` before `threads.lua`
      before `async.lua`.
- [x] A module that declares its own `sleep` still pulls in no helper.

## Deviations

*File length.* `promise.lua` is 395 lines against the 250 the conventions ask
for. The plan scopes one file — the state machine, `spawn`, `await`, `settle`,
`delay`, `next`/`catch`, `all`/`race`, the registries and `sleep` — and
splitting it would either expose `settle` and `create` on the public `Promise`
table for a second file to reach, or duplicate them. `class.lua` (280) and
`threads.lua` (257) already sit above the line for the same reason: a runtime
helper is copied whole into a resource and cannot `require` a sibling.
