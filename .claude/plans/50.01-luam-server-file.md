# 50.01 - Add the `.luam.server` file and its schema

## Objective

Give a directory of resources one file that names the MTA installation they
share, parsed and checked by the machinery `.luam.manifest` already uses, and
found by walking up from wherever a command was run.

## What this reuses

`.luam.formatter` is the same shape and cost almost nothing to build, because
`analyzeManifest` takes a `ManifestSchema`:

```ts
export interface ManifestSchema {
    fields: readonly ManifestField[];
    removed: Readonly<Record<string, string>>;
    normalize(raw, positions): ManifestNormalization;
    retag?(diagnostic): Diagnostic;
    unknownName?(name): string;
}
```

A field table buys the parse, the type check against
[the checker's types](../../packages/compiler/src/checker/types.ts), the closed-set
value check, the unknown-field diagnostic, and — through
[manifest-field-table](../../packages/lsp/src/features/manifest-field-table.ts) —
the editor hover and completion. Nothing in this task writes a parser.

## Scope

- **In:** A `workspace` module in the compiler holding the field table, the
  schema, the analysis entry point and the upward discovery walk. The CLI loader
  that turns a found file into a validated value.
- **Out:** Who calls it (50.02), what happens when a manifest sets the same field
  (50.03), and the editor's language id and grammar (50.08).

## The fields

| Field | Type | Default | Rule |
|---|---|---|---|
| `serverPath` | `string` | — required | none; absolute is allowed, as it is in the manifest today |
| `resourcesDir` | `string` | `'mods/deathmatch/resources'` | `contained-path` |
| `executable` | `string?` | platform probe | `server-contained-path` |
| `logs` | table | `{}` | — |
| `logs.enabled` | `boolean` | `false` | — |
| `logs.maxMessageLength` | `number` | `4096` | `positive-integer` |
| `logs.rateLimit` | `number` | `30` | `positive-integer` |
| `logs.rateWindowMs` | `number` | `1000` | `positive-integer` |

`serverPath` is the only required field, and it is required here where it is
optional in the manifest: a `.luam.server` that does not name a server describes
nothing.

`development.server.executable` flattens to `executable` and `development.logs`
flattens to `logs`. The `development` wrapper exists in the manifest to separate
development behaviour from the resource contract; this whole file is development
deployment, so the wrapper would name the file twice.

## Steps

- [ ] Create `packages/compiler/src/workspace/` with `workspace-fields.ts`
      (`SERVER_FILE_NAME`, `SERVER_FIELDS`, `SERVER_FIELD_NAMES`,
      `isServerFilePath`), mirroring
      [formatter-fields](../../packages/compiler/src/format/formatter-fields.ts).
      Reuse `DEFAULT_RESOURCES_DIR` from `manifest-defaults` rather than restating
      it, so the two files cannot drift.
- [ ] Add `workspace-file.ts` with `SERVER_SCHEMA` and `analyzeServerFile`,
      mirroring [formatter-file](../../packages/compiler/src/format/formatter-file.ts).
      Retag lexer and parser diagnostics to `server-parse-error`, `UNKNOWN_FIELD`
      to `server-unknown-field`, and everything else to `server-invalid-value`.
      `unknownName` lists the known fields, as the formatter's does.
- [ ] Add `workspace-discovery.ts` with `findServerFile(files, start)`, a copy of
      the `findFormatterFile` walk: stop at a `node_modules` segment, stop at the
      filesystem root, return the first `.luam.server` found. Take the same
      injected `FormatterFileSystem`-shaped interface so the walk is testable
      without touching disk; consider lifting that interface to a shared
      `ConfigFileSystem` rather than declaring a second identical one.
- [ ] Add `discoverResources(files, workspaceRoot)`: the direct children of the
      workspace root that hold a `.luam.manifest`, sorted by name. One level, no
      recursion, and no special-casing beyond skipping entries that are not
      directories — a one-level walk cannot reach `node_modules/*/…` anyway.
- [ ] Add `packages/cli/src/config/workspace-loader.ts`: `loadServerFile(path)`
      returning `{ path, source, config, diagnostics }` in the shape
      [manifest-loader](../../packages/cli/src/config/manifest-loader.ts) returns,
      so `reportManifestDiagnostics` renders it with no change.
- [ ] Resolve `serverPath` relative to the directory holding the `.luam.server`,
      not to the working directory. A workspace file is the anchor for its own
      paths; anything else makes `luam dev` mean different things from different
      shells.

## Acceptance Criteria

- [ ] A `.luam.server` holding `serverPath = 'server'` parses, validates, and
      resolves the path against its own directory.
- [ ] A file with no `serverPath` reports a missing-required-field error naming
      the file, not the manifest.
- [ ] An unknown field reports `server-unknown-field` and lists the known fields.
- [ ] A wrong type reports `server-invalid-value` at the field's position.
- [ ] Anything the dialect forbids — a call, a function, a loop — reports
      `server-parse-error`, as it does in a manifest.
- [ ] `findServerFile` walks up from a nested resource directory and finds the
      file at the workspace root; it returns `null` from inside `node_modules`
      and from a tree that holds no such file.
- [ ] `discoverResources` returns the direct children holding a
      `.luam.manifest`, sorted, and ignores files, a child with no manifest, and
      anything nested two levels down.
- [ ] `pnpm -r test`, `pnpm typecheck` and `pnpm conventions` pass.
