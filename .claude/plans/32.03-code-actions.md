# 32.03 - Add code actions, quick fixes and workspace symbols to the LSP

## Objective

Turn a diagnostic into something the editor can act on, and let a developer jump
to any symbol in the project without knowing which file holds it.

## Scope

- **In:** `codeActionProvider` with quick fixes for the diagnostics that have one
  obvious repair, and `workspaceSymbolProvider` over the existing symbol index.
- **Out:** Formatting, which is [32.02](32.02-formatting-provider.md).
- **Out:** Inlay hints. They are not part of milestone 32 at all.
- **Out:** Refactorings that move code between files. There is no import graph to
  move a declaration through.

## Context

`packages/lsp/src/server/capabilities.ts` declares no `codeActionProvider` and no
`workspaceSymbolProvider`. Every diagnostic the checker reports is therefore
read-only: the editor says what is wrong and the developer types the repair by
hand, including the repairs where the message already names the exact fix.

The symbol machinery to answer workspace symbols already exists —
`packages/lsp/src/symbols/symbol-index.ts` backs definition, references and
rename across the workspace. This is a provider over an index that is already
built, not a new index.

Quick fixes have a boundary worth stating: a fix is offered only where the
repair is unambiguous. Offering a plausible-but-wrong edit on a type error is
worse than offering nothing, because the developer accepts it and moves on.

## Steps

### T-01 - Choose the fixable diagnostics

**Agent:** architecture-engineer

- [ ] Walk [diagnostics](../../docs/en/reference/diagnostics.md) and mark every
      code where exactly one repair is correct.
- [ ] Expect the environment and MTA-catalog codes to carry most of them — a
      server-only API in a client file, a misspelled catalog name with one close
      match, a missing `#!` directive.
- [ ] Record the ones deliberately left without a fix, and why, so the list is a
      decision rather than an omission.

### T-02 - Implement the code action provider

**Agent:** architecture-engineer

- [ ] Declare `codeActionProvider` and answer with actions scoped to the
      diagnostics in the requested range.
- [ ] Emit each fix as a workspace edit the editor applies, with the diagnostic
      it resolves attached so the lightbulb points at the right line.
- [ ] Offer no action where the repair is a guess.

### T-03 - Implement workspace symbols

**Agent:** architecture-engineer

- [ ] Declare `workspaceSymbolProvider` and answer from the existing symbol
      index.
- [ ] Return classes, interfaces, enums, type aliases, exported functions and
      top-level declarations, each with its kind and its environment.
- [ ] Answer from the index without recompiling, so the response stays usable on
      a large project.

## Acceptance Criteria

- [ ] Every diagnostic marked fixable in T-01 offers its fix, and applying it
      makes the diagnostic go away.
- [ ] No diagnostic outside that list offers an action.
- [ ] Applying a quick fix produces source that compiles — the fix is verified by
      recompiling the edited file, not by comparing text.
- [ ] Ctrl+T in VS Code finds a class, an interface, an enum and an exported
      function declared in a file that is not open.
- [ ] A workspace symbol result carries the symbol's environment, so a `server`
      and a `client` declaration of the same name are distinguishable.
- [ ] The symbol index is not rebuilt to answer a workspace symbol query.
