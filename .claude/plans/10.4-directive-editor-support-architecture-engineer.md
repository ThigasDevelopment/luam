# 10.4 — Editor support for build directives

> File: `.claude/plans/10.4-directive-editor-support-architecture-engineer.md`
> Can run in parallel with 10.2. It depends on the syntax from 10.1, not on the
> manifest.

## Objective

Make a directive look and behave like part of the language in the editor, so a
misplaced `export` is visible before a build and an exported function reads
differently from a private one.

## Scope

- **In:** TextMate grammar rules, LSP completion, hover text for an exported
  function, the existing diagnostics flowing through unchanged.
- **Out:** Renaming an export across the project, a code action that adds or
  removes a directive.

## Steps

- [x] Add a grammar rule in `packages/vscode/syntaxes/luam.tmLanguage.json`
      matching `export` before `function` and scoping it
      `storage.modifier.luam`, following the existing `class` rule that captures
      the keyword and the name separately.
- [x] Add the same rule for `setting` and `depends` once 10.3 lands, and keep
      all three out of the plain-identifier rule.
- [x] Offer `export` in `packages/lsp/src/features/completion.ts` at statement
      position only, so it does not appear inside an expression.
- [x] Mark an exported function in hover output, so
      `packages/lsp/src/features/hover.ts` shows the export and its side rather
      than only the signature.
- [x] Record the export on `DocumentAnalysis.directives` so a future rename can
      find both the declaration and the manifest entry it produces. It sits
      beside the symbol index rather than inside it: `SymbolDeclaration` is
      built by the collector from AST shape alone, while the export list is the
      checker's own answer, already filtered by the 10.1 diagnostics.
- [x] Confirm the LSP reports the 10.1 diagnostics with no change — they arrive
      through `document-analysis` like every other checker diagnostic.
- [x] Extend `packages/vscode/tests/grammar.test.ts` with a case per directive,
      including `local export = 1` scoped as a variable rather than a keyword.

## Acceptance Criteria

- [x] `export function f() {}` highlights `export` as a modifier and `f` as a
      function name.
- [x] `local export = 1` highlights `export` as a variable.
- [x] Completion offers `export` at the start of a statement and not after
      `local` or inside an argument list.
- [x] Hover on an exported function states that it is exported and on which
      side.
- [x] `export local function f() {}` shows the `parse-export-local` diagnostic
      in the editor at the `export` token.
