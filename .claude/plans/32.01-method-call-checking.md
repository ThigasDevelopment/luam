# 32.01 - Type-check method calls on non-nominal receivers

## Objective

Make `receiver:method(...)` check its arguments when the receiver is an object
type or a native library instance, closing the gap milestone 31 left open and
making the library type surface worth the annotations it carries.

## Scope

- **In:** The non-nominal branch of `checkMethodCall`, the implicit `self`
  parameter, and the types the native libraries publish through
  `LUAM_RUNTIME_GLOBALS`.
- **Out:** The MTA element path. `isMtaElement` and `resolveMtaMember` already
  check what they resolve and must keep behaving exactly as they do.
- **Out:** Inferring a method on a table the checker never saw annotated. A
  receiver that is genuinely `any` stays `any`.

## Context

`checkMethodCall` in `packages/compiler/src/checker/expressions.ts:216` opens by
rejecting everything that is not a nominal type:

```ts
if (receiver.kind !== 'named') {
    checkValueList(context, expression.args);

    return ANY_TYPE;
}
```

`checkValueList` walks the arguments to type the expressions inside them, but it
never compares them against a signature. So a class or an interface — both
`named` — has its method calls checked, and an object type does not. The native
libraries fall on the wrong side of that line: `Threads` and `Async` are typed in
`LUAM_RUNTIME_GLOBALS`, member *access* on an instance resolves, and the call
that follows is unchecked. `task:getInterval()` returns `any`, and passing it
three arguments is silent.

This is the behaviour milestone 31 recorded under "Still open", and it is the one
piece of the language where reading the docs and reading the diagnostics
disagree.

## Steps

### T-01 - Resolve a member on a non-nominal receiver

**Agent:** architecture-engineer

- [ ] Extend member resolution so an object type resolves a method the same way
      `memberOf` resolves one on a nominal type.
- [ ] Keep the nominal path first, so no class or interface changes behaviour.
- [ ] Return `ANY_TYPE` unchanged when the receiver is `any` or resolves to no
      member, so unannotated code compiles exactly as it does today.

### T-02 - Check the signature, accounting for self

**Agent:** architecture-engineer

- [ ] Route a resolved function member through `checkSignature` instead of
      `checkValueList`.
- [ ] Decide and document how the implicit `self` argument is counted, so a
      method declared with an explicit `self` parameter and one declared without
      report the same arity.
- [ ] Confirm `check-argument-count` and `check-argument-type` positions point at
      the offending argument, not at the call.

### T-03 - Type the native library instances

**Agent:** architecture-engineer

- [ ] Give the instance types the libraries publish real method signatures, so
      `Threads` and `Async` instances resolve their methods.
- [ ] Verify a resource that names none of the library globals still ships
      neither file — the trigger is `reference`, and typing must not widen it.

### T-04 - Record the closure

**Agent:** architecture-engineer

- [ ] Remove the "Still open" note from
      [31.01](31.01-native-libraries.md) and from milestone 31 in the roadmap,
      pointing both at this plan.
- [ ] Check whether [limitations](../../docs/en/reference/limitations.md) needs
      an entry for whatever remains unchecked, in both `en` and `pt-br`.

## Acceptance Criteria

- [ ] `obj:method(...)` on an object type checks argument count and argument
      types, and reports the same diagnostics a nominal receiver reports.
- [ ] `task:getInterval()` returns the declared return type, and calling it with
      the wrong arity is a diagnostic.
- [ ] Every existing method-call diagnostic on a class, an interface and an MTA
      element is unchanged — the suite that covered them passes untouched.
- [ ] A receiver typed `any` still produces no diagnostic and still returns
      `any`.
- [ ] A method declared with an explicit `self` and one declared without agree on
      the arity they report.
- [ ] Milestone 31 no longer carries a "Still open" note for this behaviour.
