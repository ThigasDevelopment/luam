# 23.01 - Make `.luam.manifest` a restricted Luam dialect with first-class editor support

## Objective

Replace the ES module manifest with a restricted Luam dialect the compiler parses,
checks, and evaluates in process, so configuration diagnostics carry a position,
the editor offers completion and hover for every field, and the child process and
settings snapshot that existed only to contain JavaScript are deleted.

## Context

[22.1](22.01-luam-manifest-env.md) delivered `.luam.manifest`
as an ES module evaluated in a short-lived child process, with a JSON-only stdout
protocol and a `.luam/settings.json` snapshot so the language server never has to
run project code. That machinery exists for one reason: the file is JavaScript.

It also leaves two things unsolved. Configuration diagnostics have no position,
because `validateConfig` receives a plain object with no provenance — the manifest
is the only file in a Luam project whose errors have no caret. And the editor's
view of `oop` is a snapshot, only as fresh as the last CLI run.

[ADR-015](../docs/adr/015-luam-manifest-language.md) records the replacement: the
manifest becomes a Luam file with most of the language removed, parsed by the
parser that already exists and checked against a record type the type model
already supports. Nothing from 22.1 has been published, so this replaces it inside
the same unreleased cycle.

## Proposed Contract

`.luam.manifest` is a Luam module restricted to two statements — a `local`
declaration and an assignment to a manifest field:

```
local password = env.LUAM_MTA_PASSWORD

name = 'luam-demo'
version = '1.0.0'

sourceDirs = { 'src' }
assetDirs = { 'assets' }
outDir = mode == 'production' and 'build' or 'build-dev'

output = {
    bundle = true,
    map = true,
}

transport = {
    kind = password and 'http' or 'none',
    resource = 'luam-sync',
    username = 'luam',
    passwordEnv = 'LUAM_MTA_PASSWORD',
}
```

A bare assignment declares a field; a `local` is an intermediate value. There is no
`return` and no `#!` directive — the file name is the identity.

The expression language is literals, table constructors, `and`, `or`, `not`,
comparison, arithmetic, concatenation, member and index access, and parentheses.
Calls and function expressions are rejected, which is what makes evaluation pure
and total, and therefore safe in the editor process.

Three values are in scope: `mode` (`development` for `dev` and `ensure`,
`production` for `build`, otherwise the command name), `env` (a table whose members
are `string?`), and `root` (the absolute project root).

## Decisions Required Before Implementation

| Decision | Recommended choice | Rationale |
| --- | --- | --- |
| Field source of truth | One catalog in the compiler | The record descriptor, the validator, completion, hover, and the manual reference all derive from it, so a field cannot be documented as one type and validated as another. |
| Global scope in manifest mode | Closed | Ordinary Luam lets an assignment publish a global. Closing the scope is what turns `outdir = 'build'` into an unknown field with a caret instead of a global nobody reads. |
| Conditional syntax | `a and b or c`, no new expression | The parser has no ternary, the idiom is native Lua, and adding an `if` expression to the language to serve the manifest inverts the dependency. |
| Evaluation host | In process, in both the CLI and the LSP | A pure total expression language has nothing unsafe to contain, so the process wall from 22.1 protects against nothing. |
| Legacy support | Breaking, inside the unreleased cycle | The ESM manifest never shipped. Migrating the repository twice is cheaper than carrying two syntaxes. |

## Scope

- **In:** The manifest dialect, the field catalog, manifest-mode checking, the pure
  evaluator, CLI integration, deletion of the 22.1 evaluator and snapshot channel,
  LSP diagnostics/completion/hover, the VS Code grammar, tests, and EN/PT-BR
  documentation.
- **Out:** Conditional expressions in the language proper, manifest imports or
  includes, generating the reference table from the catalog, searching parent
  directories, merging manifests, and any change to what the fields mean.

## Steps

### T-01 - Specify the language and the field catalog

**Agent:** architecture-engineer

- [x] Record the decision in an ADR: the statement and expression allowlist, the
  `local`-versus-field rule, the injected values, the closed global scope, and the
  diagnostics that are added and removed.
- [ ] Define the field catalog entry shape — name, type descriptor, default,
  required flag, closed value set when it has one, and validation rule — and
  populate it from `config-schema.ts` and `config-validation.ts` without changing
  any field's meaning.
- [ ] Specify the two subset diagnostics: one for a disallowed statement, one for a
  disallowed expression, each naming what is allowed instead.

**Acceptance criteria:**

- [ ] Every field the current validator accepts appears exactly once in the catalog,
  with the same default and the same rule.
- [ ] `name` is the only entry marked required.

### T-02 - Parse and check the manifest dialect

**Agent:** architecture-engineer

- [ ] Add a manifest analysis mode that reuses the existing lexer and parser and
  rejects every statement but `local-statement` and `assignment-statement`, and
  every expression form outside the allowlist, with a position.
- [ ] Build the `Manifest` record descriptor from the catalog and check each
  assignment against its member type, including nested `output`, `transport`, and
  `development.logs` tables.
- [ ] Close the global scope: bind the manifest fields, `mode`, `env`, and `root`,
  and report an assignment to anything else as `config-unknown-field`.
- [ ] Type member access on `env` as `string?` and reject arithmetic on it.
- [ ] Report a missing required field once, at the top of the file.

**Acceptance criteria:**

- [ ] `outdir = 'build'` reports `config-unknown-field` with a caret under `outdir`.
- [ ] `outDir = 5` reports `config-invalid-type` with a caret under `5`.
- [ ] A function declaration, a call, an `if` statement, and a `return` are each
  rejected with a position and a message naming what the manifest allows.
- [ ] A manifest with no `name` reports `config-missing-field` once.
- [ ] An unread `local` is reported as unused, exactly as it is in a source file.

### T-03 - Evaluate the manifest in process and validate it

**Agent:** architecture-engineer

- [ ] Implement a pure evaluator over the checked AST that produces a plain value:
  literals, tables, the boolean operators with Lua truthiness, comparison,
  arithmetic, concatenation, and lookups against the injected values.
- [ ] Derive the semantic validator from the catalog, keeping path safety, resource
  name, helper names, and transport credential resolution unchanged, and attach a
  position to every diagnostic it produces.
- [ ] Keep `LuamConfig` as the validated internal model and `passwordEnv` as the
  only path from an environment variable to a credential.

**Acceptance criteria:**

- [ ] A manifest and its former ESM equivalent produce the same `LuamConfig`, field
  for field.
- [ ] Evaluation terminates on every accepted input, and no accepted input can read
  a file, spawn a process, or reach the network.
- [ ] No diagnostic prints an environment value.

### T-04 - Move the CLI onto the in-process loader

**Agent:** cli-engineer

- [ ] Replace the child-process loader with the in-process one, keeping discovery,
  `--manifest`, and the `mode` each command passes.
- [ ] Delete `manifest-evaluator.ts`, `manifest-evaluator-source.ts`,
  `settings-snapshot.ts`, and the `editor-settings` contract, along with the
  diagnostics that described the evaluator.
- [ ] Render configuration diagnostics through the existing excerpt and caret
  layout rather than as bare messages.
- [ ] Update `luam init` to scaffold the dialect.

**Acceptance criteria:**

- [ ] `init`, `check`, `build`, `dev`, `ensure`, and `trace` resolve the same
  manifest path contract, and no command spawns a process to read it.
- [ ] A configuration error renders with a file, a line, and an excerpt.
- [ ] A newly scaffolded project validates and builds without manual edits.
- [ ] `.luam/` is no longer written.

### T-05 - Teach the language server the manifest

**Agent:** lsp-engineer

- [ ] Analyze `.luam.manifest` documents in manifest mode and publish their
  diagnostics, without the environment checks a source file gets.
- [ ] Read `oop` from the manifest directly and recheck open documents when it
  changes; delete the snapshot reader.
- [ ] Offer **completion** at statement position: every field not already assigned,
  as a property-kind item so the client renders its icon, with the type as detail
  and the default plus rule as documentation. **Required fields sort first and are
  labelled required; optional fields show their default.**
- [ ] Offer completion inside `output`, `transport`, and `development.logs` table
  constructors for that table's members only, under the same required/optional
  rule — `transport.kind` is required once a transport table exists, `host` and
  `port` are not.
- [ ] Offer value completion for closed sets: `transport.kind`, `helpers` entries,
  and booleans, plus `mode` comparisons against the modes that exist.
- [ ] Offer hover on a field: type, default, required or optional, and the rule
  that rejects a bad value.
- [ ] Complete `env.` from the variables the project's `.env` declares, which the
  workspace already reads, marking them `string?`.

**Acceptance criteria:**

- [ ] Completion in an empty manifest offers `name` first, marked required.
- [ ] Completion never offers a field the file already assigns.
- [ ] Completion inside `transport = { }` offers transport members and no top-level
  field.
- [ ] Hovering `outDir` shows `string`, the default `build`, and that it is optional.
- [ ] The server reports a manifest type error as you type, with the same span the
  CLI prints.
- [ ] A malformed manifest degrades `oop` to its default and never crashes the
  server.

## Risks And Mitigations

| Risk | Mitigation |
| --- | --- |
| Manifest mode leaks into ordinary checking, closing the global scope for source files. | Make the mode an explicit input to the analysis entry point, and cover an ordinary file publishing a global in the same test file. |
| The catalog and the checker drift, so completion offers a field the validator rejects. | Derive the record descriptor and the validator from the catalog rather than writing either by hand, and assert the derivation in a test. |
| A pure evaluator grows a call form later and quietly restores the trust boundary. | State the exclusion in the ADR, and assert that a call is rejected in the subset tests, so restoring it is a deliberate ADR change. |
| Removing `.luam/settings.json` regresses the editor for a project that never runs the CLI. | The server now reads the manifest itself, which is strictly fresher; cover a manifest edit changing `oop` with no CLI run. |
| Rewriting every sample twice in one cycle strands a stale snippet. | `pnpm docs:verify` compiles every snippet project and compares captured output, so a stale sample fails the build. |
