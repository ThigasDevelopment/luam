# 8.2 — Build the MTA catalog generator

> File: `.claude/plans/8.2-catalog-generator-architecture-engineer.md`

## Objective

Generate the `mta-types` catalog files from the upstream source with a script,
so a refresh is a command instead of a thousand hand written signatures.

## Scope

- **In:** Generator script, descriptor emission, deterministic output, the
  `generate` package script, generated-file marking.
- **Out:** Normalization rules for ambiguous declarations and the import itself.

## Steps

- [x] Add `packages/mta-types/scripts/generate-catalog.ts` reading the source
      chosen in 8.1.
- [x] Map every upstream signature onto the descriptor model in
      `src/type-descriptor.ts`, including `minimumArguments` from optional
      parameters and `isVariadic` from a trailing rest parameter.
- [x] Emit `mta-shared.ts`, `mta-server.ts`, `mta-client.ts`, `mta-events.ts`,
      and `element-types.ts` in the repository code style: single quotes, four
      spaces, alphabetically sorted, no comments inside code.
- [x] Make the output deterministic so regenerating without a source change
      produces a byte-identical file.
- [x] Mark generated catalogs as generated in the package README and keep the
      handwritten overrides in a separate module.
- [x] Wire `pnpm --filter @luam/mta-types generate` and document it.

## Acceptance Criteria

- [x] Running the generator twice produces no diff.
- [x] Generated files pass `pnpm typecheck` and match the code conventions.
- [x] A malformed or unexpected upstream entry fails the generator with a clear
      message instead of emitting a broken declaration.
- [x] The generator never executes upstream content, it only parses it.
