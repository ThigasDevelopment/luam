# 45.03 - Accept nil assignment as the deletion of a key

> File: `.claude/plans/45.03-nil-assignment-deletes-a-key.md`

## Objective

Let `t[key] = nil` remove an entry from a map or an array, which is the only way
Lua deletes one, without forcing every container's value type to become optional.

## Reproduction

```luam
local map: table<string, number> = { }

map['k'] = 1
map['k'] = nil
# check-type-mismatch: Assignment expects "number" but received "nil".
```

The message offers `number?` as the remedy. Taking it is wrong: it makes every
**read** optional, so a value the code just wrote has to be guarded before use.
The container has no missing values; it has removals.

The ported resource hit this three times: `self.events[requestName] = nil` in the
network module, `self.timers[player] = nil` in the vehicle service, and
`pendingVehicles[index] = nil` over an array.

## Options Considered

| Option | Reads stay non-optional | Catches a real mistake | Decision |
|---|---|---|---|
| Widen every map value to `T?` | No | No | Reject |
| Accept `nil` only when the target is an index expression on a map or an array | Yes | Yes — a field and a plain variable still reject `nil` | Accept |
| Require an explicit `table.remove` / delete helper | Yes | Yes | Reject — it does not exist in Lua 5.1 for a map, and rewriting the source is not the compiler's call |
| Accept `nil` for any assignment target | Yes | No | Reject |

The distinction that makes the accepted row safe is syntactic and narrow: the
target must be `receiver[key]` or `receiver.key` where the receiver's type is a
map or an array. A class field, a record key and a local keep the current rule,
because for those `nil` really is a value the type does not admit.

## Scope

- **In:** `nil` as the right-hand side of an assignment whose target is an index
  on a map or an array, including the compound forms the language allows there.
- **Out:** A record key, a class field, a local, a parameter and a return, all of
  which keep reporting `check-type-mismatch`. Reading a key, which stays
  non-optional. Any change to the emitted Lua.

## Steps

- [x] Add the case to the assignment check: when the target resolves to an index
      on a map or an array and the source type is exactly `nil`, accept it.
- [x] Keep the check for every other target, and keep the existing message and
      its `T?` suggestion there — that suggestion is correct for a field.
- [x] Decide and record what a read after a deletion reports. The recommendation
      is: nothing changes. A map read is already the value type, the language does
      not model presence, and making it optional is the option this plan rejects.
- [x] Invalidate any narrowing fact keyed on a path through the deleted key, the
      way ADR-025 already invalidates on a dynamic index write.
- [x] Assert the emitted Lua is the assignment as written.

## Acceptance Criteria

- [x] The three occurrences from the ported resource compile.
- [x] `local n: number = 1; n = nil` and `self.count = nil` on a `number` field
      still report `check-type-mismatch`.
- [x] A record key set to `nil` still reports, because a record declares its keys.
- [x] A read of a map value is still the value type, unchanged.
- [x] The emitter baseline is byte identical.
