# 51.02 - Restructure the field catalog into sections

## Objective

Give every manifest field a home in one of the five sections, so the catalog that
drives checking, completion, hover and the manual describes the table the author
writes rather than a flat namespace.

## The sections

| Section | Fields |
|---|---|
| `info` | `author` (record: `name` required, extra keys emitted as attributes), `version`, `description`, `dependencies` |
| `environment` | `secret`, `oop`, `strict`, `version.server`, `version.client`, `libraries` |
| `scripts` | ordered list of `{ path, type }` — 51.03 |
| `files` | ordered list of paths — 51.04 |
| `build` | `output`, `details.bundle`, `details.minify`, `details.map` |

`environment` holds four questions deliberately, because all four describe the
environment the resource executes in. The property ADR-017's one-owner rule
protected is kept by other means and this task is where that is implemented:
**cache identity is per field, not per section.** `secret` invalidates
environment loading, `oop` and `strict` invalidate checking, `version`
invalidates only the generated file, and `libraries` invalidates vendoring.
Editing `.env` must not recompile because `strict` shares its table.

## What this task must decide first

**The compiler option vocabulary.** `oop` and `strict` are settled and live in
`environment`. Four options stay manifest fields — that much is decided —
but neither their spelling nor their arrangement is: `noUnusedLocals`,
`noImplicitGlobals`, `noUnusedParameters` and `warningsAsErrors`. The owner's
note is that the language server has more to offer here than a list of booleans,
so the shape waits on what the editor answers (51.09). Until that is written the
four keep their current spelling inside `environment`, and the decision is
recorded in ADR-047 before this task closes.

## Scope

- **In:** `MANIFEST_FIELDS` restructured into sections, per-field cache identity,
  and a stated destination for every field that exists today.
- **Out:** `scripts` (51.03) and `files` (51.04), which are ordered lists with
  their own shape rules.

## Steps

- [ ] Restructure `MANIFEST_FIELDS` into the five sections, keeping `field` and
      `table` as the only two constructors so the catalog stays derivable.
- [ ] Move `engine.minVersion` to `environment.version`, a record of `server` and
      `client`. `'latest'` stays legal in both and keeps the resolution, cache and
      offline fallback from ADR-008.
- [ ] Move `environment.file` to `environment.secret` and delete
      `environment.localFile`. One environment file, named once.
- [ ] Move `compiler.oop` and `compiler.strict` to `environment`, move the
      remaining four per the decision above, and delete the `compiler` table.
- [ ] Move `libraries` into `environment` unchanged.
- [ ] Move `outDir` to `build.output` and `output.*` to `build.details.*`.
- [ ] Turn `info.author` from an optional string into a record with a required
      `name` and an open set of extra string keys, each emitted as an attribute
      and readable at runtime through `getResourceInfo`.
- [ ] Delete `name`. The resource name is the project folder; `build.output` names
      the directory the artifact is written under. Every reader of `config.name` —
      the writer, `ensure`, `dev`, the resource map — takes the folder instead.
- [ ] Delete `development` entirely, along with the log relay it configured. The
      position mapping is what the relay worked around, and removing it also
      removes generated code from the resource.
- [ ] Delete `helpers`, `loadOrder` and `contracts` from the catalog.
- [ ] Move `serverPath`, `resourcesDir` and `development.server` to
      `REMOVED_FIELDS` naming `.luam.server`, completing the deprecation 50.03
      scheduled rather than carrying it forward into a shape it was not written
      for.
- [ ] Rebuild `REMOVED_FIELDS` for every old spelling, each naming its exact new
      path. This table is what 51.08 reads to write the migration.
- [ ] Key each cache on the fields it consumes, and add a test per field asserting
      what it does and does not invalidate.

## Acceptance Criteria

- [ ] Every field readable in a manifest today is readable in the new form at a
      stated path, or is listed in ADR-047 as removed with a reason.
- [ ] `REMOVED_FIELDS` names a replacement for every old spelling, and each entry
      has a test that asserts the message.
- [ ] `info.author = { name = 'x', discord = 'y' }` emits both attributes.
- [ ] `info.author` with no `name` is an error at the record, not at the file.
- [ ] Editing `environment.secret` does not invalidate compilation; editing
      `environment.strict` does; editing `environment.version` invalidates only
      the generated file.
- [ ] A resource with no `name` builds into a directory named after its folder,
      and `ensure` restarts that name.
- [ ] Completion inside `environment = { }` offers only environment fields, and
      hover on any field states its section.
- [ ] The reference table in the manual is generated from the catalog and needs no
      hand edit to match it.
