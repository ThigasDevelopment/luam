# 12.02 - Instrument the build with named phases and progress events

> File: `.claude/plans/12.02-build-phases.md`
> The compiler must stay unaware of terminals. It reports what it is doing; the
> CLI decides how that looks.

## Objective

Turn the build from one opaque call into a sequence of named phases with their
own timings and, where there is a unit to count, their own progress — so the
renderer in 12.3 has something real to draw.

## Scope

- **In:** The phase vocabulary, an optional progress callback through
  `CompileProjectOptions` and the resource writer, per-phase timings on
  `BuildOutcome`.
- **Out:** Any rendering (12.3), colour and symbols (12.1).

## Steps

- [x] Define the phase sequence: discovery, compile, assembly, manifest, write,
      and — for `ensure` — sync and restart.
- [x] Add an optional `onProgress` callback to `CompileProjectOptions`, invoked
      per file as the cache compiles it, carrying the file path, the index, and
      the total. It stays optional, so `compileProject` keeps working untouched.
- [x] Emit the same shape from `writeResource`, where copying assets is the part
      that can actually take time.
- [x] Record a duration per phase on `BuildOutcome` beside the total that is
      already there, so the final report can break the time down.
- [x] Mark which phases have a unit count. Only compile and write do; the rest
      are single steps and must not pretend to have a percentage.
- [x] Keep every callback synchronous. The pipeline is synchronous today and
      this task does not change that — see 12.3 for what it means for painting.
- [x] Confirm no compiler package imports anything from the CLI, and that the
      callback carries data only, never formatting.

## Acceptance Criteria

- [x] `cache.compile(files, { onProgress })` fires once per file, in order, with
      a correct index and total, and the compiled result is unchanged.
- [x] Omitting `onProgress` leaves behaviour and performance identical; the
      benchmark does not regress beyond the margin in
      [performance.md](../docs/performance.md).
- [x] `BuildOutcome` carries a duration per phase, and they sum to within a
      millisecond of the total.
- [x] No file under `packages/compiler` references the CLI or a terminal.
