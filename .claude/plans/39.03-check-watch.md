# 39.03 - Add a watch mode to luam check

## Objective

Give a developer a fast type-checking loop that writes nothing, so working on a
project without a running server does not require a command that produces a
resource.

## Scope

- **In:** `--watch` on `luam check`, reusing the watcher and the incremental
  cache `ensure` already uses.
- **Out:** A new watcher. `packages/cli/src/watch` exists and is what this
  reuses.
- **Out:** Any writing. `luam check` is `luam build` without the writing, and
  watching does not change that.

## Context

`--watch` is owned by `dev` and `ensure`, and both write. `ensure` compiles,
syncs the resource and restarts it; `dev` follows the server log. A developer who
is editing types, has no server running, and wants the checker to re-run on save
has no command that does only that — the options table in
`docs/en/tooling/cli.md` lists `--watch` under `dev` and `ensure` only, and
passing it to `check` exits `2`.

The gap is small but it is on the path a developer walks most: the tightest loop
the toolchain offers currently has a side effect on disk.

Everything needed exists. `packages/cli/src/watch` holds the watcher `ensure`
drives, `packages/compiler/src/project/project-cache.ts` holds the incremental
cache, and `check-command.ts` already builds the same project inputs `build` does
and stops before the writing.

## Design

`luam check --watch` runs one check, then re-runs on change, printing a
separator between runs the way `ensure` does through
`packages/cli/src/reporting/rebuild-separator.ts`. It never writes, never
resolves the MTA release, and never touches the output directory.

The watched set is the manifest's `sources` patterns plus the manifest itself. A
manifest change re-reads the configuration, because a change to `sources` changes
what is watched. Library sources from [38.01](38.01-libraries-manifest-domain.md)
are watched if they resolve to a workspace link and are not if they resolve
inside `node_modules` — decide in T-01, and prefer not watching `node_modules`,
which is a large tree that changes only on install.

Exit behaviour: a watch runs until interrupted, so the exit code reflects
termination, not the last check. That matches `ensure` and needs no new rule,
but T-01 should confirm it rather than inherit it silently — a script that runs
`check --watch` expecting a build's exit code is a mistake worth making
impossible to make quietly, and `--no-watch` is already the explicit single-shot
form.

## Steps

### T-01 - Decide the watched set and the exit contract

**Agent:** architecture-engineer

- [ ] Confirm the watched set: manifest, `sources` patterns, `.d.luam` files.
- [ ] Decide whether library sources are watched, per resolution kind.
- [ ] Confirm the exit contract matches `ensure`, and that `--no-watch` remains
      the single-shot form.

### T-02 - Register and implement

**Agent:** architecture-engineer

**Files:** `packages/cli/src/cli/registry/check-registration.ts`,
`packages/cli/src/commands/check-command.ts`

- [ ] Add `--watch` / `--no-watch` to the `check` registration, defaulting to
      off — unlike `dev` and `ensure`, whose watch is the point.
- [ ] Drive the existing watcher, reusing the incremental cache.
- [ ] Print the rebuild separator between runs, matching `ensure`.
- [ ] Confirm nothing is written, no release lookup runs, and the output
      directory is untouched.

### T-03 - Update the options table

**Agent:** architecture-engineer

- [ ] Move `--watch` in `docs/*/tooling/cli.md` from "owned by `dev`, `ensure`"
      to include `check`, and state that `check` defaults to off while the other
      two default to on.

## Acceptance Criteria

- [ ] `luam check --watch` re-runs on a source change and prints a separator
      between runs.
- [ ] It writes nothing, in any layout, proven against a directory snapshot taken
      before and after several rebuilds.
- [ ] It performs no release lookup, so it works offline with no flag.
- [ ] A manifest change re-reads the configuration and re-derives the watched set.
- [ ] `luam check` with no flag behaves exactly as it does today.
- [ ] The options table lists the new ownership and the differing default.

## Out of Scope

- A new watcher or a new cache.
- Writing anything.
- `--json` interaction, which is [39.02](39.02-machine-readable-diagnostics.md)
  T-01's decision.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The command writes something through a shared code path with `build` | High | Directory snapshot asserted across rebuilds, not just after one |
| Watching `node_modules` makes the loop slow | Medium | T-01 decides against it by default |
| A script reads the exit code of a watch and misinterprets it | Medium | T-01 confirms the contract and the docs state it |
