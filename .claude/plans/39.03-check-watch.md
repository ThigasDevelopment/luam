# 39.03 - Add a watch mode to luam check

## Objective

Give a developer a fast type-checking loop that writes nothing, so working on a
project without a running server does not require a command that produces a
resource.

## Scope

- **In:** `--watch` on `luam check`, reusing the watcher and the incremental
  cache `ensure` already uses.
- **Out:** A new watcher. `packages/cli/src/watch` exists and is what this
  reuses.
- **Out:** Any writing. `luam check` is `luam build` without the writing, and
  watching does not change that.

## Context

`--watch` is owned by `dev` and `ensure`, and both write. `ensure` compiles,
syncs the resource and restarts it; `dev` follows the server log. A developer who
is editing types, has no server running, and wants the checker to re-run on save
has no command that does only that — the options table in
`docs/en/tooling/cli.md` lists `--watch` under `dev` and `ensure` only, and
passing it to `check` exits `2`.

The gap is small but it is on the path a developer walks most: the tightest loop
the toolchain offers currently has a side effect on disk.

Everything needed exists. `packages/cli/src/watch` holds the watcher `ensure`
drives, `packages/compiler/src/project/project-cache.ts` holds the incremental
cache, and `check-command.ts` already builds the same project inputs `build` does
and stops before the writing.

## Design

`luam check --watch` runs one check, then re-runs on change, printing a
separator between runs the way `ensure` does through
`packages/cli/src/reporting/rebuild-separator.ts`. It never writes, never
resolves the MTA release, and never touches the output directory.

The watched set is the manifest's `sources` patterns plus the manifest itself. A
manifest change re-reads the configuration, because a change to `sources` changes
what is watched. Library sources from [38.01](38.01-libraries-manifest-domain.md)
are watched if they resolve to a workspace link and are not if they resolve
inside `node_modules` — decide in T-01, and prefer not watching `node_modules`,
which is a large tree that changes only on install.

Exit behaviour: a watch runs until interrupted, so the exit code reflects
termination, not the last check. That matches `ensure` and needs no new rule,
but T-01 should confirm it rather than inherit it silently — a script that runs
`check --watch` expecting a build's exit code is a mistake worth making
impossible to make quietly, and `--no-watch` is already the explicit single-shot
form.

## Record

### T-01 - The watched set and the exit contract

- **The watched set is the manifest's `sources` roots plus `.luam.manifest`
  itself.** The source half reuses `watchSources` unchanged, which already
  filters to `.luam` files the resolver matches — so a `.d.luam` file inside a
  source root is watched, and one outside it is not, exactly as `ensure` behaves.
  The manifest half is a new `watchManifest`, watching the manifest file itself
  rather than its directory: watching the project root turned out to trip a libuv
  assertion under a short-name temp path, and the file watch is both narrower and
  robust.
- **Library sources are never watched.** `node_modules` is in
  `EXCLUDED_DIRECTORIES` and `watchSources` only opens the resolver's roots, so a
  library resolved into `node_modules` is outside the watch by construction. A
  large tree that changes only on install is not worth a recursive watcher.
- **The exit contract matches `ensure`:** a watch runs until interrupted and
  returns `EXIT_OK` on termination, not the verdict of the last check. `check`
  without `--watch` remains the single-shot form and keeps today's exit codes
  exactly; `--no-watch` states it explicitly. The docs say so in both trees, so a
  script that wants a verdict is told which form gives one.
- **`check` defaults to not watching**, unlike `dev` and `ensure`, whose watch is
  the point.

### T-02 - What was built

- `runCheckCommand(context, cache?)` gained an optional incremental cache and is
  otherwise unchanged; every existing caller and test still passes it nothing.
- `runCheckWatch(context, options)` runs one check, opens the watchers, and
  re-checks on change behind the same running/queued guard `ensure` uses, printing
  `reportRebuildSeparator` between runs.
- A manifest change calls `options.reload()`, supplied by the registration, which
  re-reads and re-validates through `loadManifest` and reports its diagnostics. An
  invalid manifest keeps the previous configuration and says so rather than
  stopping the watch. A valid one replaces the configuration, discards the
  incremental cache, reopens the source watcher on the new roots, re-checks, and
  re-announces what is being watched.
- `untilAborted` moved from `ensure-command.ts` to `@cli/watch/abort-wait` and is
  now shared by both loops rather than copied.
- Nothing writes: `runCompile` is called without a writer, and the tests assert a
  full directory snapshot of the project root is unchanged across three
  re-checks. No release lookup runs, so the loop is offline with no flag.

### On running the watch tests locally

On the maintainer's Windows checkout the vitest workers that watch files abort
with `Assertion failed: !_wcsnicmp(filename, dir, dirlen)` — a libuv fault on the
8.3 short name in `os.tmpdir()`. It predates this task; `ensure-command.test.ts`
aborts the same way. Running the suite with the long temp path
(`TEMP=C:\Users\<user>\AppData\Local\Temp`) makes all 41 files pass.
