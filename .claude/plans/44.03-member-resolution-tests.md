# 44.03 - Test member resolution against name collisions

> File: `.claude/plans/44.03-member-resolution-tests.md`

## Objective

Lock the reported case and the narrowing it depends on, in the editor and in the
compiler.

## Scope

- **In:** LSP fixtures for hover, definition, references and rename under a name
  collision, and a compiler fixture for the optional-field guard.
- **Out:** Benchmarks and VS Code end-to-end automation.

## Steps

- [ ] Add the reproduction from 44.01 as a fixture, asserting hover, definition
      and rename on `props.secret` and on `self.secret`.
- [ ] Add fixtures where the receiver is a class instance, an MTA element, a
      library and a table literal, each with a colliding class field in the file.
- [ ] Add a compiler fixture for
      `if props.password and type(props.password) == "string" then self.password = props.password end`
      asserting no diagnostic, and a negative one without the guard asserting the
      assignment diagnostic.
- [ ] Assert the CLI and the LSP agree on every fixture.

## Acceptance Criteria

- [ ] Every assertion above has a test, and the ones covering the defect fail
      against the current tree.
- [ ] The hover, navigation and access-path suites pass untouched.
