# 15.01 - Write ensure output only to the MTA server

> File: `.claude/plans/15.01-ensure-server-only.md`

## Objective

Make `luam ensure` materialize each successful build only at
`<serverPath>/<resourcesDir>/<name>`, so its initial run and watch rebuilds never
write generated files into the developer's project output directory.

## Scope

- **In:** Command-specific output targets, the `serverPath` precondition,
  `EnsureResult`, ensure reporting, watch behavior, CLI tests, and public command
  documentation.
- **Out:** Changes to compilation, incremental caching, source watching,
  restart transport behavior, `outDir` semantics for `luam build`, and temporary
  or atomic deployment directories.

## Options Considered

| Option | Correctness | Maintainability | Developer experience | Decision |
|---|---|---|---|---|
| Keep writing to `outDir` and then sync to the server | Produces the right server resource but keeps the unwanted duplicate write | Keeps the current coupling | Continues modifying the developer's project on every rebuild | Reject |
| Write to `outDir` only for the initial ensure run | Leaves watch rebuilds cleaner but makes command behavior depend on timing | Adds a special case that is easy to regress | The first run still modifies the project | Reject |
| Give `build` and `ensure` separate target resolvers | Each command can write only to its intended destination | Makes the command boundary explicit and testable | `build` remains predictable; `ensure` touches only the server | Accept |

## Behavior Contract

| Command | `serverPath` | Filesystem destination | Result |
|---|---|---|---|
| `luam build` | absent or present | `<root>/<outDir>/<name>` only | Existing behavior |
| `luam ensure` | present | `<serverPath>/<resourcesDir>/<name>` only | Build, sync, and conditionally restart |
| `luam ensure` | absent | None | Report a command diagnostic and do not start watch mode |

An existing `<root>/<outDir>/<name>` directory is outside `ensure` ownership.
`ensure` must neither create, update, prune, nor delete it.

## Steps

- [x] Replace the combined `resolveTargets` contract in
      `packages/cli/src/commands/resource-targets.ts` with command-specific
      build and server target resolvers. Keep relative and absolute
      `serverPath` resolution unchanged.
- [x] Update `runBuildCommand` to request only the build target and preserve its
      current `outDir` write, pruning, diagnostics, and reporting behavior.
- [x] Update `createEnsureRunner` and `runOnce` to request only the server target
      and call `writeResource` once per successful cycle. Remove the `write`
      phase and local `Wrote ... to outDir` message from ensure; retain the
      server `sync` phase and restart only when that write changed files.
- [x] Remove the now-unused `EnsureResult.output` field and keep the server write
      result in `EnsureResult.sync`. Do not add a compatibility alias because the
      type is an internal CLI runner contract with no current consumers.
- [x] Validate the `serverPath` precondition before compilation and before the
      watcher is installed. Report that `luam ensure` requires `serverPath`,
      return a diagnostic exit code, and leave both `outDir` and transport
      untouched.
- [x] Update ensure runner tests to assert that the first run and watched
      rebuilds create or update the server resource without creating `build`.
- [x] Add a regression test that places sentinel files in the configured
      `outDir`, runs multiple ensure cycles including a stale server-file prune,
      and verifies every local output file remains byte-identical.
- [x] Add coverage for missing `serverPath`, absolute `serverPath`, custom
      `resourcesDir`, and custom `outDir`; verify the first three affect only the
      server destination and the last one is ignored by ensure.
- [x] Keep build-command tests proving that `luam build` still writes and prunes
      `<root>/<outDir>/<name>` and never writes to `serverPath`.
- [x] Update CLI output snapshots, README command documentation, roadmap results,
      and the `cli-ensure-runner`/`cli-resource-targets` code-graph descriptions
      after implementation.
- [x] Run `pnpm --filter @luam/cli typecheck`,
      `pnpm --filter @luam/cli test`, and the workspace `pnpm typecheck`.

## Acceptance Criteria

- [x] A successful `luam ensure --no-watch` writes generated resource files only
      under `<serverPath>/<resourcesDir>/<name>`.
- [x] Every successful watched rebuild writes and prunes only the server resource
      directory; `<root>/<outDir>/<name>` remains unchanged even when it already
      exists.
- [x] `luam ensure` without `serverPath` writes no generated files, invokes no
      transport operation, installs no watcher, and exits with diagnostics.
- [x] A failed compilation leaves the previously synced server resource and the
      local output directory untouched.
- [x] An unchanged server resource does not trigger `refresh` or `restart`; a
      changed server resource preserves the existing restart sequence.
- [x] `luam build` retains its current `outDir` behavior regardless of whether
      `serverPath` is configured.
- [x] CLI type checking and tests pass.
