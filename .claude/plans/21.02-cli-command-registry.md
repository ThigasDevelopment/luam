# 21.02 - Rebuild CLI registration and command boundaries

> File: `.claude/plans/21.02-cli-command-registry.md`

## Objective

Replace the global hand-written argument parser and dispatcher with declarative,
testable command modules while preserving all existing Luam operations.

## Scope

- **In:** Commander setup, a minimal executable entrypoint, declarative command
  registration, per-command validation, shared command context, and migration
  of existing command handlers.
- **Out:** New end-user commands, changes to config schema, changed transport
  behavior, or a rewrite of compiler resource assembly.

## Steps

- [x] Add and lock the selected parser dependency in `packages/cli`.
- [x] Keep `index.ts` limited to the Node shebang, invocation of the CLI program,
      and assignment of the returned exit code.
- [x] Add one root program module that owns package name, version, global output
      capability, global options, and registration of a declarative command list.
- [x] Move each command into a command-local module that defines its syntax and
      translates parsed options to the existing command implementation.
- [x] Introduce a shared context factory for root resolution, config loading,
      logger, reporter, environment, cancellation, editor services, and MTA
      transport injection used by tests.
- [x] Preserve stdout for reports and stderr for progress, warnings, diagnostics,
      and interactive rendering.
- [x] Preserve non-interactive operation; prompts are allowed only in `init` and
      `setup`, and cancellation returns a controlled exit result.
- [x] Remove the old parser and central conditional dispatch only after every
      command has been migrated and covered by compatibility tests.

## Acceptance Criteria

- [x] `luam --help` and `luam <command> --help` expose the documented command
      contract.
- [x] Unknown commands, unknown options, missing option values, invalid operands,
      and incompatible command options return exit code `2`.
- [x] `build`, `check`, `ensure`, `dev`, `trace`, `init`, `setup`, and `doctor`
      retain their current observable behavior when invoked with valid options.
- [x] No command calls `process.exit()` outside the executable boundary.
- [x] `NO_COLOR`, `--no-color`, redirected streams, and injected logger tests
      retain plain and deterministic output.
