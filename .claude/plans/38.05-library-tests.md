# 38.05 - Cover milestone 38 with a real library fixture

## Objective

Prove the library model end to end against an actual package, so the milestone is
verified by a resource that builds and starts rather than by unit tests over each
half.

## Scope

- **In:** A fixture library package, a fixture consumer project, and coverage of
  resolution, compilation, collisions, requirements, both output layouts and the
  network invariant.
- **Out:** Publishing anything to npm. The fixture is a workspace package; the
  registry path is asserted by the resolution rules, not by a live install.

## Context

Every previous milestone that touched output was verified by compiling a real
project and reading what it produced. This one needs the same, because the
failure modes are structural: a symbol that goes invisible, an order that
disagrees with the compile, output that ships after a library is removed. None of
those show up in a unit test over one function.

The fixture library must exercise the shapes the model claims to support: `.luam`
compiled from source, verbatim `.lua` with a `.d.luam` beside it, more than one
environment, a class the consumer extends, a runtime helper the library triggers
and the project does not, and a `requires` entry.

38.01 T-01 decides whether a workspace link resolves. This task depends on that
answer, and if it is no, the fixture has to be installed some other way — which
would itself be a finding worth recording rather than working around quietly.

## Steps

### T-01 - Build the fixture

**Agent:** test-engineer

- [ ] Create a fixture library package with a `luam` field declaring `shared` and
      `client` sources.
- [ ] Include a class the consumer extends, a function the consumer calls, a
      verbatim `.lua` with a `.d.luam` beside it, and a construct that triggers a
      runtime helper the consumer does not use.
- [ ] Give it a `requires` entry naming a second fixture package.
- [ ] Create the consumer project that lists both.

### T-02 - Resolution and configuration

**Agent:** test-engineer

- [ ] A listed, installed package resolves. A listed, missing one reports
      `config-library-missing` and writes nothing.
- [ ] An installed package absent from `libraries` is not compiled.
- [ ] A malformed `luam` field, a duplicate entry and an escaping pattern each
      report their code.
- [ ] A scoped name resolves and flattens as 38.04 T-01 decided.

### T-03 - Compilation and visibility

**Agent:** test-engineer

- [ ] The consumer extends the library's class and the build succeeds.
- [ ] A call into a library function is checked; a wrong argument reports.
- [ ] A deliberate type error inside the library fails the consumer's build, with
      a path naming the package.
- [ ] A `server` library symbol used from a client file reports the existing
      environment diagnostic.
- [ ] A library file referencing a project global fails, per 38.02 T-01.
- [ ] The library `.d.luam` supplies types and emits nothing.

### T-04 - Collisions and requirements

**Agent:** test-engineer

- [ ] Two fixture libraries claiming one name on one side report
      `project-library-collision`; on sides that never meet, they report nothing.
- [ ] A library colliding with a project file reports, with the message reading
      as the library intruding.
- [ ] An unlisted requirement reports `config-library-requirement-missing`;
      listing it clears the diagnostic.
- [ ] The MTA-shadowing case behaves as 38.03 T-01 decided.

### T-05 - Output

**Agent:** test-engineer

- [ ] Tree output snapshot: `libs/<package>/<environment>/`, the enumerated
      `<script>` entries, and their position relative to helpers, `config.lua`,
      `loadOrder` and the wildcards.
- [ ] Bundle output snapshot: library modules ahead of project modules.
- [ ] The helper the library triggers is emitted once and first.
- [ ] Removing the library from the manifest removes its output on the next
      build; renaming it moves it.
- [ ] The generated resource starts in the smoke build.

### T-06 - Invariants

**Agent:** test-engineer

- [ ] A build with `node_modules` populated and no network succeeds and is
      byte-identical to a networked one.
- [ ] A project with an empty `libraries` list produces byte-identical output to
      the pre-milestone build, proven against a recorded baseline.
- [ ] The suite passes on Node 22 and Node 24.

## Acceptance Criteria

- [ ] Every acceptance criterion in 38.01 through 38.04 has a test that fails
      when the behaviour is reverted.
- [ ] The fixture consumer builds, and its resource starts.
- [ ] The no-libraries baseline is unchanged, byte for byte.
- [ ] No test reaches the network.

## Out of Scope

- Publishing to npm.
- Benchmarking the added resolution and compile cost. If it is measurable, it is
  a performance task, not a test task.
