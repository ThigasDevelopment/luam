# 51.03 - Replace `sources` and `loadOrder` with an ordered `scripts` list

## Objective

Make the order a resource loads in the order it is written, by folding discovery,
classification and load order into one ordered list where each entry declares its
own side.

## The shape

```luam
scripts = {
    { path = 'config.lua', type = 'shared' },

    { path = 'src/index.luam', type = 'server' },

    { path = 'src/server/**/*.luam', type = 'server' },
    { path = 'src/client/**/*.luam', type = 'client' },
}
```

`path` is a literal file, a `*` pattern or a `**` pattern, under the grammar
ADR-017 fixed — `*`, `**`, `?`, `/` as the separator, no regex, no negation, no
braces, no absolute path, no `..`. `type` is `server`, `client` or `shared`.

## Why the side is declared and not inferred

`sources` says where to look and `environmentRoot` recovers the side afterwards
by walking for the literal segments `src/server`, `src/client` and `src/shared`.
A resource that puts its utilities in `src/utils` gets every file classified
`shared`, silently, and with it the wrong MTA API surface. The side is the
question that decides what the checker allows; it belongs on the entry.

## Scope

- **In:** The entry shape, matching, ordering, the diagnostics, and the removal
  of `sources`, `loadOrder` and the path-sniffing classifier.
- **Out:** How an entry becomes a `<script>` element (51.06), and the blank line
  between entries (51.05).

## Steps

- [ ] Replace `SourceMapping` with an ordered `ScriptEntry[]`, and make source
      discovery walk it in order, assigning each matched file the entry's `type`.
- [ ] Delete `environmentRoot` as a classifier. A file's side comes from the
      entry that matched it; a `#!server`, `#!client` or `#!shared` directive
      stays a per-file override and keeps the existing disagreement warning.
- [ ] Report `config-script-side-conflict` when one file is matched by two
      entries of different sides, naming the file and both entries with their
      positions. Two entries of the same side matching one file is the same code:
      the file would be emitted twice and loaded twice.
- [ ] Report `config-missing-script` for a literal path that does not exist, and
      `config-empty-script-entry` for a pattern that matched nothing — the shape
      49.06 established for an empty asset mapping.
- [ ] Report `config-no-scripts` when the whole list matched nothing.
- [ ] Keep a `.lua` path legal in `scripts`. A native `config.lua` is copied
      verbatim under ADR-022 and ADR-036 and is a script in the generated file, so
      the list is the one place both kinds of script are ordered against each
      other.
- [ ] Make `scripts` invalidate discovery, and each file's assigned side join the
      declaration and module cache keys, per ADR-017's per-domain identity.

## Acceptance Criteria

- [ ] The eight interleaved blocks of the `heaven-roleplay` fixture produce
      `<script>` elements in exactly that order.
- [ ] Moving an entry up in the list moves its element up and changes nothing
      else in the generated file.
- [ ] A file under `src/utils/` typed `client` by its entry resolves client APIs
      and reports a server-only API, with no reference to its directory.
- [ ] One file matched by two entries reports `config-script-side-conflict` with
      both entry positions.
- [ ] A literal path that does not exist fails the build before anything is
      written, naming the entry.
- [ ] A `.lua` entry is copied verbatim, is never checked, and appears in the
      generated file at its position in the list.
- [ ] `sources` and `loadOrder` are in `REMOVED_FIELDS` and each names its
      replacement.
