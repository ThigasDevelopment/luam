# 25.1 - Evolve `.luam.manifest` into the complete project contract

## Objective

Turn `.luam.manifest` into one typed, editor-aware contract for compilation,
source-side discovery, assets, resource dependencies, engine requirements, output,
development, and deployment without turning it into an executable build script.

## Context

The manifest already owns resource identity, source and asset directories, output,
runtime helpers, OOP, development logs, and transport. The fields work, but their
flat organization does not establish durable ownership boundaries. Compiler behavior
sits beside deployment behavior, `sourceDirs` discovers files while the compiler
hard-codes `src/server`, `src/client`, and `src/shared`, and `assetDirs` cannot map an
individual file or glob to a different output path.

The restricted manifest dialect from [23.1](23.1-luam-manifest-language-architecture-engineer.md)
already gives Luam a safe foundation: typed fields, pure expressions, nested tables,
positioned diagnostics, completion, and hover. This plan uses that foundation to
make the manifest powerful through declarative domains. It does not add calls,
plugins, hooks, arbitrary Lua, or another configuration file.

## Proposed Contract

```lua
name = 'luam-resource'
author = 'Luam Team'
version = '1.0.0'
description = 'A typed MTA resource.'

compilerOptions = {
    strict = true,
    oop = true,
    noUnusedLocals = true,
    noUnusedParameters = false,
    warningsAsErrors = false,
}

sources = {
    server = {
        'src/server/**/*.luam',
        'src/jobs/**/*.luam',
        'src/bootstrap.luam',
    },
    client = {
        'src/client/**/*.luam',
        'src/ui/**/*.luam',
    },
    shared = {
        'src/shared/**/*.luam',
        'src/types.d.luam',
    },
}

assets = {
    {
        from = 'assets/**/*',
        to = 'assets',
    },
    {
        from = 'config/default.json',
        to = 'config/default.json',
    },
}

dependencies = {
    'scoreboard',
    'database',
}

engine = {
    minVersion = '1.6.0',
}

environment = {
    file = '.env.development',
    localFile = '.env.development.local',
}

helpers = { 'env' }
loadOrder = { 'src/shared/bootstrap.luam' }
outDir = 'build'

output = {
    bundle = true,
    map = true,
    minify = true,
}

development = {
    logs = {
        enabled = true,
    },
}

serverPath = env.MTA_SERVER_PATH
resourcesDir = 'mods/deathmatch/resources'

transport = {
    kind = 'http',
    resource = 'luam-sync',
    username = 'luam',
    passwordEnv = 'LUAM_MTA_PASSWORD',
}
```

Every domain remains optional except `name`. Omitted domains normalize to complete,
immutable defaults before any CLI, compiler, or LSP consumer sees them.

## Domain Model

### `compilerOptions`

Only fields that change source checking or emission belong here.

| Option | Type | Default | Effect |
| --- | --- | --- | --- |
| `strict` | `boolean` | `true` | Uses `strict` as the project default; `false` selects `nonstrict`. |
| `oop` | `boolean` | `false` | Enables the MTA OOP checker surface, rewrites, and generated `<oop>true</oop>`. |
| `noUnusedLocals` | `boolean` | `false` | Reports unused local declarations. |
| `noUnusedParameters` | `boolean` | `false` | Reports unused function and method parameters. |
| `warningsAsErrors` | `boolean` | `false` | Promotes compiler warnings after checking without changing diagnostic codes. |

Strictness precedence is deterministic:

1. A file's `#!strict`, `#!nonstrict`, or `#!nocheck` directive.
2. `compilerOptions.strict`.
3. The built-in default, `true`.

The manifest itself always uses its restricted strict dialect. Project compiler
options never weaken manifest validation. Project-wide `nocheck`, `target`, `noEmit`,
and arbitrary diagnostic suppression are intentionally absent.

Top-level `oop` moves to `compilerOptions.oop`. No alias remains because accepting
both paths would create conflicting sources of truth.

### `sources`

`sources` replaces `sourceDirs` and owns both discovery and the default side assigned
to each source. Each side accepts any number of literal paths and globs.

```lua
sources = {
    server = { 'src/server/**/*.luam', 'workers/queue.luam' },
    client = { 'src/client/**/*.luam', 'ui/**/*.luam' },
    shared = { 'src/shared/**/*.luam', 'types/global.d.luam' },
}
```

Matching rules:

- A string without a wildcard is a literal project-relative file path.
- `*`, `**`, and `?` are the complete initial glob grammar.
- Raw regex, negation, brace expansion, and extglobs are unsupported.
- Paths use `/` on every platform and may not be absolute or contain `..`.
- Several entries in one side form a union; duplicate same-side matches deduplicate.
- A file matched by different sides is a positioned configuration error. Order does
  not establish precedence.
- A literal must exist and end in `.luam`; this includes `.d.luam`.
- A glob may match zero files, but the complete mapping must discover at least one.
- A side directive remains a per-file override and keeps the existing conflict
  warning when it disagrees with the mapped side.

Defaults preserve the conventional directories:

```lua
sources = {
    server = { 'src/server/**/*.luam' },
    client = { 'src/client/**/*.luam' },
    shared = { 'src/shared/**/*.luam' },
}
```

Non-Luam files are no longer copied merely because they share a source directory.
They must be declared under `assets`, making source discovery and passthrough copying
independent and explicit.

### `assets`

`assets` replaces `assetDirs` with ordered declarative mappings.

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `from` | `string` | required | Literal file, directory, or glob relative to the project root. |
| `to` | `string` | `.` | Destination file or directory relative to the generated resource root. |

A directory or glob preserves the relative suffix below its static source root. A
literal file may rename its destination. Sources, the generated `meta.xml`, helper
paths, and asset destinations may not collide. Two mappings producing the same output
are an error even when their bytes are identical. Asset traversal uses the same path
normalizer and containment checks as `sources`; regex is unsupported here too.

### `dependencies`

`dependencies` is a deduplicated list of required MTA resource names. Each entry
generates one `<include resource="..." />` in deterministic order. Names use the same
resource-name validation as `name`; self-dependency is rejected.

Optional dependencies are excluded until Luam has a concrete checking or runtime
semantic for them. A field that only documents a name but changes no build artifact
would create false confidence.

### `engine`

Runtime-engine requirements live under `engine`, not under `mta`. This keeps the
manifest vocabulary centered on the role of the setting while the generated artifact
remains MTA-compatible.

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `minVersion` | `string` | `'latest'` | Pinned engine version or `'latest'` for the existing cached release lookup. |

`engine.minVersion = '1.6.0'` emits that exact validated version and performs no
network request. `'latest'` preserves the current fresh lookup, cache, and offline
fallback. The compiler packages remain network-free; only the CLI resolves
`'latest'`. Generated XML continues to use MTA's
`<min_mta_version server="..." client="..." />` spelling.

There is no `mta` table and no `mta.minVersion` alias. Migration documentation maps
the conceptual `mta.minVersion` name directly to `engine.minVersion`.

### `environment`

`environment` selects the project environment files that the CLI and LSP load.

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `file` | `string` | `'.env'` | Declares keys and types for `process.env` and provides the generated resource environment template. |
| `localFile` | `string` | `'.env.local'` | Overrides declared values for local CLI and editor analysis without introducing undeclared keys. |

Both fields are literal project-relative file paths. They may not be globs, absolute
paths, parent traversals, or expressions that depend on `env`, `mode`, or another
manifest field. This static restriction avoids a bootstrap cycle: Luam must know
which environment file to read before those variables can participate in analysis.

The loader resolves the manifest first far enough to validate these two static paths,
then loads the selected files and completes project analysis. The same resolved paths
feed CLI builds, `process.env` declarations and completion, manifest `env.` completion,
and LSP workspace refresh. The LSP stops searching parent directories for the nearest
`.env`; the selected project files are authoritative.

The base file owns the declared key set and inferred `string`, `number`, or `boolean`
types. The local file may override values only for keys declared by the base file,
preserving the current secret-safe merge rule. Missing default files remain optional;
an explicitly configured non-default path that does not exist receives a positioned
configuration diagnostic. Neither file's values may appear in diagnostics, logs,
traces, hover, completion details, or generated source maps.

### Existing Domains

| Domain | Ownership |
| --- | --- |
| Identity (`name`, `author`, `version`, `description`) | Resource identity and `<info>` metadata. |
| `helpers`, `loadOrder` | Runtime assembly and deterministic script order. |
| `outDir`, `output` | Local artifact layout, maps, bundling, and minification. |
| `environment` | Project environment declaration, local overrides, CLI loading, and LSP typing/completion. |
| `development` | Behavior enabled only by development commands. |
| `serverPath`, `resourcesDir`, `transport` | Deployment and live-server communication. |

`output.minify` controls the existing production Lua minifier. Command-line output
flags override manifest defaults for that invocation; compiler options receive no
CLI overrides in this milestone.

## Architectural Decisions

| Decision | Choice | Rationale |
| --- | --- | --- |
| Manifest model | Closed, typed domain tables | Powerful completion and validation without arbitrary keys. |
| Evaluation | Existing pure restricted dialect | Mode and environment expressions remain useful without hooks or code execution. |
| Source matching | Literals plus `*`, `**`, and `?` | Covers practical layouts without regex escaping, flags, or pathological patterns. |
| Source ownership | `sources` replaces `sourceDirs` | Discovery and side classification must have one source of truth. |
| Asset ownership | `assets` replaces `assetDirs` | One model handles directories, individual files, globs, and destination mapping. |
| Engine naming | `engine.minVersion` | Describes the runtime requirement while keeping MTA names at the generated XML boundary. |
| Environment selection | Static `environment.file` and `environment.localFile` paths | Gives CLI and LSP one source of truth without a circular env-dependent lookup. |
| Dependency semantics | Required resources only | Every declared dependency has an observable `<include>` effect. |
| Internal ownership | Normalized contracts live in compiler packages | CLI and LSP consume one interpretation rather than reimplementing defaults. |
| Cache identity | Hash normalized semantic domains | Formatting-only manifest edits must reuse work; behavior changes must invalidate it. |
| Extension policy | Add fields only with an implemented consumer | Prevents the manifest becoming a collection of inert promises. |

Record these decisions in an ADR before implementation. Any future plugin, hook,
configuration inheritance, optional dependency, regex, or arbitrary diagnostic ignore
list requires a separate decision.

## Scope

- **In:** Domain catalog, normalization, compiler options, source matching and side
  assignment, asset mappings, required dependencies, `engine.minVersion`, project
  environment file selection, output minification, CLI and watcher integration,
  project cache identity, LSP completion and hover, diagnostics, migration, tests,
  and bilingual documentation.
- **Out:** Build hooks, executable plugins, raw regex, negated globs, configuration
  inheritance, multiple manifests, project-wide `nocheck`, arbitrary warning ignores,
  optional dependencies, remote assets, package installation, and non-Lua targets.

## Risks And Mitigations

| Risk | Mitigation |
| --- | --- |
| A powerful manifest becomes an unrestricted build system. | Keep the dialect pure, use closed typed domains, and require a concrete built-in consumer for every field. |
| CLI, watcher, and LSP disagree on path matching. | Share one normalized matcher and provenance model from the compiler package. |
| Broad globs traverse generated output or dependencies. | Restrict static roots, enforce containment, and exclude tool/build directories before traversal. |
| One file matches several sides. | Fail before compilation and report every conflicting side and pattern. |
| Asset mappings overwrite generated files. | Build a complete destination index and reject all collisions before writing. |
| Compiler options leak into manifest checking. | Keep manifest analysis on its own strict restricted mode and test `strict = false`. |
| Watch mode reuses stale semantic results. | Fingerprint normalized domains at each consuming phase and test edits in one cache instance. |
| Pinned and latest engine versions behave differently offline. | Pinned values never use HTTP; latest follows the existing cache-to-omission fallback and never fails compilation. |
| Environment selection creates a bootstrap cycle. | Require static literal paths and resolve them before environment-backed manifest analysis. |
| The LSP exposes values from a selected local environment file. | Use values only for evaluation, expose names and inferred types only, and redact diagnostics, logs, traces, hover, and completion. |
| CLI and LSP load different environment files. | Normalize paths once from the manifest and remove hard-coded and nearest-parent discovery paths. |
| Renaming `sourceDirs` and `assetDirs` breaks implicit behavior. | Provide targeted diagnostics and explicit migration examples, especially for non-source passthrough files. |
| `engine` becomes a generic vendor escape hatch. | Admit only runtime-engine requirements with validated effects on checking or generated artifacts. |
