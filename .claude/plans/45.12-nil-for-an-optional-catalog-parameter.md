# 45.12 - Accept nil for a parameter the catalog declares optional

> File: `.claude/plans/45.12-nil-for-an-optional-catalog-parameter.md`

## Objective

Make "may be omitted" and "may be nil" the same thing for an MTA parameter, so
forwarding an optional callback into an API that already accepts none stops being
an error.

## Reproduction

```luam
function svgCreateRoundedRectangle(width: number, height: number, callback?: fun): DxTexture
    return svgCreate(width, height, '<svg/>', callback)
    # check-type-mismatch: Argument 4 expects "fun(any): void" but received "fun(...): any?".
end
```

`svgCreate` declares three required parameters and a fourth optional one, so
omitting the callback is legal. Passing `nil` explicitly is the same call in Lua,
and it is rejected, because the parameter's **type** is not optional even though
its **arity** says it is.

The wrapper above is the single most common shape in a ported resource: an
optional argument received and forwarded.

## Root Cause

A catalog function carries a required-argument count and a list of parameter type
descriptors. The count makes a missing argument legal; the descriptor is not
`optionalOf(...)`, so an argument that is present and optional fails
assignability. The two facts describe the same property and disagree.

## Scope

- **In:** Argument assignability for a parameter positioned beyond the declared
  required count, in the procedural catalog, the OOP surface and the Luam runtime
  globals.
- **Out:** A required parameter, which keeps rejecting `nil`. Any regeneration of
  the catalog data. Any change to the arity check itself.

## Steps

- [x] At the point an argument is checked, treat a parameter whose index is at or
      beyond the required count as accepting `nil` in addition to its declared
      type, rather than editing every descriptor in the generated catalog.
- [x] Keep the message for a required parameter unchanged, and make the optional
      case print the type without a spurious `?` so the diagnostic does not
      contradict itself.
- [x] Apply the rule to a method on the OOP surface and to a Luam runtime global,
      so the three surfaces agree.
- [x] Add a catalog-coverage assertion that no function declares an optional
      parameter whose descriptor is already optional, so the two encodings do not
      both appear.
- [x] Confirm the emitted Lua is unchanged.

## Acceptance Criteria

- [x] The reproduction compiles.
- [x] `svgCreate(1, 1, xml, 42)` still reports the fourth argument.
- [x] `setElementPosition(nil, 0, 0, 0)` still reports the first argument.
- [x] The same rule holds for an OOP method and a runtime global, each with a
      test.
- [x] The catalog-coverage suite passes.

## Outcome

`setElementPosition(nil, 0, 0, 0)` reports nothing, and reported nothing before
this change: an MTA element parameter is not modelled with a type that rejects
`nil`, so the acceptance line naming it was already false on the tree this plan
was written against. Nothing here made it weaker — the required/optional split
this task added is exercised by the `string.len(42)` case instead.
