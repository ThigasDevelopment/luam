# 38.04 - Vendor library output and order it in meta.xml

## Objective

Write a library's compiled code into the generated resource, in both output
layouts, in an order the resource actually loads correctly.

## Scope

- **In:** The `libs/<package>/<environment>/` tree layout, concatenation into the
  environment bundle, the enumerated `<script>` entries in `meta.xml`, scoped
  name flattening, and the interaction with runtime helpers and `loadOrder`.
- **Out:** Minification and map generation, which apply to library output the
  same way they apply to project output and need no new rule.
- **Out:** Copying a library's assets. A library ships code; a library that wants
  to ship an image is a question this task does not answer, and 38.06 records it
  as a boundary.

## Context

MTA has no module system, so a library has to end up inside the resource.
[ADR-038](../docs/adr/038-library-distribution.md) fixes where:

- Tree layout: `libs/<package>/<environment>/`, beside the `lib/<environment>/`
  runtime helpers of [ADR-008](../docs/adr/008-generated-manifest-standard.md).
- Bundle layout: concatenated into the environment bundle ahead of the project's
  own modules, per [ADR-016](../docs/adr/016-flat-bundle-concatenation.md).
- `@scope/name` flattens to `scope-name`, so no `@` and no nested scope directory
  reaches an MTA path.
- Library scripts are enumerated `<script>` entries, never wildcards, since the
  compiler owns those paths.
- They sit after the runtime library and before `config.lua`, the pinned
  `loadOrder` entries and the source wildcards.
- Libraries appear in `libraries` order; a library's files in the order its
  `luam` field declares.

`packages/compiler/src/project/resource-layout.ts` already holds the pieces this
extends: `LIBRARY_DIRECTORY` is `'lib'` for the runtime helpers, `libraryPath`
builds a helper path, `collectScripts` builds the script list, `resolveLoadOrder`
pins entries and reports `project-load-order-missing`, and `groupByRoot` collapses
project sources into wildcards. Library scripts must bypass that last one.

The directory names are one letter apart — `lib/` for runtime helpers,
`libs/` for third-party libraries. That is what the ADR wrote, and it is a
legibility hazard worth reconsidering once, in T-01, before it is baked into
every generated resource and every documentation page.

## Design

### Helpers stay first

A library that uses a class, a template string or `table.count` needs the same
runtime helper a project file needs. ADR-038 says a library feeds the same
requirement set the reference trigger already computes, so a helper is emitted
once, ahead of everything, whether the project or a library asked for it.

`collectHelpers` already takes the module list and a manual list and merges
environments. Library modules joining that list is the whole change, provided
[38.02](38.02-library-compilation.md) put them in the same list — which is the
main reason it did.

### Ordering, end to end

The `meta.xml` script order becomes, per environment:

1. Runtime helpers.
2. Library scripts, in `libraries` order, each library's files in its declared
   order.
3. `config.lua` and `env.lua`.
4. Pinned `loadOrder` entries.
5. Project source wildcards.

This has to be the same order [38.02](38.02-library-compilation.md) compiled in,
or the checker approved a program the resource does not load. T-02 asserts the
two agree rather than assuming it.

### `loadOrder` and libraries

`resolveLoadOrder` reports `project-load-order-missing` for an entry matching no
source file or asset. A library file is now a third thing an entry could name.
Decide in T-01 whether a `loadOrder` entry may pin a library file — pinning one
would let a consumer override the declared order, which the ADR's ordering rule
implies it should not — and make the diagnostic say which, rather than leaving a
confusing "no source file matches" for a path that plainly exists.

### Pruning

`resource-prune.ts` removes output a build no longer produces. A library removed
from `libraries` must take its `libs/<package>/` directory with it, or the next
build ships code the manifest no longer names. That is the failure this model is
least able to detect at run time, so T-04 covers it explicitly.

## Steps

### T-01 - Decide the three open points

**Agent:** architecture-engineer

- [ ] Reconsider `libs/` beside `lib/` once. Keep the ADR's names or propose a
      change with the reasoning; either way, record the decision so it is not
      reopened per page in 38.06.
- [ ] Decide whether a `loadOrder` entry may name a library file, and make the
      diagnostic reflect the answer.
- [ ] Confirm scoped-name flattening cannot collide: `@a/b-c` and `@a-b/c` both
      flatten to `a-b-c`. Decide whether that is a diagnostic or an accepted
      improbability, and record it.

### T-02 - Emit into both layouts

**Agent:** architecture-engineer

**Files:** `packages/compiler/src/project/resource-layout.ts`,
`packages/compiler/src/project/bundle-layout.ts`,
`packages/cli/src/build/resource-writer.ts`

- [ ] Write tree output to `libs/<package>/<environment>/`, mirroring the
      library's own source tree beneath it.
- [ ] Concatenate library modules into the environment bundle ahead of the
      project's own.
- [ ] Emit enumerated `<script>` entries for library files, never wildcards, in
      the order above.
- [ ] Assert the emission order equals the compile order from 38.02.

### T-03 - Helpers

**Agent:** architecture-engineer

- [ ] Confirm a helper a library requires is emitted once, ahead of everything,
      through the existing requirement set.
- [ ] Confirm a helper required only by a library is emitted, and one required by
      nobody still is not.

### T-04 - Prune and rebuild

**Agent:** architecture-engineer

**Files:** `packages/cli/src/build/resource-prune.ts`

- [ ] Removing a library from `libraries` removes its output directory on the
      next build.
- [ ] Renaming a library removes the old directory and writes the new one.
- [ ] A watch rebuild through `ensure` reflects a library change without a clean
      build.

## Acceptance Criteria

- [ ] Tree output places a library at `libs/<package>/<environment>/`, with `@`
      flattened.
- [ ] Bundle output concatenates library modules ahead of project modules, in
      `libraries` order.
- [ ] `meta.xml` lists library scripts as enumerated entries, after the runtime
      helpers and before `config.lua`, the pinned `loadOrder` entries and the
      source wildcards.
- [ ] The emission order equals the compile order, asserted rather than assumed.
- [ ] A helper a library needs is emitted once and first.
- [ ] Removing a library from the manifest removes its output.
- [ ] A generated resource with a library starts in MTA, proven by the smoke
      build.
- [ ] A project with no libraries produces byte-identical output to today.

## Out of Scope

- Library assets.
- New minification or map rules.
- A per-library output directory the consumer can configure.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Emission order and compile order drift apart | High | T-02 asserts equality; both derive from one order fixed in 38.02 T-01 |
| Stale library output ships after a library is removed | High | T-04 covers prune, rename and watch rebuild |
| `libs/` and `lib/` are confused by readers and by scripts | Medium | T-01 reconsiders the names once, deliberately, before they spread |
| A `loadOrder` entry naming a library file gets a misleading diagnostic | Medium | T-01 decides the rule and fixes the message |
| Two scoped names flatten to one directory | Low | T-01 records it as a diagnostic or an accepted improbability |
