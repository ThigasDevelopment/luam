# 31.02 - Close the grammar scopes the theme cannot reach

## Objective

Give the two TextMate grammars a scope for every element the role table names,
so a theme can colour an element instead of inheriting whatever the editor's
default paints.

## Root Cause

The grammar was written to highlight, not to discriminate. Three collapses stop
any theme from differentiating elements the user reads as different things:

- `call` labels every bare `foo()` `support.function.any-method.luam`, the same
  scope `method` gives `obj:foo()`. A user function, a method, and an MTA native
  are one colour today.
- `directive` labels `#!strict` and `#!server` alike as
  `keyword.control.directive.luam`. R6 needs the environment word separated from
  the strictness word, and the three environments separated from each other.
- Nothing scopes parameters, enum members, table keys, or punctuation. They fall
  through to `variable.other.luam` or to no scope at all.

A regex grammar cannot fix all of this — telling an MTA native from a user
function needs the symbol table, which is 31.3's job. This task fixes what is
positional, and stops there.

## Scope

- **In:** New scopes in `luam.tmLanguage.json` and `luam-manifest.tmLanguage.json`
  for the distinctions a pattern can decide from position alone.
- **Out:** Any distinction requiring resolution — native vs user function,
  parameter vs local at a use site, class vs any capitalized name. Those are
  semantic tokens in 31.3, and this task must not fake them with heuristics.

## Steps

### T-01 - Split the directive scope

**Agent:** architecture-engineer

- [ ] Separate the strictness directives (`strict`, `nonstrict`, `nocheck`) into
      `keyword.control.directive.strictness.luam`.
- [ ] Give each environment its own scope:
      `keyword.control.directive.environment.server.luam`, and the `client` and
      `shared` counterparts. R6 tints them apart, and one scope cannot.
- [ ] Keep `#!` on `punctuation.definition.directive.luam` rather than reusing
      the comment punctuation scope it borrows today.

### T-02 - Separate call sites from method sites

**Agent:** architecture-engineer

- [ ] Move bare calls to `entity.name.function.call.luam` and keep `obj:method()`
      on `entity.name.function.method.luam`. Neither is `support.*` — support
      means a library symbol, and the grammar cannot know that.
- [ ] Reserve `support.function.library.luam` and `support.function.luam` for the
      literal Lua stdlib lists the grammar already carries, which are the only
      library symbols it can prove.
- [ ] Scope `new Foo(` so the constructor call is distinguishable from a plain
      call, keeping the class name on the type scope it already gets.

### T-03 - Scope parameters and enum members

**Agent:** architecture-engineer

- [ ] Add a parameter-list pattern over `function ... (` and `fun (` so declared
      parameters take `variable.parameter.luam`, with the type annotation inside
      still routed through the existing annotation rule.
- [ ] Scope enum body entries as `variable.other.enummember.luam`, bounded by the
      `enum Name {` block so ordinary table literals are unaffected.
- [ ] Scope a table literal key as `meta.object-literal.key.luam` so a key reads
      differently from the value beside it.

### T-04 - Scope the punctuation the theme dims

**Agent:** architecture-engineer

- [ ] Brackets, braces, parentheses, commas, and semicolons take
      `punctuation.*.luam` scopes. Ambient punctuation is a third of a file's
      glyphs; leaving it at foreground is what makes a theme feel loud.
- [ ] Scope the type-position punctuation separately — `|`, `&`, `<`, `>`, `[]`
      inside an annotation — so Set 6 can dim them without dimming arithmetic.

### T-05 - Carry the same treatment into the manifest grammar

**Agent:** architecture-engineer

- [ ] `.luam.manifest` gets the same punctuation and key scopes, and keeps its
      own property-name scope, so a manifest is themed by the same roles rather
      than by an accidental resemblance to Lua.
- [ ] Confirm the manifest's environment-bearing fields, if any, resolve to the
      R6 roles rather than to a generic string colour.

### T-06 - Keep the grammar tests honest

**Agent:** architecture-engineer

- [ ] Extend `packages/vscode/tests/grammar.test.ts` for every new rule, in the
      style it already uses — assert the pattern matches what it should and, for
      the split scopes, assert it does not match what now belongs elsewhere.
- [ ] Add a case proving `#!client` and `#!server` produce different scopes, and
      one proving `foo()` and `obj:foo()` do.

## Acceptance Criteria

- [ ] Every role in the 31.1 table that a grammar can decide has a scope, and the
      mapping table in 31.4 has no hole attributable to a missing scope.
- [ ] No new scope is produced by a heuristic that guesses at resolution. A
      pattern either proves its claim from position or does not make it.
- [ ] `pnpm --filter luam test` passes, including the new grammar cases.
- [ ] Opening an existing `.luam` fixture under the current default theme shows
      no regression: nothing that was coloured before is now unscoped.
