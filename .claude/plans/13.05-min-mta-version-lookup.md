# 13.05 - Resolve `min_mta_version` from the MTA release feed

> File: `.claude/plans/13.05-min-mta-version-lookup.md`
> This is the only network call in the whole build, and it must never be able to
> fail one. The compiler packages stay offline; the lookup lives in the CLI.

## Objective

Emit `<min_mta_version server client />` from the latest published MTA release,
resolved by the CLI, cached in the project, and degrading to the cached value —
then to silence — when the network is not there.

## Scope

- **In:** The release lookup in the CLI, the on-disk cache, the fallback chain,
  the warning, and the manifest element.
- **Out:** A separate feed per side. `multitheftauto/mtasa-blue` ships both
  sides from one release, so both attributes carry the same value until a
  per-side feed is identified.

## Steps

- [ ] Add the lookup to the CLI, beside the `ensure` transport — the only other
      place the project allows outbound HTTP. Query the GitHub releases of
      `multitheftauto/mtasa-blue` and take the latest published tag.
- [ ] Validate the response before it reaches the manifest: a tag must match an
      expected version shape, and anything else is treated as a failed lookup.
      The value ends up in generated XML, so it is untrusted input.
- [ ] Cache the resolved value in the project, with a timestamp, so a normal
      build does not hit the network on every run.
- [ ] Implement the fallback chain, in order: a fresh lookup, the cached value,
      then nothing — a warning through the reporter and no element emitted. No
      path in this chain fails the build.
- [ ] Give the build a way to skip the lookup entirely, so CI and offline work
      are deterministic and the benchmark does not measure a network call.
- [ ] Never let the lookup block the reported build time in a misleading way:
      it gets its own phase or folds into discovery, and its duration is
      visible in the timing breakdown milestone 12 prints.
- [ ] Record in [ADR-008](../docs/adr/008-generated-manifest-standard.md) that
      the manifest is no longer a pure function of the source, and that
      reproducibility now reads "identical for a given resolved MTA version".

## Acceptance Criteria

- [ ] A build with network access emits
      `<min_mta_version server="..." client="..." />` with the latest release,
      and writes the value to the cache.
- [ ] A build with the network unavailable emits the cached value, succeeds, and
      says nothing alarming.
- [ ] A build with no network and no cache warns, omits the element, and still
      produces a complete, loadable resource — asserted with the lookup stubbed
      to throw.
- [ ] A malformed or unexpected feed response is treated as a failure, never
      written into the manifest, and never crashes the build.
- [ ] No file under `packages/compiler`, `packages/runtime`, or
      `packages/mta-types` makes or imports a network call.
- [ ] `pnpm typecheck`, `pnpm build`, and `pnpm test` pass, and the suite runs
      with no real network access.
