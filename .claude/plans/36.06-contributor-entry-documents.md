# 36.06 - Add the contributor entry documents and templates

## Objective

Give an outside contributor everything needed to open a pull request that
passes: how to set the workspace up, what the pipeline will check, what the
project will not accept, and where to report a vulnerability privately.

## Problem

The repository has none of the files GitHub looks for. There is no
`CONTRIBUTING.md`, no `CODE_OF_CONDUCT.md`, no `SECURITY.md`, no issue or pull
request template, and no `CODEOWNERS`. A contributor arriving today has to infer
the conventions from the diff, and someone finding a vulnerability has no
private channel and will open a public issue.

## Scope

- **In:** `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, issue forms,
  the pull request template, and the contributing page in both documentation
  locales.
- **Out:** Governance, maintainer roster, and any promise about response time
  the project cannot keep.

## Steps

### T-01 - Write the contributing guide

**Agent:** documentation-engineer

- [x] Document the workspace setup — pnpm, the supported Node versions the CI
      matrix pins, and the Lua 5.1 requirement for the minifier and smoke tests.
- [x] List the commands the pipeline runs, so a contributor can reproduce every
      required check locally before pushing.
- [x] State the branch model, the commit message convention, and that a plan and
      roadmap row move together with the change.
- [x] State the constraints a reviewer will enforce: English everywhere a user
      reads, Lua 5.1 and MTA compatibility, no network call from the compiler
      packages, and the conventions in
      [code-conventions](../docs/code-conventions.md).
- [x] Explain that a first-time contributor's workflow waits for approval, so
      nobody reads the delay as a broken pipeline.

### T-02 - Add the templates

**Agent:** documentation-engineer

- [x] Add issue forms for a bug report, a language or compiler proposal, and a
      documentation problem. A bug form asks for the Luam version, the Node
      version, the MTA side, and the smallest reproducing source.
- [x] Add a pull request template that asks what changed, which plan it belongs
      to, and how it was verified.
- [x] Add `SECURITY.md` with the supported versions and a private reporting
      channel, and state that a vulnerability must not be opened as an issue.
- [x] Add `CODE_OF_CONDUCT.md`.

### T-03 - Reach the documentation site

**Agent:** documentation-engineer

- [x] Add a contributing page to the manual in both locales, linking the
      repository documents rather than restating them.
- [x] Link it from the README and the manual navigation.

## Acceptance Criteria

- [x] `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md` and `SECURITY.md` exist and GitHub
      surfaces each one in its expected place.
- [x] A contributor can run every required check locally by following the guide,
      verified by someone who has not set the project up before.
- [x] Issue forms collect the reproduction detail a maintainer needs, so a bug
      report does not require a second round trip.
- [x] `SECURITY.md` names a private channel; no step tells a reporter to open an
      issue.
- [x] The contributing page exists in both locales and passes the parity check.
- [x] Nothing in these documents duplicates the manual; they link to it.
