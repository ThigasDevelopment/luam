# 24.02 - Automate safe MTA catalog refreshes

> **Superseded by milestone 28.** This plan's accepted option was bumping the
> pinned `mtasa-lua-types` version. That package stopped being published on
> 2023-02-05 and `1.1.1` is final, so the refresh it automates no longer exists.
> [28.06](28.06-scheduled-refresh-workflow.md) automates the
> replacement: a scheduled fetch of the MTA wiki snapshot that opens a pull
> request and never merges one.

## Objective

Reduce MTA catalog lag through reproducible scheduled updates while keeping compilation network-free and unknown APIs non-blocking.

## Options Considered

| Option | Reproducibility | Freshness | Decision |
|---|---|---|---|
| Fetch the MTA wiki during every build | Low | High | Reject |
| Periodically update the pinned upstream package | High | Depends on upstream | Accept as primary |
| Maintain a complete independent scraper | Medium | High | Defer until upstream lag is measured |

## Scope

- **In:** Scheduled dependency checks, deterministic generation, catalog diffs, overrides, coverage reports, tests, and release metadata.
- **Out:** Build-time HTTP, automatic merge, and errors for unknown MTA globals.

## Steps

### T-01 - Establish freshness metrics

**Agent:** architecture-engineer

- [ ] Record the pinned source version, generated-at metadata, covered MTA release, declaration counts, and override count.
- [ ] Define when an upstream delay justifies a local override or a new source ADR.

### T-02 - Automate refresh proposals

**Agent:** github-engineer

- [ ] Add a scheduled workflow that detects an upstream release, updates only the pinned dependency, regenerates the catalog, and opens a reviewable PR.
- [ ] Include function, event, OOP surface, environment, and signature diffs in the PR summary.
- [ ] Pin action versions and grant the workflow minimum permissions.

### T-03 - Protect catalog correctness

**Agent:** test-engineer

- [ ] Fail generation on nondeterministic output, duplicate declarations, invalid environments, or unreviewed lossy normalization.
- [ ] Preserve tests proving that unknown APIs remain `any` without blocking builds.

## Acceptance Criteria

- [ ] Running generation twice from one lockfile produces no diff.
- [ ] The scheduled workflow never publishes or merges without review.
- [ ] Compiler packages perform no network request.
- [ ] Catalog metadata names both upstream and covered MTA versions.
- [ ] MTA catalog and compiler coverage suites pass.
