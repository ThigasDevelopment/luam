# 50.09 - Cover the workspace and the session in the tests

## Objective

Lock the workspace behaviour where it can regress silently: the schema, the
precedence, the line split in the console, the session lifecycle, and the
language server's per-project scoping.

## What makes this testable

The session reads lines from stdin and writes lines to a child process, and both
ends are already fakeable.
[fake-process-service](../../packages/cli/tests/support/fake-process-service.ts)
stands in for the MTA process,
[mock-server-console](../../packages/cli/tests/support/mock-server-console.ts)
records what was written to it, and 50.04 keeps the line split working on a
non-TTY stdin precisely so a test can drive a session from a string. No test in
this task needs a terminal or a real server.

## Scope

- **In:** New suites for the server file, the workspace context, the session, and
  LSP scoping; extensions to the existing console-input, ensure, dev and server
  suites.
- **Out:** New product behaviour. A test that wants a behaviour that does not
  exist belongs in the task that owns it.

## Steps

- [ ] Extend
      [project-fixture](../../packages/cli/tests/support/project-fixture.ts) with
      a workspace shape: a root holding a `.luam.server`, N resource
      subdirectories each with a manifest and sources, and a fake server tree with
      an executable. It already grew `executable` for the permission probe; this
      is the same idea one level up.
- [ ] Add a session driver to the support directory: feed it a script of lines,
      collect the reporter output and everything written to the child's stdin, and
      assert on both. Every session test in this task should read as a transcript.
- [ ] Compiler suite for the server file: each field's type and rule, the required
      `serverPath`, unknown fields, parse errors, and the `.luam.formatter`-style
      retagging. Mirror `packages/compiler/tests/formatter-options.test.ts`.
- [ ] Compiler suite for discovery: the upward walk from a nested directory, the
      `node_modules` stop, the filesystem-root stop, and `discoverResources`
      returning the direct children with a manifest, sorted, ignoring files and
      deeper directories.
- [ ] CLI suite for the workspace context: mode resolution in all three cases,
      `--manifest` forcing project mode, the unknown-resource message listing what
      was discovered, and an invalid `.luam.server` stopping the command with
      `EXIT_USAGE`.
- [ ] CLI suite for precedence: the four rows of 50.03's table, the single
      warning naming three fields, the silent case with no workspace file, and
      `warningsAsErrors` promoting it.
- [ ] Extend
      [server-console-input](../../packages/cli/tests/server-console-input.test.ts):
      the verb split, the whole-first-word rule, the leading-space escape, a
      multi-line paste, backspace, `Ctrl+C` mid-line, and the no-verbs
      construction forwarding byte for byte.
- [ ] Session suite: opening attaches nothing; `ensure` builds, syncs and writes
      `refresh` then `start`; a save rebuilds and writes `refresh`, `stop`,
      `start`; a save with no output change writes nothing; a failing build syncs
      nothing and stays attached; `ensure` twice does not double-watch; `drop`
      stops the rebuilds and leaves the server alone; `rebuild` with and without a
      name; `list` in both states; `help`; and an unknown name.
- [ ] Session lifecycle: a server that exits unexpectedly ends the session with
      `EXIT_DIAGNOSTICS`, `Ctrl+C` shuts down and closes every watcher, and a verb
      typed before readiness runs after it.
- [ ] LSP suite for scoping: the leak, the borrowed compiler option and the
      misclassified side from 50.07, each as its own case with a two-resource
      fixture; plus the nested-project rule and the projectless file.
- [ ] VS Code suite: tokenization rows for `.luam.server` and the file-icon
      mapping, following the formatter's existing rows.
- [ ] Confirm the command contract test
      ([command-contract](../../packages/cli/tests/command-contract.test.ts))
      covers the new usage errors, so the bundled CLI's surface stays described in
      one place.

## Acceptance Criteria

- [ ] Every acceptance line in 50.01 through 50.08 has a test that would fail if
      the behaviour were reverted.
- [ ] No test in this milestone starts a real MTA server, requires a TTY, or
      writes outside its fixture directory.
- [ ] The session suite asserts on what was written to the child's stdin, not
      only on the reporter output — a restart that reports itself and writes
      nothing is the failure this milestone is most able to ship.
- [ ] Existing CLI, LSP and VS Code suites pass unchanged except where a
      behaviour deliberately changed, and each such change is named in the diff.
- [ ] `pnpm -r test`, `pnpm typecheck`, `pnpm conventions` and `pnpm build` pass.
