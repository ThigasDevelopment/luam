# 30.01 - Replace the dead upstream with a committed wiki snapshot

## Objective

Give the catalog a raw input that can still move: a revision-stamped snapshot of
the MTA wiki, committed to the repository and refreshed by an explicit command,
so generation stays offline while the source stops being frozen.

## Root Cause

`packages/mta-types` generates its entire catalog from `mtasa-lua-types@1.1.1`.
That package was last published on 2023-02-05 and `1.1.1` is the newest version
that will ever exist. ADR-006 planned refreshes as "bumping the pinned version",
which is no longer a refresh path at all. Measured on 2026-08-25: the catalog
declares 1294 functions against 1383 native functions the wiki lists, a gap of
119.

## Scope

- **In:** A fetch command, the snapshot format and its revision stamps, the
  canonical function list, and the guarantee that generation reads only the
  committed file.
- **Out:** Parsing signatures out of the snapshot (30.3), changing what the
  catalog emits (30.4), and CI automation (30.6). This task lands a new input
  that nothing consumes yet.

## Steps

### T-01 - Derive the canonical function list

**Agent:** architecture-engineer

- [ ] Take the list from the rendered `Client_Scripting_Functions` and
      `Server_Scripting_Functions` pages, which are curated: 1159 client and 754
      server entries, 1383 as a union.
- [ ] Do not use `Category:Client_functions`. It mixes third-party library docs
      into the same category — 2229 titles against 1159 real functions, with DGS
      and Astrath pages inseparable from native ones by name alone.
- [ ] Derive the environment from list membership: present in both lists means
      shared. Measured 98.1% agreement with the current catalog, and every
      disagreement is a function that became shared in a later MTA release.

### T-02 - Fetch and store the snapshot

**Agent:** architecture-engineer

- [ ] Batch through the MediaWiki API with `action=query&prop=revisions`, 50
      titles per request, storing per page the title, the `revid`, and the
      wikitext.
- [ ] Trim each page at the Example section. Measured: 2450 KB whole, 1253 KB
      trimmed, and the sections after Syntax carry nothing the generator reads.
- [ ] Emit keys in a stable order so a refetch against an unchanged wiki
      produces a byte-identical file and an empty diff.
- [ ] Write the file only after every batch succeeded, so a network failure
      never leaves a half-written snapshot behind.

### T-03 - Keep generation offline

**Agent:** architecture-engineer

- [ ] Add `fetch-wiki` as its own package script. Generation never triggers it.
- [ ] Make `generate` read the committed snapshot and nothing else, so a clone
      with no network still regenerates the catalog byte for byte.
- [ ] Fail with a message naming the missing file, and the command that writes
      it, when the snapshot is absent.

### T-04 - Treat the snapshot as untrusted input

**Agent:** architecture-engineer

- [ ] Parse the wikitext as text. Never evaluate it, never import it, never
      expand a template by executing anything.
- [ ] Validate on read: a page count far below the recorded baseline, or a page
      with no Syntax section, fails the run naming the page.

## Acceptance Criteria

- [ ] The committed snapshot holds every function on the two curated lists, each
      with a `revid`.
- [ ] `pnpm --filter @luam/mta-types generate` completes with no network access.
- [ ] Running `fetch-wiki` twice against an unchanged wiki produces no diff.
- [ ] An interrupted fetch leaves the previous snapshot intact.
- [ ] `pnpm typecheck` and `pnpm test` pass.
