# 49.03 - Name the source files no pattern matched

## Objective

Replace the dead end a build hits when `sources` matches nothing with a
diagnostic that names the `.luam` files the project does have and says what to do
with them, so `config-no-sources` is reported only for a project that has no
source file at all.

## Scope

- **In:** A new `config-unmatched-source` error in
  [source-discovery](../../packages/cli/src/build/source-discovery.ts), raised on
  the failure path only.
- **Out:** Reporting unmatched files on a build that did find sources. A project
  may hold `.luam` files it deliberately does not compile, and a warning on every
  successful build is how a diagnostic gets ignored.

## The message today

```
error config-no-sources: No ".luam" source files matched "sources" in "C:/…/luam-resource-test".
```

The project holds `index.luam`. The message says nothing about it, nothing about
which patterns were tried, and nothing about the fix. Every fact it needs is one
directory walk away, and that walk is free here — the build has already failed.

## Steps

- [ ] Walk the project when, and only when, no file matched and no other
      diagnostic was produced. Reuse `listProjectFiles(root, [''], excluded)`,
      which honours `EXCLUDED_DIRECTORIES` and the `outDir` and contracts
      directories the runner already passes in.
- [ ] Keep only `.luam` paths that are not `isTestPath`. When the walk finds
      none, report `config-no-sources` with the message it has today. Nothing
      about an empty project changes.
- [ ] Otherwise report `config-unmatched-source`, naming at most five paths in
      sorted order and counting the rest, and closing with the three ways out:
      add a pattern to `sources`, move the file under a directory the manifest
      already names, or put it in the project root, where an unmatched file
      compiles with the side its `#!` directive declares.
- [ ] Keep the wording in the one English voice the CLI already speaks, quoting
      paths the way the neighbouring `config-missing-source` and
      `config-source-side-conflict` messages quote theirs.
- [ ] After 49.01 the only way to reach this code with a root file present is a
      pattern conflict, so keep the two codes exclusive: one build reports
      `config-unmatched-source` or `config-no-sources`, never both.

## Acceptance Criteria

- [ ] A manifest whose `sources` names `src/server`, `src/client` and
      `src/shared`, in a project whose only source is `tools/helper.luam`,
      reports `config-unmatched-source` naming that file and the three remedies.
- [ ] A project with a manifest and no `.luam` file still reports
      `config-no-sources` with today's message.
- [ ] A project with eight unmatched files names five and reports the remaining
      three as a count.
- [ ] A successful build reports neither code, whatever else the tree holds.
- [ ] The walk runs only after the build has already failed; a successful build
      does no extra filesystem work.
- [ ] `pnpm -r test`, `pnpm lint` and `pnpm typecheck` pass.
