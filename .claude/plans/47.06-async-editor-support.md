# 47.06 - Surface async, await and Promise in the editor

## Objective

Make the two new words look and behave like language in the editor, and make a
`Promise` value answer hover and completion the way `Threads` already does.

## Scope

- **In:** Grammar scopes, semantic tokens, completion, hover, and the inlay hint
  for a local bound to an `await`.
- **Out:** A code action to convert a `:next` chain into `await`, or any
  refactoring beyond highlighting and answering.

## Steps

- [ ] Add `async` and `await` to the TextMate grammar in
      `packages/vscode/syntaxes/luam.tmLanguage.json`, scoped as keywords, and
      keep them unhighlighted where they are ordinary identifiers if the grammar
      can express that distinction. Semantic tokens are the fallback and the
      authority.
- [ ] Classify both words in the semantic token provider, which has the parse
      result and can tell the modifier from an identifier.
- [ ] Offer `async` and `await` as contextual completions — `async` at statement
      start, `await` only inside an async body — following how the existing
      contextual keywords are filtered.
- [ ] Hover an async function's name with its `Promise<T>` return, and hover
      `Promise`, `next`, `catch`, `all`, `race`, `settle` and `delay` with the
      text added in 47.03.
- [ ] Show the awaited type on the inlay hint for `local variable = await f()`,
      reusing the value-list distribution shared in 46.01 rather than reading the
      call expression whole.

## Acceptance Criteria

- [ ] `async` and `await` render as keywords in their operator positions and as
      plain identifiers in `local async = 1`.
- [ ] Completion offers `await` inside an async body and not outside one.
- [ ] Hover on an async function reports `Promise<T>`, and hover on a `Promise`
      member reports its documented text.
- [ ] The inlay hint on a local bound to an `await` shows the inner type.
- [ ] Every existing theme and semantic-token test still passes.
