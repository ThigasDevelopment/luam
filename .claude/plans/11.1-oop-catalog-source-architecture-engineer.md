# 11.1 — Generate the MTA OOP surface from the upstream catalog

> File: `.claude/plans/11.1-oop-catalog-source-architecture-engineer.md`
> Milestone 8 imported the procedural catalog and deferred the OOP form. This
> task adds the second view of the same upstream source, without a second
> source of truth.

## Objective

Produce, from the pinned `mtasa-lua-types` snapshot the generator already reads,
the class-shaped view of the MTA API: which element classes exist, which methods
and properties each carries, and which procedural function each one maps to.

## Scope

- **In:** The OOP extraction pass in the `mta-types` generator, the descriptor
  shape that carries a class, the mapping from a method to the procedural
  function it wraps, generated output and drift test.
- **Out:** Anything in the checker (11.2), the `oop` gate (11.3), the editor
  (11.4).

## Steps

- [x] Confirm the pinned snapshot carries the OOP declarations. If it does not,
      record the alternative in an ADR before writing any generator code — a
      second upstream source is a decision, not an implementation detail.
- [x] Extend the generator to emit an `ApiClass` per element type: name,
      superclass, methods, properties, and the environment each member is
      available in.
- [x] Record for every method the procedural function it corresponds to, so a
      diagnostic can name `getPlayerName` when the author wrote `player:getName`.
- [x] Keep the procedural catalog byte identical. The OOP surface is a new
      generated file, not a rewrite of the existing one.
- [x] Carry the environment split through: a method whose procedural function is
      server-only stays server-only.
- [x] Extend the drift test so a hand edit to the generated OOP file fails.
- [x] Record the counts (classes, methods, properties) the way milestone 8
      recorded its own.

## Acceptance Criteria

- [x] `pnpm --filter @luam/mta-types generate` regenerates both the procedural
      catalog and the OOP surface, and produces no diff on a clean tree.
- [x] The generated OOP surface covers the element hierarchy with `Element` at
      the root, and every method resolves to a declared procedural function.
- [x] The procedural catalog file is unchanged by this task.
- [x] A method declared only on the server is marked `server`.
- [x] `pnpm typecheck` and `pnpm test` pass.
